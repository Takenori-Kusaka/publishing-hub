### 1. なぜ、評価を1冊に分けるのか

生成AIを仕事に組み込むとき、最後に残る問いは「この出力で良いのか」です。モデルを選び、プロンプトを書き、社内の文書をつないでも、それだけでは本番に出せません。出力が期待に届いたかを確かめる手順が要ります。

この問いの重要さは、広く認められています。OpenAIは評価の枠組みevalsの説明(README)で、LLMで何かを作るなら、質の高い評価を作ることが最も影響の大きい仕事の1つだと書きました [ [ 54 ] ](https://github.com/openai/evals) 。一方で、独立の開発者Simon Willisonは2024年末に、誰もが評価の重要さを知っているのに、どう実装するかの良い指針が欠けていると述べています [ [ 648 ] ](https://simonwillison.net/2024/Dec/31/llms-in-2024/) 。重要さは知られていても、やり方の地図がない状態です。

著者の前著『AIトランスフォーメーションの設計図』(以下、本編)は、生成AIとAIエージェントの導入を段階として整理しました。本編は[道筋別の戦略の章](https://zenn.dev/takenori_kusaka/books/ai-transformation-blueprint/viewer/35-strategy-by-path)で、何を良い出力と見なすかを定めて測り続ける「評価の能力」を、どの未来が来ても無駄にならない手の1つに挙げています。ただし、評価の手順そのものは本編の主題ではありません。本書は、その手順を1冊に広げた別冊です。

### 2. 本書の主題：出力は、どこまで期待に近づいたか

本書の主題は、生成AIの「出力の評価」です。ユーザーの入力に対する期待に、出力がどこまで近づいたか。それを、どう測ってきたか、いま何で測れるか、これからどう測るようになるかを扱います。

本書は、評価の対象を2つの層に分けます。

1. **入力側(収集の評価)**。ユーザーの入力だけでは足りない情報を、検索、検索拡張生成(RAG)、ツール、長い文脈で必要十分に集められたか。集めた情報は正確で、新しく、出所が確かか。
2. **生成側(生成の評価)**。集めた情報から期待する形の出力を作れたか。その出力は根拠に忠実で、事実に合い、安全か。期待にどこまで近づいたか。

各層を5つの項目に分けた「2層10項目」が、本書の軸です。入力側はI1必要、I2十分、I3精度、I4鮮度、I5出所、生成側はG1整形、G2忠実、G3事実、G4安全、G5期待です。定義は[期待値への距離の章](16-distance-to-expectation)で示します。

### 3. 扱わないものと、その理由

本書は、モデルの問題解決能力を測るベンチマークの歴史を主役にしません。MMLU、GPQA、SWE-benchのような能力の試験です。

理由は2つあります。第一に、能力のベンチマークは計算機の性能の指標のように着々と進み、こまめに入れ替わります。LLMは2025年までにMMLUのような代表的な試験で90%超に達し、測定が機能しにくくなりました [ [ 60 ] ](https://arxiv.org/abs/2501.14249) 。Stanford HAIの2026年の年次報告は、数年もつはずの評価が数か月で飽和すると述べています [ [ 630 ] ](https://hai.stanford.edu/ai-index/2026-ai-index-report/technical-performance) 。

第二に、能力の高さは、自社の用途での出力の良さを保証しません。アメリカの国立標準技術研究所(NIST)は生成AIのリスク管理の手引きで、狭く非体系的で逸話的な評価から性能を外挿しないよう求めています [ [ 259 ] ](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf) 。本書が扱うのは、自社の入力と期待に対する出力の評価です。

能力のベンチマークは、評価の手法の起源として必要な範囲で触れます。主役にしない理由の詳細は、[能力ベンチマークとの距離の章](10-capability-benchmarks-distance)で根拠とともに述べます。

### 4. 本編との関係

本書は本編の付録にあたる別冊で、本編の導入フェーズS1〜S6と接続します。本編のS1〜S6は、生成AIを組織に取り込む深さの6段階です。本書は、評価を組織で回す仕組みの段階を、V0(目視)からV4(評価駆動)の5段階として定義します。

| 本書の段階 | 名前 | 何が起きているか |
| --- | --- | --- |
| V0 | 目視 | その用途の担当者が数件を見て判断する |
| V1 | 固定セット | ゴールデンセットと人の採点で判断する |
| V2 | 自動評価 | 指標と審判モデルで、変更のたびに回帰を検査する |
| V3 | 本番評価 | 本番の記録を採取し、抜き取りと監視で評価する |
| V4 | 評価駆動 | 評価が仕様と改善を決め、監査に耐える |

審判モデルは、AIの出力を別のAIに採点させる仕組みです。S1〜S6のどの段階でどのV段階が要るかは、[導入フェーズと評価の章](20-adoption-stage-and-evaluation)で対応づけます。本編で導入の段階を決めた読者は、その章から読み始めることもできます。

1つ注意があります。本編と本書は、どちらも未来を「3つの道筋」として描き、A・B・Cの記号を使います。ただし中身は別です。本編の道筋は、生成AI全体の加速・漸進・調整です。本書の道筋は、評価の担い手の自動化・人手回帰・規制主導です。本書でA・B・Cと書くときは、本書の道筋を指します。

### 5. 設計思想と5つの規範

本書は本編と同じく、砂時計の構造を採ります。上半分が過去の系譜、くびれが現在地、下半分が未来です。未来は1つの予言ではなく、2031年までの3つの道筋として描きます。この構造の上で、本編と同じ5つの規範を守ります。

**規範1：過去と現在の記述は、事実のみで構成します。** 第1章から第15章までの本文は、出来事、統計、公表された文書の内容に限ります。著者の解釈は、各章末の「本章の要点と解釈」に隔離し、冒頭に免責の文を置きます。第16章以降の枠組みと未来の章では、章末に「本章の位置づけ」か「経営層への含意」を置きます。

**規範2：出典は、当該記述の直後にインラインで示します。** 数値や事実の文末に、一次資料への外部リンクを直接置きます。番号は巻末の参考文献と対応します。

**規範3：情報源は、一次資料・公的資料・査読論文・発行元の公式発表に限定します。** 言説は、誰が、いつ、どの利害のもとで述べたかを明記します。報道しかない数値は、報道であることを書きます。

**規範4：1つの正解を出しません。** 評価の分野には、2026年10月時点で事実上の標準(デファクト)がありません。本書は特定の道具や手法を推奨せず、評価の未来を3つの道筋として並べ、分岐条件と早期警戒指標を示します。

**規範5：可読性を優先します。** 各章に1枚の図を置き、1つの主張だけを示します。経営層と、生成AIを仕事に組み込む実務家が、1章を10分で読めるよう、表と箇条書きを使います。

### 6. 本書の構成

本書は、4つの部と総括、2つの付録で構成されます。

**第Ⅰ部：系譜(第1章〜第10章)**。人が測っていた時代から、参照との一致、意味の一致、嗜好の学習、審判としてのLLM、RAG評価、幻覚の計測、ガードレール、道具の氾濫までを追います。最後に、能力ベンチマークを主役にしない理由を述べます。

**第Ⅱ部：現在地(第11章〜第15章)**。公開された失敗の事例と、そこから逆算した評価、規格と規制、日本の実践、2026年の実務の分布を確かめます。

**第Ⅲ部：枠組み(第16章〜第20章)**。期待値への距離を2層10項目で定義し、入力側と生成側の測り方、成熟度V0〜V4、本編の導入フェーズとの対応を示します。

**第Ⅳ部：未来と実装(第21章〜第23章)**。言説を分類し、自動化・人手回帰・規制主導の3つの道筋を描きます。最後に、1つの用途を90日でV2まで上げる手順(V0から始める組織も含む)と、経営会議に出す1枚の資料の型を示します。

**総括**では、推論の連鎖を1本につなぎ、本書が答えていない問いを挙げます。**付録A**は用語集、**付録B**は参考文献です。

AIの技術の知識は前提にしません。専門用語は初出で説明し、付録Aの用語集で定義します。本書が示すのは、判断の材料と、その材料がどの出典に立っているかです。結論を受け入れることを求めるのではなく、読者が自分の前提を置いて推論をやり直せることを目指します。
