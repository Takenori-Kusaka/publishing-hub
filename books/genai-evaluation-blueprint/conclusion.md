### 1. 本書の推論を1本につなぐ

本書の推論は、次の7つの段で1本につながっています。各段は、各章の事実と章末の解釈をつないだ著者の推論です。各段の根拠は、括弧内の章にあります。

**第一に、評価の歴史は代役探しの繰り返しでした**([人が測っていた時代の章](01-human-judgement-era)から[審判としてのLLMの章](05-llm-as-judge))。期待への近さは、最初は人の判定そのものでした。BLEUとROUGEは人の判定の代役として生まれ、用途の外では人と相関しないと批判されました。意味の一致と忠実性の指標、人の嗜好を学んだ報酬モデル、審判モデルと、代役は替わり続けました。どの代役も、最後は人の判定との一致で正しさを示しており、人の判定の不安定さから逃れられていません。

**第二に、評価が訓練の目標になると、評価は目的から離れます**([嗜好の学習の章](04-preference-learning)、[幻覚の計測の章](07-hallucination-measurement))。報酬モデルの最適化のしすぎで真の性能が落ちることは、測定で示されています。正答率だけを採点する評価が当て推量を促し、幻覚を生むという説明は、モデルの提供者自身から出ています。

**第三に、入力側と生成側を分けて測らなければ、失敗の原因を取り違えます**([RAG評価の成立の章](06-rag-evaluation)、[期待値への距離の章](16-distance-to-expectation))。RAGの評価の指標は、入力側と生成側の両方を測る形に整いました。不十分な文脈を与えると誤答が増えるという実測は、生成側だけを測ることの危うさを示しています。

**第四に、著者の解釈では、公開された失敗の多くは、生成の誤りより運用の空白で実害になりました**([失敗の記録の章](11-failure-records)、[失敗から逆算する評価の章](12-evaluation-from-failures))。空白が集中したのは、長い対話や本番の基盤の劣化のような、開発時の短い固定の評価では現れない条件でした。

**第五に、規格と規制は「測る仕組みを持て」と求め、指標の中身は組織に委ねています**([規格と規制が求める評価の章](13-standards-and-regulation))。最も具体的なのは記録の要求です。道具の側でも事実上の標準は現れず、評価の基盤の提供を約2年で止める例も出ました([道具の氾濫の章](09-tool-proliferation))。著者の解釈では、日本の実務は、審判モデルを人の判定の補完として使う方向にあります。ただし、少量の人のラベルで較正した記録は、要約の一貫性の採点に限ったAI Shiftの1件の比較だけです([日本の評価の実践の章](14-japan-practice))。

**第六に、だから評価の資産は自社で持つ必要があります**([評価の成熟度の章](19-evaluation-maturity)、[導入フェーズと評価の章](20-adoption-stage-and-evaluation))。2層10項目で何を測るかを決め、V0からV4の段階で測る仕組みを上げます。評価の成熟度は導入の段階に先行させます。道具は買えますが、評価の基準とゴールデンセットは買えません。

**第七に、未来は3つの道筋に分かれますが、最初の手は共通です**([言説の分類の章](21-discourse-taxonomy)、[3つの道筋の章](22-three-paths)、[評価体制の立ち上げの章](23-launching-evaluation))。自動化・人手回帰・規制主導のどれが来ても、ゴールデンセット、評価の記録、審判の較正、移せる形での保管の4つは無駄になりません。最初の90日は、これらを1つの用途で作り、V2へ上げることに使います。顧客向けの用途では、広げる前に本番の抜き取りを足します。

### 2. 推論の弱い環

上の連鎖には、根拠の薄い環があります。著者が自覚している弱い環を5つ挙げます。

- **2層10項目への対応づけは著者の判断です。** 各手法は実在しますが、RAGASの忠実性をG2に置くような対応は、手法の作り手が名づけたものではありません。
- **実務の分布を示す調査の多くは、評価の道具を提供する事業者によるものです。** 審判モデルと人のレビューの利用率を示したLangChainの調査はその例で [ [ 423 ] ](https://www.langchain.com/state-of-agent-engineering) 、回答者が評価に関心の高い組織に偏る可能性があります。[評価の現在地の章](15-state-of-2026)の分布は、この偏りを前提に読む必要があります。
- **日本の失敗の記録が少ないことです。** 自治体や、生成AIを提供する企業自身が、誤回答を理由にサービスの停止と謝罪を公式に発表した一次資料は、本書の調査では見つかりませんでした。公表が少ないことは、失敗が少ないことを意味しません。
- **未来の像の数値の根拠が細いことです。** 評価そのものについての年限つきの数値の予測は、一次資料ではGartnerのものに限られました。2027年・2029年・2031年の像は、規則の適用日のような確定した日付から著者が推論したものです。
- **保険と賠償の経路を扱っていません。** 評価の中身が、規制ではなく保険の引受や損害賠償の側から決まる経路は、本書の調査の外にあります。

### 3. 本書が答えていない問い

本書は、次の問いに答えていません。いずれも、2026年10月時点の一次資料では答えを確かめられなかった問いです。

1. 審判モデルと人の判定の一致は、どの水準で十分と言えるか。実務家の提案はありますが、用途を超えて通用する基準は確かめられませんでした。
2. ドメイン専門家を評価者としてどう育て、どう処遇するか。人手評価の単価は公開されていますが、専門家の評価の市場の価格は見えていません。
3. 組織は評価に年間いくら払うべきか。V4の段階の費用の総額を示す公開の一次資料はありません。
4. AIエージェントの行動の軌跡を、本番でどう継続して評価するか。事業者自身が、エージェントの評価はまだ初期段階だと述べています [ [ 406 ] ](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 。
5. 利用者の満足と出力の正しさが食い違うとき、どちらを優先するか。迎合の事例は、満足の指標だけを報酬にする危うさを示しましたが、優先の規則は示していません。
6. 規制当局は、どの形式の評価の記録を適合の証拠として受け入れるか。EUの整合規格は2026年10月時点でまだ利用可能になっていません。
7. 評価がモデルの訓練の中に吸収されたとき、外から何を測るか。モデルが評価中にテストを疑った事例は、外からの評価が信頼できるかが、問われ続ける問題であることを示しています [ [ 619 ] ](https://www.anthropic.com/engineering/eval-awareness-browsecomp) 。

### 4. 本書の更新について

本書の事実は、2026年10月29日までに確認した一次資料に基づきます。評価の道具と規制は、数か月で変わります。OpenAIの評価の基盤は、本書の確認日の約1か月後に停止する予定です [ [ 128 ] ](https://developers.openai.com/api/docs/deprecations) 。

更新の手がかりは、[3つの道筋の章](22-three-paths)の早期警戒指標です。指標の値が動いたとき、どの道筋へ近づいたかを読み直し、[評価体制の立ち上げの章](23-launching-evaluation)の1枚の資料の「前提とする道筋と指標」の欄を書き換えます。本書が目指すのは、結論を受け入れてもらうことではありません。読者が自分の前提を置き、出典に戻って推論をやり直せることです。
