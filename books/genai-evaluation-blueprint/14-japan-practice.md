### 序論：本章が扱う範囲

本章は、日本で生成AIの出力がどう評価されてきたかを、2022年から2026年10月までの公開資料で記録します。対象は、日本語の評価資源(ベンチマーク・データセット・リーダーボード)、日本のLLM開発企業の公式評価、企業の技術ブログに現れた評価の実務、自治体と官公庁の検証記録、日本の事例です。

日本の公的な指針の条文は、[規格と規制が求める評価の章](13-standards-and-regulation)で扱いました。本章は、その指針の下で現場が何を測ったかに重心を置きます。

数値には、誰が・どの審判モデルで・いつ測ったかを添えます。企業の技術ブログは各社の公式ドメインの記事に限り、自社の測定であることを明記します。

### 1. 日本語の評価資源：翻訳ではなく自前で作る

日本語の汎用言語理解ベンチマークJGLUEは、ヤフーと早稲田大学の共同研究として、翻訳を介さず日本語で一から構築されました。2022年の言語処理学会と国際会議LRECで発表されています [ [ 687 ] ](https://github.com/yahoojapan/JGLUE) 。

生成の評価は2023年に始まりました。

- **Rakuda。** 2023年6月に公開された、日本の歴史・社会・地理などを問う40問の自由回答のベンチマークです。GPT-3.5を審査員にした対戦比較でモデルを順位付けしました [ [ 688 ] ](https://www.passaglia.jp/llm-ranking) 。
- **ELYZA-tasks-100。** 2023年8月、ELYZAがモデルの公開と同時に公開した100件の評価データです。モデル名を伏せた3人のブラインド評価の平均で採点しました [ [ 689 ] ](https://note.com/elyza/n/na405acaca130) 。
- **人と審判モデルの一致。** 2023年9月、ELYZAは人手評価4,200件とGPT-4の自動評価の相関を公表しました。相関は人間同士で0.848、GPT-4と人間で0.818でした。GPT-4は全体に人間より高い点を付け、不自然な日本語の判定が苦手でした [ [ 690 ] ](https://zenn.dev/elyza/articles/5e7d9373c32a98) 。

その後、複数の評価を束ねる基盤が整いました。Weights & Biases Japanは2023年7月から「Nejumi LLMリーダーボード」を運用しています [ [ 692 ] ](https://prtimes.jp/main/html/rd/p/000000016.000119963.html) 。2024年7月の第3版は、言語の能力に加えて、制御性・倫理・毒性・バイアス・真実性・堅牢性の「アラインメント」の軸を足しました [ [ 694 ] ](https://note.com/wandb_jp/n/nd4e54c2020ce) 。2025年8月の第4版は、従来のベンチマークでは多くのモデルが高得点を取り、性能差を見極めにくくなったことを背景に、難度の高い評価を加えています [ [ 695 ] ](https://prtimes.jp/main/html/rd/p/000000024.000119963.html) 。2024年11月には、LLM-jpとHugging FaceがOpen Japanese LLM Leaderboardを公開しました [ [ 702 ] ](https://huggingface.co/blog/leaderboard-japanese) 。

### 2. 日本語に固有の評価の軸

英語圏の評価では測れない軸のために、専用のデータセットが作られています。

LCTG Benchでは、要約の文字数の制約を守る能力がGPT-4 Turboでも0.450にとどまりました。論文の著者は、言語モデルがトークン単位で処理するため日本語の文字数を正確に捉えられないことを原因と考察しています [ [ 696 ] ](https://www.anlp.jp/proceedings/annual_meeting/2024/pdf_dir/D11-2.pdf) 。日本語TruthfulQAでは、全問の正答率で人間を超えるLLMはありませんでした [ [ 336 ] ](https://www.anlp.jp/proceedings/annual_meeting/2024/pdf_dir/P6-15.pdf) 。Preferred Networksは2026年8月31日、LLMエージェントで生成した500問のJapanese-Mail-Benchを公開しました。日本語として正しいかだけでなく、敬語の使い方などメールとして状況に合ったものを書けているかを重視すると述べています [ [ 705 ] ](https://www.preferred.jp/ja/blog/tech/generate-benchmark-by-llm) 。

### 3. 開発企業の公式評価：何を根拠に語ったか

日本のLLM開発企業の性能の主張は、第三者のリーダーボードか自社の測定に基づいています。

- サイバーエージェントは2024年7月、自社モデルの性能をNejumi LLMリーダーボード3の結果で説明しました [ [ 715 ] ](https://www.cyberagent.co.jp/news/detail/id=30463) 。
- 富士通は2024年9月、Takaneを「世界一の日本語性能」と発表しました。根拠としたJGLUEの数値は、富士通とCohereによる自社の測定です [ [ 716 ] ](https://info.archives.global.fujitsu/jp/news/2024/09/30.html) 。
- NTTは2025年10月、tsuzumi 2が社内の問い合わせ対応のRAGの評価で他社の先進モデルと同等以上だと発表しました。評価のデータと指標は、発表の本文には記載がありません [ [ 718 ] ](https://group.ntt/jp/newsrelease/2025/10/20/251020a.html) 。

公的な事業の成果ページにも、評価の揺れが記録されています。経済産業省のGENIACの成果ページでは、ある採択者が日本語MT-Benchのスコアを6.8〜7.0とし、ランダムシードの関係で評価の度に変動すると注記しました [ [ 140 ] ](https://www.meti.go.jp/policy/mono_info_service/geniac/selection_1/result_1/result_details_1/index.html) 。東京科学大学のSwallowの評価ページは、未評価のタスクを含めた平均の順位でモデルの優劣を論じるのは適切でない場合がある、と注記しています [ [ 708 ] ](https://swallow-llm.github.io/evaluation/about.ja.html) 。

### 4. 企業の評価の実務

企業の技術ブログには、RAGと審判モデルの評価の運用記録が多く公開されています。数値はいずれも各社の自社測定です。

| 企業 | 公開 | 評価の要点 |
| --- | --- | --- |
| LINEヤフー | 2024年8月 | 社内RAGの回答を4つの観点で、数値でなく真偽値で判定する |
| LayerX | 2024年11〜12月 | 評価を中心に開発を回す。生成文でなく検索の再現率などの間接指標も使う |
| DeNA | 2025年11月 | 0〜4点の自動採点で合格率を追い、回答精度を50%台から79%へ上げた |
| JMDC | 2025年12月 | 審判モデルの評価のばらつき、知識の欠如、冗長な回答の過大評価を報告 |
| GMOインターネットグループ | 2026年6月 | 根拠に支持されるかと正解に一致するかの2軸で、検索の失敗と捏造を分ける |
| AI Shift | 2026年7月 | 要約の一貫性の採点で、人手のラベル10件で審判モデルを校正し、専門家間の一致の8割に達した。幻覚の検知ではラベルの効果は小さかった |

LINEヤフーは、人手の評価は数日かかり変更のたびには回せないため、審判モデルを構築したと述べました。審判の誤判定に備え、性能の異なる複数のモデルの回答を評価して傾向を見る、とも書いています [ [ 721 ] ](https://techblog.lycorp.co.jp/ja/20240819a) 。LayerXは「評価駆動開発」を提唱し、初期の少数の人手評価から自動評価と監視に移ったと述べています [ [ 723 ] ](https://tech.layerx.co.jp/entry/2024/12/12/191131)  [ [ 724 ] ](https://tech.layerx.co.jp/entry/2024/11/18/151901) 。DeNAは、検索結果の件数を5件から20件に増やすと精度が54%から69%に上がったと報告しました [ [ 726 ] ](https://engineering.dena.com/blog/2025/11/its-ai-journey-rag-tech/) 。

審判モデルの限界も実測されています。JMDCは、同じモデル・同じサンプルでも評価が大きく変動し、審判モデルは人の評価の完全な代替ではなく補完する道具だと結論しました [ [ 727 ] ](https://techblog.jmdc.co.jp/entry/20251208) 。Insight Edgeは、温度を0にしシードを固定しても、同じ入力に異なるスコアを返すモデルがあったと報告しています [ [ 728 ] ](https://techblog.insightedge.jp/entry/llm-as-a-judge-determinism) 。Beatrustは、RAGの評価ツールRagasの総合スコアと人手評価の相関が最大0.55にとどまったと報告しました [ [ 765 ] ](https://note.com/beatrust/n/n6474d36f9290) 。GMOの記録は同社の記事にあります [ [ 736 ] ](https://recruit.group.gmo/engineer/jisedai/blog/evidence-first-rag-grounding) 。AI Shiftは、少ない人手のラベルで審判モデルを人手評価に近づける8つの手法を比べました。要約の一貫性(SummEval)の採点では、評価基準の校正がラベル10件でκ=0.438となり、専門家間の一致(0.544)の8割に達しました。κは、偶然の一致を除いた一致の度合いです。幻覚の検知(RAGTruth)では、定義を書いた採点基準だけで大きく改善し、ラベルの効果は小さいものでした。比較は各条件1回で、審判はGPT-5.4-miniだけです [ [ 729 ] ](https://zenn.dev/aishift/articles/08bbe9ec0a4b3b) 。

### 5. 自治体と官公庁の検証

自治体の評価は、職員のアンケートから始まりました。2023年4月、横須賀市は自治体で初めて全庁的なChatGPTの活用実証を始めました [ [ 741 ] ](https://www.city.yokosuka.kanagawa.jp/0835/nagekomi/20230418_chatgpt.html) 。同年6月の結果報告では、6%程度の職員は、概ね不適切な回答が返ると答えています。報告書は、5割近い職員が回答の精度に不満を持つことを、GPT-4の導入を検討する根拠にしました [ [ 742 ] ](https://www.city.yokosuka.kanagawa.jp/0835/nagekomi/20230605_chatgpt2.html) 。

その後の自治体と官公庁の動きは、次のとおりです。

- 東京都は2023年8月、職員向けのガイドラインを策定し、全局の約5万人が使える環境を整えました [ [ 744 ] ](https://www.spt.metro.tokyo.lg.jp/tosei/hodohappyo/press/2023/08/23/14.html) 。
- 神戸市は2023年6月から9月に職員133名でChatGPTを試行し、課題を集めました [ [ 745 ] ](https://www.city.kobe.lg.jp/z/kikakuchose/digitalsenryaku/seiseiai.html) 。
- 渋谷区は2025年3月から区の情報に基づくチャットボットを公開し、回答ごとに解決したかどうかの反応を集めて精度の向上に使うとしています [ [ 753 ] ](https://www.city.shibuya.tokyo.jp/kusei/kocho/ai-chatbot/ai_chatbot.html) 。
- 総務省は2025年12月、自治体向けのガイドブックの第4版に、生成AIのリスクケースの報告フォームを別添として付けました [ [ 751 ] ](https://www.soumu.go.jp/menu_news/s-news/01gyosei04_02000155.html) 。

### 6. 日本の事例と、見つからなかった資料

日本でも、出力の誤りが訴訟の請求原因になりました。2025年8月、朝日新聞社と日本経済新聞社はPerplexityを共同で提訴しました。両社は、回答の引用元に両社の社名や記事を表示しながら記事と異なる虚偽の事実を多数表示しており、不正競争行為に当たると主張しています [ [ 762 ] ](https://www.asahi.com/corporate/info/15986577) 。

自治体や地域の情報でも誤りが報じられています。2023年10月、大阪府の生成AIのチャットが大阪・関西万博を「中止」と誤って回答したと報じられ、府は正確性を保証しない旨の注意書きを掲載したと報じられています [ [ 468 ] ](https://bunshun.jp/articles/-/66576) 。2024年11月には、福岡県内の自治体が後援する事業の運営会社が、生成AIで作った記事に存在しない施設などが含まれていたとして謝罪し、記事を削除して配信を一時停止しました [ [ 483 ] ](https://www.j-cast.com/2024/11/11497594.html?p=all) 。規制当局では、2023年6月に個人情報保護委員会が、応答に不正確な個人情報が含まれるリスクを利用者に注意喚起しました [ [ 758 ] ](https://www.ppc.go.jp/files/pdf/230602_kouhou_houdou.pdf) 。

一方で本書の調査では、日本の自治体や生成AIを提供する企業自身が、誤回答を理由にサービスの停止と謝罪を公式に発表した一次資料は見つかりませんでした。大阪府の事例は報道だけで、府の公式発表は取得できていません。福岡県の事例で謝罪し配信を止めたのは、生成AIで記事を作った民間の運営会社です。日本の裁判所に架空の判例が提出された事例も見つかりませんでした。

#### 図の読み方

図は、上から下へ年を追って5つの段を並べています。2022年は汎用の言語理解を測るJGLUEです。2023年は人手と審判モデルで生成を採点するELYZA-tasks-100とRakudaです。2024年は文字数の制御やバイアス、安全性の軸が加わった時期です。2025年は飽和への対策として難度を上げたNejumi 4です。2026年は司法試験・誤情報・敬語のような日本固有の課題のデータセットです。

5つの段は同じ藍の淡い色で塗り、色の濃さに意味を持たせていません。評価の軸が増えたことは、図の下の一文で述べています。各段の出典は、本文の第1節と第2節にあります。

### 本章の要点と解釈

本節は、著者による解釈です。前節までの事実記述とは区別して読んでください。

- **日本の評価資源は「自前で作る」ことの連続です。** JGLUEから司法試験のデータセットまで、翻訳では測れない軸のために作られてきました。著者は、日本語で生成AIを使う組織は、汎用のリーダーボードの順位を自社の業務の評価の代わりにできないと考えます。文字数・敬語・固有名詞・法令は、それぞれ別に測る必要があります。
- **審判モデルについての日本の実務の答えは「補完」です。** ELYZAは高い相関と「甘い採点」を同時に示しました。JMDCとInsight Edgeは揺れを観測し、AI Shiftの1件の比較では、少量の人手ラベルによる校正が、要約の一貫性の採点で効きました。著者は、少量の人手ラベルで審判モデルを校正する手順を、日本の実務の到達点の1つだと考えます。ただし根拠は1件の記録で、幻覚の検知では効果が小さいとされています。
- **公表された失敗が少ないことは、失敗が少ないことを意味しません。** 本書の調査で一次資料が見つからなかったのは、自治体や生成AIを提供する企業自身による停止と謝罪の公表です。著者は、自治体の評価が職員のアンケートと人の確認の義務にとどまっている段階では、誤りが表に出る経路自体が細いと推定します。

経営層と実務家への含意は、日本語固有の評価の軸を自社のゴールデンセットに入れることです。企業の技術ブログでは評価データの件数がほとんど公開されていません。それでも、数十件で始めて少量のラベルで審判モデルを校正する、という順序は複数の記録から読み取れます。この順序を成熟度として整理する作業は、[評価の成熟度の章](19-evaluation-maturity)で行います。
