### 序論：本章が扱う範囲

本章は、失敗の当事者が「何を測れていなかったか」を自ら書いた資料を読みます。[失敗の記録の章](11-failure-records)は、公開事例を失敗の4つの区分に分けて並べました。本章はその中から、評価の欠落を当事者が文章で認めた事例を選びます。そして、欠落の中身と、その後に表明された対策を記録します。

中心に置くのは4件です。2023年のBingの長い対話、2025年のGPT-4oの迎合、2025年のChatGPTの長い対話での安全策の劣化、2025年のClaudeの品質劣化です。いずれも事業者自身の公表文が一次資料として残っています。

続いて、同じ組織の名で同じ型の失敗が続けて報じられた例と、評価済みの仕組みへの更新の後に失敗が起きた例を並べます。その後に、当事者が導入した工程上の対策を記録します。最後に、規制当局や裁判所が「出力の誤り」ではなく「評価や確認をしていないこと」を問題にした例を扱います。

本文は事実の記述に限ります。各事例を本書の入力5項目・生成5項目のどれに対応させるかという判断は、章末の解釈の節に置きます。

### 1. Bing：長い対話で口調が外れる(2023年)

2023年2月15日、Microsoftは新しいBingの公開から1週間の学びを公表しました。15問以上の長い対話では、回答が繰り返しになったり、意図した口調から外れる方向へ誘導されたりすると述べています。モデルは、問われた口調に合わせて応答しようとすることがある、とも書きました [ [ 470 ] ](https://blogs.bing.com/search/february-2023/The-new-Bing-Edge-Learning-from-our-first-week) 。

2日後の2月17日、同社はチャットを1セッション5ターン、1日50ターンに制限しました [ [ 1201 ] ](https://blogs.bing.com/search/february-2023/The-new-Bing-Edge-Updates-to-Chat) 。問題が出る対話の長さを、製品の側で使わせない対策です。

### 2. GPT-4o：迎合を捕まえられなかった(2025年)

2025年4月29日、OpenAIは前週のGPT-4oの更新を取り消したと公表しました。更新後のモデルは過度にお世辞を言い同意的で、迎合的(sycophantic)と表現されるものでした。同社は、モデルの行動の調整にChatGPTの高評価・低評価の信号を使っていたと明記しています [ [ 302 ] ](https://openai.com/index/sycophancy-in-gpt-4o/) 。

5月2日の続報は、経緯をより詳しく書きました [ [ 303 ] ](https://openai.com/index/expanding-on-sycophancy/) 。

- 更新は4月24日から25日に展開され、利用者の高評価・低評価に基づく追加の報酬信号を含んでいました。
- 小規模なA/Bテストでは問題が出ませんでした。4月28日に取り消しを始めています。
- 同社は、オフライン評価が迎合的な挙動を捕まえるだけの広さと深さを持っていなかったと書きました。A/Bテストにも、その面の挙動を十分な細かさで示す信号がなかったとしています。
- 少数の専門家による定性的な評価は違和感を示していましたが、同社はそれを重く見ずに展開しました。この判断を同社は「誤り」と呼んでいます。

その後の2025年8月のGPT-5のシステムカードで、OpenAIは迎合を本番に近い会話で採点し、報酬信号に使ったと報告しました。オフライン評価の迎合の得点は、GPT-4oの0.145に対しgpt-5-mainで0.052でした。初期の本番計測では、迎合の出現が無料の利用者で69%、有料の利用者で75%減ったとしています [ [ 304 ] ](https://cdn.openai.com/gpt-5-system-card.pdf) 。

### 3. ChatGPT：長い対話で安全策が劣化する(2025年)

2025年8月26日、OpenAIは「Helping people when they need it most」を公表しました。公表文は、安全策は一般的な短いやりとりでより確実に働くと述べました。そのうえで、長いやりとりでは安全訓練の一部が劣化し得ると認めています。例として、利用者が最初に自殺の意図に触れたときには相談窓口を正しく案内しても、長い時間の多くのやりとりの後では安全策に反する回答をすることがある、と書きました [ [ 508 ] ](https://openai.com/index/helping-people-when-they-need-it-most/) 。

同じ日、16歳の利用者の両親が、OpenAIとその経営者らをサンフランシスコの上級裁判所に不法死亡で提訴したと報じられています [ [ 1706 ] ](https://techpolicy.press/breaking-down-the-lawsuit-against-openai-over-teens-suicide) 。訴状の記載は原告の主張で、裁判所が認定した事実ではありません。

第1節のBingの公表と、本節の公表の間は2年半です。どちらも、対話が長くなると挙動が設計から外れることを当事者が書いています。

### 4. Claude：ノイズの多い評価に頼りすぎた(2025年)

2025年9月17日、Anthropicは、8月から9月にClaudeの応答品質を断続的に劣化させた3件のインフラの不具合を公表しました。提供の基盤の側の不具合で、技術的には、要求を誤ったサーバへ振り分ける誤り、出力の生成の誤り、TPU向けコンパイラの潜在的なバグの3件です。最も影響の大きかった8月31日の1時間には、Sonnet 4へのリクエストの16%が影響を受けました [ [ 494 ] ](https://www.anthropic.com/engineering/a-postmortem-of-three-recent-issues) 。

同社は検出が遅れた理由を2つ挙げています。1つは、社内のプライバシーとセキュリティの統制が、技術者が利用者のやりとりに触れる方法と時期を制限していたことです。もう1つは、ノイズの多い評価に頼りすぎたことです。対策として、本番環境での継続的な品質評価の導入を表明しました [ [ 494 ] ](https://www.anthropic.com/engineering/a-postmortem-of-three-recent-issues) 。

この事例では、モデルの能力ではなく提供の基盤の不具合が、出力の期待外れとして利用者に現れました。

### 5. 4件の比較

| 事例 | 公表 | 当事者が書いた空白 | 当事者が表明した対応 |

| Bing | 2023年2月 | 15問以上の長い対話での逸脱 | 対話の回数の上限 |
| GPT-4oの迎合 | 2025年4〜5月 | オフライン評価の広さと深さ、A/Bテストの信号 | 取り消し、迎合を採点して報酬に使う(同年8月のGPT-5) |

| Claudeの品質劣化 | 2025年9月 | ノイズの多い評価、利用者のやりとりに触れる制約 | 本番での継続的な品質評価 |

### 6. 同じ組織の名での再発と、更新の後の失敗

当事者の公表とは別に、2種類の例があります。1つは、同じ組織の名で同じ型の失敗が続けて報じられた例です。

- **Deloitte。** Deloitteのオーストラリアのメンバーファームが作った政府向けの報告書の架空引用は、2025年10月に報じられました [ [ 1704 ] ](https://fortune.com/2025/10/07/deloitte-ai-australia-government-report-hallucinations-technology-290000-refund) 。その翌月、Deloitteが作成したカナダのニューファンドランド・ラブラドール州の医療人材計画にも、存在しない論文などが見つかったと報じられています。Deloitteは、AIを報告書の執筆には使っておらず、少数の引用の支援に選択的に使ったと説明しました。この説明は報道で伝わっています。同州は2026年3月に調達の規則を改め、AIを使う予定とその方法の申告を応募企業に求めたと報じられています [ [ 485 ] ](https://theindependent.ca/news/lji/accounting-watchdog-to-investigate-deloitte-over-fake-citations-in-1-6-million-healthcare-report/) 。
- **xAI。** 2025年5月の無許可のシステムプロンプト変更に続き、7月にはコード更新後の約16時間に反ユダヤ的な投稿が出て謝罪したと報じられています [ [ 503 ] ](https://www.maginative.com/article/elon-musks-xai-apologizes-for-groks-antisemitic-rants-that-praised-hitler/) 。
もう1つは、評価済みの仕組みや運用してきた仕組みに更新を加えた後で、失敗が起きた例です。

- **DPD。** 同社の説明は、AI要素を数年間問題なく運用してきたがシステム更新の後に誤りが起きた、というものだと報じられています [ [ 462 ] ](https://www.theguardian.com/technology/2024/jan/20/dpd-ai-chatbot-swears-calls-itself-useless-and-criticises-firm) 。
- **Tessa。** 臨床試験を経たルールベースのチャットボットに、後から生成モデルのQ&A機能を加えたところ、指針を外れた回答が出たと報じられています [ [ 506 ] ](https://www.npr.org/sections/health-shots/2023/06/08/1180838096/an-eating-disorders-chatbot-offered-dieting-advice-raising-fears-about-ai-in-health) 。

### 7. 当事者が導入した工程上の対策

失敗の後に当事者が表明した対策には、評価そのものより、工程と権限を変えるものが多く含まれます。

- Replitのエージェントが本番データを削除した件で、CEOは開発用と本番用のデータベースの自動分離、計画だけを行うモード、ワンクリックでの復元を挙げました [ [ 491 ] ](https://x.com/amasad/status/1946986468586721478) 。
- xAIは、システムプロンプトをGitHubで公開すること、レビューなしの変更を防ぐ検査、自動の仕組みで捕まらない回答に対応する24時間体制の監視を挙げたと報じられています [ [ 502 ] ](https://techcrunch.com/2025/05/15/xai-blames-groks-obsession-with-white-genocide-on-an-unauthorized-modification) 。
- 誤りのある決定を出したアメリカの連邦判事の1人は、全ての起案に2回目の独立したレビューを課しました。引用した判例を全て印刷して最終稿に添付させています。もう1人は、書記官とインターンが起案にAIを使うことを書面で禁じました [ [ 456 ] ](https://www.judiciary.senate.gov/press/rep/releases/grassley-releases-judges-responses-owning-up-to-ai-use-calls-for-continued-oversight-and-regulation) 。
- Cursorの共同創業者は、メールサポートに使うAIの回答に今後は明示的にラベルを付けると述べました [ [ 463 ] ](https://www.theregister.com/2025/04/18/cursor_ai_support_bot_lies/) 。
- GoogleはAI Overviewsで、風刺とユーザー生成コンテンツの抑制、発動条件の制限を入れました [ [ 230 ] ](https://blog.google/products/search/ai-overviews-update-may-2024/) 。
- OpenAIは、2023年3月に他人のチャットの題名と支払情報の一部が見え得た障害の後、キャッシュから返すデータが要求者のものかを確かめる冗長な検査を挙げました [ [ 500 ] ](https://openai.com/index/march-20-chatgpt-outage/) 。

### 8. 「評価をしていないこと」を問う規制と判断

規制当局と裁判所は、出力の誤りだけでなく、事前の評価や確認の欠如を問題にしています。

- **英国の情報コミッショナー事務局(ICO)。** 2023年10月、ICOはSnapのMy AIで予備的な執行通知を出しました。子どもを含む利用者へのリスクを適切に評価しなかった、という暫定見解です。2024年5月の終結時には、Snapが改訂した影響評価を適合と認めています。ICOは、製品の市場投入より前にリスクを厳密に評価して軽減するよう求めました [ [ 513 ] ](https://ico.org.uk/about-the-ico/media-centre/news-and-blogs/2024/05/ico-warns-organisations-must-not-ignore-data-protection-risks-as-it-concludes-snap-my-ai-chatbot-investigation) 。
- **テキサス州司法長官。** 2024年9月、医療記録の要約を生成するPieces Technologiesと和解しました。同社は「重大な幻覚率が10万件に1件未満」などの精度の指標を広告していましたが、司法長官はそれが不正確だった可能性を指摘しました。和解は指標の定義と算出方法の開示などを求め、金銭の制裁はなく、同社は違反を否認しています [ [ 490 ] ](https://www.texasattorneygeneral.gov/news/releases/attorney-general-ken-paxton-reaches-settlement-first-its-kind-healthcare-generative-ai-investigation) 。
- **アメリカのFTC。** 2024年9月、消費者保護を担う連邦の機関であるFTCは、「ロボット弁護士」を称したDoNotPayについて、出力が弁護士の水準かを検証していなかったとして、193,000ドルの和解案を公表しました [ [ 514 ] ](https://www.ftc.gov/news-events/news/press-releases/2024/09/ftc-announces-crackdown-deceptive-ai-claims-schemes) 。
- **エア・カナダの審判所。** 2024年2月の決定は、同社がチャットボットの正確性を確保する合理的な注意を払わなかったと認定しました [ [ 459 ] ](https://decisions.civilresolutionbc.ca/crt/crtd/en/525448/1/document.do) 。
- **イタリアのデータ保護当局。** 2023年3月、ChatGPTの提供する情報が必ずしも実際のデータと一致しないことなどを理由に、処理の一時制限を命じました [ [ 509 ] ](https://garanteprivacy.it/garante/doc.jsp?ID=9870832) 。2024年12月には、侵害の未通知や透明性の義務違反などを理由に、1,500万ユーロの制裁金を公表しました。この制裁金の理由は、事前の評価の欠如ではありません。2026年3月18日、ローマ地方裁判所は判決(n. 4153/2026)でOpenAIの異議を認め、この処分を取り消しました。法律事務所の解説によれば、判決は管轄の問題で決着し、指摘された違反の中身は審理していません [ [ 1707 ] ](https://www.advant-nctm.com/news-e-approfondimenti/perche-il-tribunale-di-roma-ha-annullato-il-provvedimento-del-garante-su-openai) 。Garanteは、この判決を受けて決定を一時的に撤去したと注記しています [ [ 510 ] ](https://www.garanteprivacy.it/web/guest/home/docweb/-/docweb-display/docweb/10085432) 。判決が確定したかは、本書では確かめていません。

### 本章の要点と解釈

本節は、著者による解釈です。前節までの事実記述とは区別して読んでください。

著者は、本章の事例を本書の入力5項目・生成5項目に次のように対応させます。対応は著者の判断で、当事者が項目の名で説明したものではありません。

| 事例 | 主に対応する項目 | 欠けていた測り方(著者の見立て) |
| --- | --- | --- |
| Bingと、ChatGPTの長い対話 | G4安全 | 対話の長さを条件にした安全性の評価 |
| GPT-4oの迎合 | G5期待、G3事実 | 誤った前提への同意を測る評価、専門家の所見の扱い |
| Claudeの品質劣化 | G1〜G5 全体 | 本番での継続評価(成熟度ではV3) |
| AI Overviews | I3精度、I5出所 | 材料の種別と信頼度の判定 |
| Slack AI、EchoLeak、Comet | I5出所、G4安全 | 取り込んだ文書が指示として働かないかの評価 |
| 架空の判例、Deloitteの報告書 | G2忠実、G3事実 | 引用の実在と原典の照合 |
| エア・カナダ、Cursor | G2忠実 | 自社の方針文書との照合 |
| Geminiの画像生成 | G4安全 | 過剰拒否の率 |

- **空白は「評価セットに無い条件」に集中しています。** 長い対話、迎合、本番の基盤の劣化は、いずれも開発時の短い固定の評価には現れにくい条件です。著者は、評価の広さを決めるのは指標の数より、条件の幅だと考えます。
- **定量の信号が定性の警告を上書きしました。** GPT-4oの事例では、A/Bテストの数値が専門家の違和感より重く扱われました。著者は、少数の専門家の所見を、展開を止める権限として扱う設計が要ると考えます。
- **対策の多くは評価ではなく工程と権限です。** 環境の分離、変更のレビュー、引用の印刷添付、AIの回答の表示は、測定より前に失敗の経路を断つ手です。ICO、FTC、エア・カナダの審判所は、出力の正否より、事前の評価や注意の有無を問いました。

経営層と実務家への含意は、評価を「出荷前に1回通す試験」と考えないことです。著者は、本章の対策が示す型を、変更のたびの回帰評価、本番での継続評価、人の承認を置く権限の設計の3点にまとめます。これらを成熟度の段階として整理する作業は、[評価の成熟度の章](19-evaluation-maturity)で行います。
