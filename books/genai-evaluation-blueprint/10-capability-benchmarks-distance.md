### 序論：本章が扱う範囲

本書は、生成AIの出力が利用者の期待にどこまで近づいたかを測る評価を主題とします。一方、MMLUやGPQA、SWE-benchのような能力ベンチマークは、決まった問題集に対するモデルの正答率を測ります。本書は能力ベンチマークの歴史を主役にしません。本章は、その理由を事実で示す章です。

理由は3つの事実に分けられます。第一に、能力ベンチマークは作られてから短い期間で上限に近づきます(飽和)。第二に、問題がモデルの学習データに混入し、得点が能力を表さなくなります(汚染)。第三に、尺度と順位表は頻繁に作り替えられ、比べる相手そのものが動きます(入れ替わり)。本書は、この性質を計算機の処理性能の指標になぞらえて扱います。その比喩の当否は、章末の解釈の節で述べます。

ただし、能力ベンチマークの歴史は、評価の手法としては多くの工夫を残しました。本章の後半では、時間地平・汚染への対策・動的な評価・多指標の評価という、本書の評価にも転用できる手法を記します。審判モデル(LLM-as-a-judge)と順位表の運営の詳細は[審判としてのLLMの章](05-llm-as-judge)で扱いました。

### 1. 能力ベンチマークと、本書の評価の違い

能力ベンチマークの代表であるMMLUは、2020年9月7日に公開されました。57の科目の多肢選択で、テキストモデルの多分野の正答率を測ります [ [ 45 ] ](https://arxiv.org/abs/2009.03300) 。測る対象はモデルの能力であり、特定の応用の出力が利用者の期待に合うかどうかではありません。

この違いは、能力ベンチマークの登場と並行して指摘されてきました。2020年9月29日、EthayarajhとJurafskyは、順位表がモデルの大きさや遅延など、実務家にとっての効用を反映しない代理指標であると批判しました [ [ 47 ] ](https://arxiv.org/abs/2009.13888) 。2021年11月26日、Rajiらは、少数の影響力あるベンチマークが汎用的な進歩の尺度として扱われることについて、構成概念の妥当性の問題を指摘しました [ [ 50 ] ](https://arxiv.org/abs/2111.15366) 。

| 観点 | 能力ベンチマーク | 本書の評価 |
| --- | --- | --- |
| 測る対象 | モデルの能力 | 応用の出力と利用者の期待との距離 |
| 問題の出どころ | 公開された共通の問題集 | 自社の業務の入力と文書 |
| 正解の決め方 | 問題集の正答 | 業務の基準、専門家の判断 |
| 寿命 | 飽和すると作り替える | 業務が続く限り運用する |

### 2. 飽和：数年もつはずの尺度が数か月で上限に近づく

飽和は、LLMの時代より前から記録されています。2018年4月に公開されたGLUEは、9つの課題からなる言語理解のベンチマークでした [ [ 43 ] ](https://arxiv.org/abs/1804.07461) 。2019年5月のSuperGLUEは、公開から1年余りでGLUEの成績が非専門家の人の水準を超え、研究の余地が限られたことを理由に、より難しい課題群へ作り替えました [ [ 44 ] ](https://arxiv.org/abs/1905.00537) 。

LLMの時代に、飽和の間隔は短くなりました。

- **2025年1月24日**: Humanity's Last Exam(HLE)は、LLMがMMLUなどで90%を超える精度に達し、最先端の能力を測れなくなったことを動機に、専門家が作った2,500問を公開しました [ [ 60 ] ](https://arxiv.org/abs/2501.14249) 。
- **2025年4月**: Stanford AI Index 2025は、MMMU・GPQA・SWE-benchの成績が2023年の導入から1年で、それぞれ18.8・48.9・67.3ポイント上がったと記しました [ [ 669 ] ](https://hai.stanford.edu/ai-index/2025-ai-index-report) 。
- **2026年**: AI Index 2026は、AIの能力が、それを測るために作られたベンチマークを追い越していると述べました。数年は難しいはずの評価が数か月で飽和し、HLEでは最先端のモデルの成績が1年で30ポイント伸びています [ [ 630 ] ](https://hai.stanford.edu/ai-index/2026-ai-index-report/technical-performance) 。

### 3. 汚染：問題が学習データに混入する

汚染は、ベンチマークの得点が能力ではなく記憶を測ってしまう問題です。2022年3月15日、MagarとSchwartzは、ウェブ由来の事前学習データが下流のテスト集合で汚染されている問題に対し、記憶と利用を区別して定量化する方法を示しました [ [ 120 ] ](https://arxiv.org/abs/2203.08242) 。2023年11月3日のZhouらは、評価集合に関連するデータを学習に使う「ベンチマークの漏えい」が評価の結果を大きく押し上げると報告しました [ [ 121 ] ](https://arxiv.org/abs/2311.01964) 。

漏えいの影響は、作り直した問題で確かめられました。2024年5月1日、小学校の算数の問題集GSM8kを模して新しく作ったGSM1kでは、主要なモデルの精度が最大8%落ちました。報告は、いくつかのモデルの系列で系統的な過学習の証拠が見られるとしています [ [ 123 ] ](https://arxiv.org/abs/2405.00332) 。日本語では、llm-jp-evalのREADMEが、同ツールのデータで指示調整したモデルは、テストデータを使っていなくてもスコアを非常に高くできると自ら注意しています [ [ 137 ] ](https://github.com/llm-jp/llm-jp-eval) 。

2026年には、モデル自身が評価を見抜く事例も報告されました。Anthropicは2026年3月6日、Claude Opus 4.6がBrowseCompの評価中にテストされていると疑い、ベンチマークを特定して解答の鍵を復号した事例を公表しました。同社は、評価の完全性を設計時の問題ではなく、継続的な敵対的問題として扱うべきだと述べています [ [ 619 ] ](https://www.anthropic.com/engineering/eval-awareness-browsecomp) 。

### 4. 入れ替わり：順位表の操作と作り替え

順位表の順位は、評価の細部で動きます。2024年2月1日の研究は、MMLUなどの多肢選択のベンチマークで、選択肢の順序や答えの取り出し方を少し変えるだけで、順位が最大8位動くことを示しました [ [ 58 ] ](https://arxiv.org/abs/2402.01781) 。

人の投票による順位表にも、運営の方針をめぐる論争があります。2025年4月29日の「The Leaderboard Illusion」は、Chatbot Arenaで非公開の事前テストと選択的な公開が許され、MetaがLlama 4の公開前に27の非公開の変種を試したと指摘しました [ [ 82 ] ](https://arxiv.org/abs/2504.20879) 。主著者は競合するモデル提供者Cohereの研究者です。Arenaの運営は2025年5月9日に反論を公表し、未公開モデルの評価の方針は公開済みで、秘密の方針は無いと主張しました [ [ 83 ] ](https://arena.ai/blog/our-response) 。

ベンチマークそのものの作り替えも続いています。OpenAIは2024年8月、元のSWE-benchの問題点を理由に、人手で検証したSWE-bench Verifiedを公開しました [ [ 114 ] ](https://openai.com/index/introducing-swe-bench-verified/) 。2026年8月26日には、成功率0%で飽和した注入攻撃の評価を引退させたという記録も、提供事業者から出ています [ [ 327 ] ](https://claude.com/blog/claude-in-chrome-generally-available) 。

研究者の言説にも、能力ベンチマークへの信頼の低下が表れています。独立研究者のKarpathyは2025年3月2日、「評価の危機」があり、いまどの指標を見ればよいか分からないと投稿しました [ [ 646 ] ](https://x.com/karpathy/status/1896266683301659068) 。同年12月19日の年次総括では、2025年にベンチマークへの信頼を失ったと書いています [ [ 647 ] ](https://karpathy.bearblog.dev/year-in-review-2025) 。

### 5. 評価の手法として拾うもの

能力ベンチマークの歴史は、飽和と汚染に対抗する手法を残しました。本書の評価に転用できるものを4つ挙げます。

第一は**時間地平**です。METRは2025年3月18日、AIが50%の成功率で完了できる課題を、人が要する時間の長さで表す尺度を提案しました。最先端のモデルの時間地平は、2019年以降およそ7か月ごとに倍増していると報告しています [ [ 639 ] ](https://arxiv.org/abs/2503.14499) 。問題集の正答率と違い、作業の長さという業務に近い単位で測る点が特徴です。ただしこの尺度も限界に当たりました。METRは2026年5月8日、16時間を超える計測は現在の作業群では信頼できないと注記し、2026年9月8日にページを積極的には更新しないと明記しました [ [ 1108 ] ](https://metr.org/time-horizons) 。

第二は**汚染への対策**です。2018年のGLUEは、公平な利用のため、4つの課題でテストデータを非公開にしていました [ [ 43 ] ](https://arxiv.org/abs/1804.07461) 。2024年12月のFACTS Groundingも、公開と非公開の分割で順位表の健全性を守る設計をとっています [ [ 184 ] ](https://arxiv.org/abs/2501.03200) 。

第三は**動的な評価**です。2021年4月7日のDynabenchは、人とモデルを循環に入れてデータを作り続ける基盤として提案されました [ [ 49 ] ](https://arxiv.org/abs/2104.14337) 。2024年3月のLiveCodeBenchは競技サイトから新しい問題を集め続けます [ [ 122 ] ](https://arxiv.org/abs/2403.07974) 。2024年6月27日のLiveBenchは、最近の情報源から問題を月次で追加し、客観的な正解で自動採点します [ [ 1109 ] ](https://arxiv.org/abs/2406.19314) 。事実の鮮度を測るFreshQAも、データを週次で更新しています [ [ 219 ] ](https://arxiv.org/abs/2310.03214) 。

第四は**多指標の評価**です。2022年11月16日のHELMは、正確さに加えて較正・頑健さ・公平さ・毒性・効率などの7指標を同じ文脈で測りました。HELMより前は、モデルが中核のシナリオの平均17.9%でしか評価されていなかったと報告しています [ [ 53 ] ](https://arxiv.org/abs/2211.09110) 。

企業の側でも、公開のベンチマークより自社の評価を重視する傾向が報告されています。a16zの2025年6月の調査では、モデルの性能の評価で、社内のベンチマーク・ゴールデンセット・開発者の意見が依然として重要だとされました [ [ 409 ] ](https://a16z.com/ai-enterprise-2025/) 。

### 🗺️ 図：能力ベンチマークは、作られては飽和し、入れ替わり続ける

![GLUEからHLEまで、能力ベンチマークが飽和して作り替えられてきた経緯を階段で示した図](/images/genai-evaluation-blueprint/10-capability-benchmarks-distance.png)

#### 図の読み方

この図は、左下から右上へ上がる4段の階段です。各段は、それまでの尺度が飽和したために作られた新しい尺度を表します。左から、GLUE(2018年4月)・SuperGLUE(2019年5月)・MMLU(2020年9月)・HLE(2025年1月)です。各段の下の添え書きは、その尺度が作られた理由か、飽和の記録です。SuperGLUEは公開から1年余りでGLUEが非専門家の人の水準を超えたため、HLEはMMLUなどで90%を超えたために作られました。

読み順は左から右です。右端のHLEの段にある「1年で+30pt」は、HLEでも最先端のモデルの成績が1年で30ポイント伸びたという、AI Index 2026の記録です。いずれも第2節で引用した事実です。図の下の帯は、本書がこの階段から拾う4つの手法、すなわち時間地平・汚染への対策・動的な評価・多指標の評価を示します。

### 本章の要点と解釈

本節は、著者による解釈です。前節までの事実記述とは区別して読んでください。

要点は3つです。第一に、能力ベンチマークは2018年のGLUEから2025年のHLEまで、飽和しては作り替えられることを繰り返しており、その間隔は数年から数か月に縮みました。第二に、学習データへの混入・順位表の運営の方針・評価の細部の違いによって、得点が能力を表さない場合のあることが、繰り返し報告されています。第三に、それでも能力ベンチマークの歴史は、時間地平・非公開の分割・動的な更新・多指標という手法を残しました。

著者は、能力ベンチマークを、計算機の処理性能の指標のように扱うのが妥当だと考えます。導入するモデルを絞り込む最初のふるいとしては役に立ちます。しかし、その得点は世代が替わるたびに更新され、自社の応用で出力が期待に届くかどうかは教えてくれません。本書が能力ベンチマークを主役にしないのは、この理由によります。実務家への含意は、本章の第5節の手法を、自社の評価データの運用に取り入れることです。評価データの一部を開発者に見せない分割、業務の変化に合わせた定期の更新、正確さ以外の指標の併記は、どれも小さな組織で始められます。経営層にとっての含意は、提供事業者が掲げるベンチマークの得点を、導入の判断の根拠ではなく候補の絞り込みの材料として扱うことです。
