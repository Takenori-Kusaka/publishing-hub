### 序論：本章が扱う範囲

本章から第Ⅲ部に入ります。第Ⅰ部と第Ⅱ部では、評価の手法がどう生まれ、いま実務でどう使われているかを事実として整理しました。第Ⅲ部では、それらを1枚の枠組みに並べ直します。本章はその土台として、「期待値への距離」を、入力の層の5項目と生成の層の5項目、合わせて2層10項目に分けるモデルを定義します。距離は10項目の組み合わせで読み、1つの点数にはまとめません。

この10項目は著者による分類です。各項目に置く測り方(RAGAS、Sufficient Context、IFEval、FACTS Grounding、SimpleQA など)は実在する手法で、その定義と数値には出典を付けます。どの手法をどの項目に置くかは著者の判断であり、各手法の作者がこの分類を主張しているわけではありません。本章では、事実(手法の定義と数値)と枠組み(著者の分類)を書き分けます。

本章は項目の定義と、項目どうしの依存関係までを扱います。入力側の各項目の測り方は[入力側の評価の章](17-evaluating-input)で、生成側の各項目の測り方は[生成側の評価の章](18-evaluating-generation)で詳しく述べます。評価を組織で回す段階は[評価の成熟度の章](19-evaluation-maturity)で扱います。

### 1. 「期待値への距離」という問い

本書の主題は、ユーザーの入力に対する期待に、出力がどこまで近づいたかを測ることです。この問いを1つの点数で答えようとすると、どこで外れたかが分からなくなります。

外れる場所が2つに分かれることは、実測で示されています。Googleの研究者は2024年に、検索で集めた文脈が質問に答えるのに「十分か」を判定する自動判定器を作り、人手ラベルとの一致が93%以上だったと報告しました。大型のモデルは文脈が十分なら正答する一方、不十分なときは答えを控えずに誤答しがちでした [ [ 172 ] ](https://arxiv.org/abs/2411.06037) 。同じ研究のブログでは、Gemmaの誤答率が文脈なしの10.2%から、不十分な文脈を与えると66.1%に上がったと述べています [ [ 173 ] ](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/) 。

この数値は、情報を集める段階の失敗が、生成の誤りとして表に出ることを示します。出力だけを見て「幻覚(ハルシネーション)が多い」と判断すると、直すべき場所を取り違えます。本書が評価の対象を入力側と生成側に分けるのは、このためです。

### 2. 入力5項目：足りない情報をどう集めたか

入力側は、ユーザーの入力だけでは足りない情報を、検索拡張生成(RAG)・ツール・長文脈でどう集めたかを問います。著者はこれを次の5項目に分けます。

| 項目 | 問い | 代表的な測り方 |
| --- | --- | --- |
| I1必要 | 入力だけで足りないものは何か | 曖昧な質問の検出、明確化の質問 |
| I2十分 | 必要な情報が集まったか | 再現率、context recall、文脈の十分性 |
| I3精度 | 集めた情報は関係があるか、雑音は少ないか | 適合率、context precision、nDCG |
| I4鮮度 | 情報は古くないか | 時点つき質問応答、更新日 |
| I5出所 | 情報は信頼でき、使ってよいか | 出所(provenance)、権限 |

I1の根拠として、AmbigQAは質問応答の標準データの質問の半数超が曖昧だと報告しました [ [ 1301 ] ](https://arxiv.org/abs/2004.10645) 。I2とI3は、ライブラリのRagasが検索の評価に用意した「文脈の再現率」と「文脈の適合率」に対応します [ [ 1651 ] ](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/) [ [ 167 ] ](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/) 。I4は、毎週新しい質問で評価するRealTime QAのような動的な評価の系譜に当たります [ [ 218 ] ](https://arxiv.org/abs/2207.13332) 。I5の「出所」は、W3CのPROV-DMが「品質・信頼性・信用性の評価に使える情報」と定義した概念です [ [ 220 ] ](https://www.w3.org/TR/prov-dm/) 。評価の軸としては、2020年のKILTが、出力の正しさに加えて出所を示せるかを採点に含めました [ [ 164 ] ](https://arxiv.org/abs/2009.02252) 。

### 3. 生成5項目：集めた情報から期待へどう近づいたか

生成側は、集めた情報から期待する出力へどう近づいたかを問います。著者はこれを次の5項目に分けます。

| 項目 | 問い | 代表的な測り方 |
| --- | --- | --- |
| G1整形 | 期待した形になっているか | 指示追従(IFEval)、構造化出力、ツール呼び出しの形式と引数 |
| G2忠実 | 与えた根拠と一致しているか | 忠実性(faithfulness)、FACTS Grounding、引用の裏づけ |
| G3事実 | 世界の事実と一致しているか | 事実性(factuality)、SimpleQA、FActScore |
| G4安全 | 有害・漏えい・権限の逸脱・注入が無いか | ガードレール、拒否率と過剰拒否 |
| G5期待 | 有用で、課題を達成し、満足されたか | 課題達成率、ルーブリック、ペア比較、回答の関連性と完全さ |

G1の代表であるIFEvalは、「400語以上で書け」のように機械で検証できる25種の指示で指示追従を測ります [ [ 57 ] ](https://arxiv.org/abs/2311.07911) 。G2のFACTS Groundingは、与えた文書に根拠づけられた長文応答かを3つの審判モデルで判定します [ [ 184 ] ](https://arxiv.org/abs/2501.03200) 。G3のSimpleQAは、短い事実質問の回答を「正解・不正解・未回答」の3値で採点します [ [ 125 ] ](https://arxiv.org/abs/2411.04368) 。G4のXSTestは、答えるべき安全な問い250件と断るべき問い200件で、断りすぎを測ります [ [ 316 ] ](https://arxiv.org/abs/2308.01263) 。G5のτ-benchは、対話の後のデータベースの状態を目標の状態と比べて、課題を達成したかを判定します [ [ 115 ] ](https://arxiv.org/abs/2406.12045) 。Chatbot Arenaは利用者のペア比較の票を24万票超集めて順位を付けましたが [ [ 76 ] ](https://arxiv.org/abs/2403.04132) 、これはモデルどうしの公開の比較で、自社の用途での満足度ではありません。

引用の裏づけは、生成した文が、引いた出典に本当に支持されているかを問うので、著者はG2に置きます。ALCEは、引用の再現率と適合率を自動で評価する基準です [ [ 224 ] ](https://arxiv.org/abs/2305.14627) 。回答の関連性と完全さは、著者はG5に置きます。Amazon Bedrockの評価は検索と生成の指標に正しさと完全さを含め [ [ 241 ] ](https://aws.amazon.com/about-aws/whats-new/2025/03/amazon-bedrock-rag-evaluation-generally-available) 、MicrosoftのFoundryは根拠性を適合率の側面、回答の完全さを再現率の側面と位置づけています [ [ 242 ] ](https://learn.microsoft.com/en-us/azure/ai-foundry/concepts/evaluation-evaluators/rag-evaluators) 。G2が測るのは、出力の主張が根拠に支持されるかという適合率の側だけです。文脈にあった必要な情報を落とす誤りは、G5の完全さで測ります。

### 4. G2とG3を分ける理由

10項目のうち、最も混同されやすいのがG2(忠実)とG3(事実)です。両者を分ける根拠は、研究と事業者の文書の両方にあります。

Jiらの幻覚の調査論文は、忠実性を「与えた情報源に一貫して忠実であること」と定義し、事実性とは「何を事実とみなすか」次第で一致しない場合があると区別しました [ [ 246 ] ](https://arxiv.org/abs/2202.03629) 。OpenAIのGPT-4のシステムカードも、与えた文脈にない情報を作る幻覚と、文脈なしに世界について誤情報を述べる幻覚を分けて測っています [ [ 253 ] ](https://cdn.openai.com/papers/gpt-4-system-card.pdf) 。

2つが食い違う例もあります。DeepMindのGopherCiteは、引用で裏づけた回答の品質を測る中で「証拠に支持された主張がすべて真とは限らない」と警告しました [ [ 222 ] ](https://arxiv.org/abs/2203.11147) 。集めた文書が誤っていれば、忠実な出力ほど誤りを正確に写します。この場合、G2は満点でもG3は落ちます。原因はI5(出所)にあります。

### 5. 項目は上流から下流へ依存する

10項目は独立していません。著者は、上流の項目の失敗が下流の項目の数値に現れると考えます。

| 上流の失敗 | 下流に現れる症状 | 根拠 |
| --- | --- | --- |
| I2の不足 | G3の誤答の増加 | 不十分な文脈で誤答率が10.2%から66.1%に上がった [ [ 173 ] ](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/) |
| I3の雑音 | G2とG3の低下 | 妨害文が1つあるだけで性能が落ちた [ [ 195 ] ](https://www.trychroma.com/research/context-rot) |
| I4の古さ | G3で古い答えを返す | 取得文書に情報が足りないとGPT-3は古い答えを返した [ [ 218 ] ](https://arxiv.org/abs/2207.13332) |
| I5の出所の悪さ | G3で誤りを忠実に写す | 検索の要約が風刺記事やフォーラムの皮肉を取り込んだ [ [ 230 ] ](https://blog.google/products/search/ai-overviews-update-may-2024/) |

最後の行は、Googleが2024年5月に検索の要約機能の誤回答について説明した内容です。同社は原因を情報の乏しい「データの空白」、風刺、フォーラムの皮肉などとし、ユーザー生成コンテンツの利用を制限しました [ [ 230 ] ](https://blog.google/products/search/ai-overviews-update-may-2024/) 。これは生成の誤りとして報じられましたが、項目で見ればI5を中心とする入力側の失敗です。

依存の向きが分かると、測る順序も決まります。下流のG3だけを測って改善しようとすると、上流の原因に届きません。Deakin大学によるRAGの失敗点の研究は、7つの失敗点を整理したうえで「RAGシステムの検証は運用中にしかできない」と結論しました [ [ 198 ] ](https://arxiv.org/abs/2401.05856) 。項目ごとに測っておけば、運用中に数値が落ちたとき、どの項目で落ちたかを切り分けられます。

この研究が挙げた7つの失敗点は、内容の欠落、上位の文書の取り逃し、統合で文脈から落ちること、文脈から答えを取り出せないこと、形式の誤り、具体さの過不足、不完全な回答です [ [ 1751 ] ](https://arxiv.org/html/2401.05856v1) 。著者は、これを次の項目に当てます。

| 失敗点 | 著者が当てる項目 |
| --- | --- |
| 内容の欠落、統合で文脈から落ちる | I2十分 |
| 上位の文書の取り逃し | I3精度(順位)、I2十分 |
| 文脈から答えを取り出せない | G5期待(回答の関連性)。I3の雑音が原因のことが多い |
| 形式の誤り | G1整形 |
| 具体さの過不足 | G5期待。質問の曖昧さが原因ならI1必要 |
| 不完全な回答 | G5期待(完全さ) |

### 6. 10項目の外にあるもの

公開された失敗事例を項目に当てると、10項目だけでは説明しきれない部分が残ります。著者が[失敗の記録の章](11-failure-records)の事例を読む限り、多くの事例で生成側の誤りと人の確認の省略が同時に起きています。これは著者の読みで、2つの事例で示します。

Mata v. Aviancaでは、弁護士がChatGPTの作った実在しない判例を提出し、裁判所は「提出物の正確性を担保する門番の役割は弁護士にある」と述べました [ [ 289 ] ](https://national.clla.org/wp-content/uploads/2025/05/Mata-v-Avianca-Inc.pdf) 。架空の判例はG3を中心とする失敗ですが、実害の条件は人の確認がなかったことです。OpenAIは2025年のGPT-4oの迎合の件で、利用者の高評価を報酬に加えた更新が迎合に傾き、小規模なA/Bテストでは問題が出なかったと説明しました [ [ 303 ] ](https://openai.com/index/expanding-on-sycophancy/) 。これはG5の測り方そのものが外れた例です。

このように、10項目は「何を測るか」を定め、測る仕組みが組織で回っているかは別の軸になります。本書はその軸を評価の成熟度V0からV4として、[評価の成熟度の章](19-evaluation-maturity)で定義します。

本書の10項目が扱わない観点もあります。HELMは、正確さ・較正・頑健さ・公平さ・偏り・有害さ・効率の7つの指標を、同じ条件で測りました [ [ 53 ] ](https://arxiv.org/abs/2211.09110) 。このうち正確さはG2とG3、有害さはG4が扱います。頑健さ(言い換えや順序を変えても結果が保たれるか)、較正(出力の自信の度合いが実際の正しさに合うか)、公平さと偏り、効率(遅延や費用)は、10項目の外の観点として扱いません。較正のうち、知らない問いに答えない判断だけは、G3で未回答を正答・誤答から分けて数える形で触れます。用途によっては、これらを10項目とは別に測る必要があります。

### 7. 測れていない項目を見つける

10項目のモデルは、1つの点数を出すためのものではありません。期待値への距離は、10項目の組み合わせで読みます。著者は、10項目を点検表として使い、測れていない項目を見つけることに主な用途があると考えます。

| 点検の問い | 測れていないときに起きやすいこと |
| --- | --- |
| I1からI5のうち、数値を持たない項目はどれか | 生成の誤りとして現れ、原因を取り違える |
| G2とG3を同じ指標で測っていないか | 忠実だが誤った出力を見逃す |
| G4を有害出力と過剰拒否の両方で測っているか | 安全を上げて有用性を下げる |
| G5を利用者の評価だけで測っていないか | 迎合を報酬にしてしまう |

各項目の具体的な測り方は、次の2章で示します。入力側は[入力側の評価の章](17-evaluating-input)、生成側は[生成側の評価の章](18-evaluating-generation)です。

### 🗺️ 図：上流の失敗は、下流の誤りとして現れる

![入力の層の5項目(I1必要、I2十分、I3精度、I4鮮度、I5出所)と生成の層の5項目(G1整形、G2忠実、G3事実、G4安全、G5期待)を上下2段に並べ、最下段は到達点。上流の項目の失敗は下流の項目で表に出る](/images/genai-evaluation-blueprint/16-distance-to-expectation.png)

#### 図の読み方

この図は、3つの段を上から下へ積んでいます。上の段が入力の層の5項目で、ユーザーの入力に足りない情報を集める段階です。中の段が生成の層の5項目で、集めた情報から出力をつくる段階です。下の段に到達点を置きます。

読み順は上から下で、各段の中は左から右です。上の段の項目で失敗すると、その失敗は下の段の項目の数値に現れます。第5節の表が、その対応の根拠です。図の表題「上流の失敗は、下流の誤りとして現れる」が本章の主張です。

色は、入力の層を淡い藍、生成の層を濃い藍で塗り分け、到達点だけを千歳緑にしています。G5期待だけは丹の縁取りです。G5は期待の基準を人が決める項目で、[生成側の評価の章](18-evaluating-generation)の図と同じ色の規則にそろえました。

### 本章の位置づけ

本章の10項目は、著者による分類です。各項目の代表的な測り方は実在する手法で、その定義と数値は出典のとおりです。ただし、手法と項目の対応づけは著者の判断です。たとえばRAGASの忠実性はG2に置きましたが、RAGAS自身は入力側と生成側という分け方をしていません。

著者は、この分類の価値は2点にあると考えます。第一に、上流と下流を分けることで、誤りの原因の場所を特定しやすくなります。第二に、10項目を点検表として使うことで、測れていない項目が見えます。次章からは、各項目をどう測るかを、項目ごとに出典つきで示します。
