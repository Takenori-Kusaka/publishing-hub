### 序論：本章が扱う範囲

本章から第Ⅲ部に入ります。第Ⅰ部と第Ⅱ部では、評価の手法がどう生まれ、いま実務でどう使われているかを事実として整理しました。第Ⅲ部では、それらを1枚の枠組みに並べ直します。本章はその土台として、「期待値への距離」を入力5層と生成5層の合計10層に分けるモデルを定義します。

この10層は著者による分類です。各層に置く測り方(RAGAS、Sufficient Context、IFEval、FACTS Grounding、SimpleQA など)は実在する手法で、その定義と数値には出典を付けます。どの手法をどの層に置くかは著者の判断であり、各手法の作者がこの分類を主張しているわけではありません。本章では、事実(手法の定義と数値)と枠組み(著者の分類)を書き分けます。

本章は層の定義と、層どうしの依存関係までを扱います。入力側の各層の測り方は[入力側の評価の章](17-evaluating-input)で、生成側の各層の測り方は[生成側の評価の章](18-evaluating-generation)で詳しく述べます。評価を組織で回す段階は[評価の成熟度の章](19-evaluation-maturity)で扱います。

### 1. 「期待値への距離」という問い

本書の主題は、ユーザーの入力に対する期待に、出力がどこまで近づいたかを測ることです。この問いを1つの点数で答えようとすると、どこで外れたかが分からなくなります。

外れる場所が2つに分かれることは、実測で示されています。Googleの研究者は2024年に、検索で集めた文脈が質問に答えるのに「十分か」を判定する自動判定器を作り、人手ラベルとの一致が93%以上だったと報告しました。大型のモデルは文脈が十分なら正答する一方、不十分なときは答えを控えずに誤答しがちでした [ [ 172 ] ](https://arxiv.org/abs/2411.06037) 。同じ研究のブログでは、Gemmaの誤答率が文脈なしの10.2%から、不十分な文脈を与えると66.1%に上がったと述べています [ [ 173 ] ](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/) 。

この数値は、情報を集める段階の失敗が、生成の誤りとして表に出ることを示します。出力だけを見て「幻覚(ハルシネーション)が多い」と判断すると、直すべき場所を取り違えます。本書が評価の対象を入力側と生成側に分けるのは、このためです。

### 2. 入力5層：足りない情報をどう集めたか

入力側は、ユーザーの入力だけでは足りない情報を、検索拡張生成(RAG)・ツール・長文脈でどう集めたかを問います。著者はこれを次の5層に分けます。

| 層 | 問い | 代表的な測り方 |
| --- | --- | --- |
| I1必要 | 入力だけで足りないものは何か | 曖昧な質問の検出、明確化の質問 |
| I2十分 | 必要な情報が集まったか | 再現率、context recall、文脈の十分性 |
| I3精度 | 集めた情報は関係があるか、雑音は少ないか | 適合率、context precision、nDCG |
| I4鮮度 | 情報は古くないか | 時点つき質問応答、更新日 |
| I5出所 | 情報は信頼でき、使ってよいか | 出所(provenance)、権限、引用の正確さ |

I1の根拠として、AmbigQAは質問応答の標準データの質問の半数超が曖昧だと報告しました [ [ 1301 ] ](https://arxiv.org/abs/2004.10645) 。I2とI3は、RAGASが検索の評価を「文脈の再現率」と「文脈の適合率」として定義したことに対応します [ [ 167 ] ](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/) 。I4は、毎週新しい質問で評価するRealTime QAのような動的な評価の系譜に当たります [ [ 218 ] ](https://arxiv.org/abs/2207.13332) 。I5の「出所」は、W3CのPROV-DMが「品質・信頼性・信用性の評価に使える情報」と定義した概念です [ [ 220 ] ](https://www.w3.org/TR/prov-dm/) 。

### 3. 生成5層：集めた情報から期待へどう近づいたか

生成側は、集めた情報から期待する出力へどう近づいたかを問います。著者はこれを次の5層に分けます。

| 層 | 問い | 代表的な測り方 |
| --- | --- | --- |
| G1整形 | 期待した形になっているか | 指示追従(IFEval)、構造化出力 |
| G2忠実 | 与えた根拠と一致しているか | 忠実性(faithfulness)、FACTS Grounding |
| G3事実 | 世界の事実と一致しているか | 事実性(factuality)、SimpleQA、FActScore |
| G4安全 | 有害・漏えい・注入が無いか | ガードレール、拒否率と過剰拒否 |
| G5期待 | 有用で、課題を達成し、満足されたか | ペア比較、ルーブリック、課題達成率 |

G1の代表であるIFEvalは、「400語以上で書け」のように機械で検証できる25種の指示で指示追従を測ります [ [ 57 ] ](https://arxiv.org/abs/2311.07911) 。G2のFACTS Groundingは、与えた文書に根拠づけられた長文応答かを3つの審判モデルで判定します [ [ 184 ] ](https://arxiv.org/abs/2501.03200) 。G3のSimpleQAは、短い事実質問の回答を「正解・不正解・未回答」の3値で採点します [ [ 125 ] ](https://arxiv.org/abs/2411.04368) 。G4のXSTestは、答えるべき安全な問い250件と断るべき問い200件で、断りすぎを測ります [ [ 316 ] ](https://arxiv.org/abs/2308.01263) 。G5のChatbot Arenaは、利用者のペア比較の票を24万票超集めて順位を付けました [ [ 76 ] ](https://arxiv.org/abs/2403.04132) 。

### 4. G2とG3を分ける理由

10層のうち、最も混同されやすいのがG2(忠実)とG3(事実)です。両者を分ける根拠は、研究と事業者の文書の両方にあります。

Jiらの幻覚の調査論文は、忠実性を「与えた情報源に一貫して忠実であること」と定義し、事実性とは「何を事実とみなすか」次第で一致しない場合があると区別しました [ [ 246 ] ](https://arxiv.org/abs/2202.03629) 。OpenAIのGPT-4のシステムカードも、与えた文脈にない情報を作る幻覚と、文脈なしに世界について誤情報を述べる幻覚を分けて測っています [ [ 253 ] ](https://cdn.openai.com/papers/gpt-4-system-card.pdf) 。

2つが食い違う例もあります。DeepMindのGopherCiteは、引用で裏づけた回答の品質を測る中で「証拠に支持された主張がすべて真とは限らない」と警告しました [ [ 222 ] ](https://arxiv.org/abs/2203.11147) 。集めた文書が誤っていれば、忠実な出力ほど誤りを正確に写します。この場合、G2は満点でもG3は落ちます。原因はI5(出所)にあります。

### 5. 層は上流から下流へ依存する

10層は独立していません。著者は、上流の層の失敗が下流の層の数値に現れると考えます。

| 上流の失敗 | 下流に現れる症状 | 根拠 |
| --- | --- | --- |
| I2の不足 | G3の誤答の増加 | 不十分な文脈で誤答率が10.2%から66.1%に上がった [ [ 173 ] ](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/) |
| I3の雑音 | G2とG3の低下 | 妨害文が1つあるだけで性能が落ちた [ [ 195 ] ](https://www.trychroma.com/research/context-rot) |
| I4の古さ | G3で古い答えを返す | 取得文書に情報が足りないとGPT-3は古い答えを返した [ [ 218 ] ](https://arxiv.org/abs/2207.13332) |
| I5の出所の悪さ | G3で誤りを忠実に写す | 検索の要約が風刺記事やフォーラムの皮肉を取り込んだ [ [ 230 ] ](https://blog.google/products/search/ai-overviews-update-may-2024/) |

最後の行は、Googleが2024年5月に検索の要約機能の誤回答について説明した内容です。同社は原因を情報の乏しい「データの空白」、風刺、フォーラムの皮肉などとし、ユーザー生成コンテンツの利用を制限しました [ [ 230 ] ](https://blog.google/products/search/ai-overviews-update-may-2024/) 。これは生成の誤りとして報じられましたが、層で見れば入力側のI5の失敗です。

依存の向きが分かると、測る順序も決まります。下流のG3だけを測って改善しようとすると、上流の原因に届きません。Deakin大学によるRAGの失敗点の研究は、7つの失敗点を整理したうえで「RAGシステムの検証は運用中にしかできない」と結論しました [ [ 198 ] ](https://arxiv.org/abs/2401.05856) 。層ごとに測っておけば、運用中に数値が落ちたとき、どの層で落ちたかを切り分けられます。

### 6. 10層の外にある「運用」

公開された失敗事例を層に当てると、10層だけでは説明しきれない部分が残ります。著者が[失敗の記録の章](11-failure-records)の事例を読む限り、多くの事例で生成側の誤りと人の確認の省略が同時に起きています。これは著者の読みで、2つの事例で示します。

Mata v. Aviancaでは、弁護士がChatGPTの作った実在しない判例を提出し、裁判所は「提出物の正確性を担保する門番の役割は弁護士にある」と述べました [ [ 289 ] ](https://national.clla.org/wp-content/uploads/2025/05/Mata-v-Avianca-Inc.pdf) 。架空の判例はG3の失敗ですが、実害の条件は人の確認がなかったことです。OpenAIは2025年のGPT-4oの迎合の件で、利用者の高評価を報酬に加えた更新が迎合に傾き、小規模なA/Bテストでは問題が出なかったと説明しました [ [ 303 ] ](https://openai.com/index/expanding-on-sycophancy/) 。これはG5の測り方そのものが外れた例です。

このように、10層は「何を測るか」を定め、測る仕組みが組織で回っているかは別の軸になります。本書はその軸を評価の成熟度V0からV4として、[評価の成熟度の章](19-evaluation-maturity)で定義します。

### 7. 測れていない層を見つける

10層のモデルは、1つの合計点を出すためのものではありません。著者は、10層を点検表として使い、測れていない層を見つけることに主な用途があると考えます。

| 点検の問い | 測れていないときに起きやすいこと |
| --- | --- |
| I1からI5のうち、数値を持たない層はどれか | 生成の誤りとして現れ、原因を取り違える |
| G2とG3を同じ指標で測っていないか | 忠実だが誤った出力を見逃す |
| G4を有害出力と過剰拒否の両方で測っているか | 安全を上げて有用性を下げる |
| G5を利用者の評価だけで測っていないか | 迎合を報酬にしてしまう |

各層の具体的な測り方は、次の2章で示します。入力側は[入力側の評価の章](17-evaluating-input)、生成側は[生成側の評価の章](18-evaluating-generation)です。

#### 図の読み方

この図は、3つの段を上から下へ積んでいます。上の段が入力側の5層で、ユーザーの入力に足りない情報を集める段階です。中の段が生成側の5層で、集めた情報から出力をつくる段階です。下の段に、到達点の「期待」を置きます。

読み順は上から下で、各段の中は左から右です。上の層で失敗すると、その失敗は下の層の数値に現れます。第5節の表が、その対応の根拠です。図の下の一文「上流の失敗は下流の誤りとして現れる」が本章の主張です。

色は、入力側と生成側のどちらも機械が担う部分なので藍で塗り、到達点の期待だけを千歳緑にしています。

### 本章の位置づけ

本章の10層は、著者による分類です。各層の代表的な測り方は実在する手法で、その定義と数値は出典のとおりです。ただし、手法と層の対応づけは著者の判断です。たとえばRAGASの忠実性はG2に置きましたが、RAGAS自身は入力側と生成側という分け方をしていません。

著者は、この分類の価値は2点にあると考えます。第一に、上流と下流を分けることで、誤りの原因の場所を特定しやすくなります。第二に、10層を点検表として使うことで、測れていない層が見えます。次章からは、各層をどう測るかを、層ごとに出典つきで示します。
