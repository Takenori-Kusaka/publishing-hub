### 序論：本章が扱う範囲

本章は、[期待値への距離の章](16-distance-to-expectation)で定義した生成5層(G1整形、G2忠実、G3事実、G4安全、G5期待)の測り方を、層ごとに示します。各手法の定義と数値は一次資料から引き、手法と層の対応づけは著者の分類として示します。

生成側の評価の系譜は、第Ⅰ部の[審判としてのLLMの章](05-llm-as-judge)、[幻覚の計測の章](07-hallucination-measurement)、[ガードレールの系譜の章](08-guardrails-lineage)で述べました。本章は、それらを層ごとに並べ直し、いま使える測り方と、その限界を示します。

入力側の評価は[入力側の評価の章](17-evaluating-input)で扱いました。本章では、必要な情報が集まった前提で、そこから出力がどこまで期待に近づいたかを問います。

### 1. 生成側の評価の骨格

生成側の採点の方法は、3つの系統に分かれます。Anthropicの開発者向け文書は、採点の方法としてコードによる採点、人手による採点、大規模言語モデル(LLM)による採点の3つを挙げ、採点には生成とは別のモデルを使うことを勧めています [ [ 352 ] ](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests) 。LLMに採点させる方法は、審判モデル(LLM-as-a-judge)と呼ばれます。

3つの系統は、層によって向き不向きがあります。著者の整理では、G1はコードで、G2とG3は審判モデルか専用の分類器で、G5は人の判断を基準にして測るのが基本です。G4は分類器と人の攻撃役を組み合わせます。

### 2. G1整形：期待した形になっているか

G1は、出力が指示した形式・長さ・構造を守ったかを問います。機械で検証できる層です。

IFEvalは、「400語以上で書け」「AIという語を3回以上使え」のように検証できる25種の指示を含む約500のプロンプトで、指示追従を測ります。人手評価と審判モデルの双方の弱点を避ける設計です [ [ 57 ] ](https://arxiv.org/abs/2311.07911) 。FollowBenchは、内容・状況・文体・形式・例示の5種の制約を1つずつ積み増して、どこで追従が崩れるかを測ります [ [ 296 ] ](https://arxiv.org/abs/2310.20410) 。

構造化出力では、「測る」から「保証する」への移行が起きました。OpenAIは2024年8月、JSONの構文の有効性を保証する従来の方式はスキーマへの適合を保証しないと認めました。複雑なスキーマへの追従は、学習だけで93%、制約付きデコーディングを重ねて100%になったと報告しています [ [ 295 ] ](https://openai.com/index/introducing-structured-outputs-in-the-api/) 。この数値は同社の社内評価です。

長さは、G1とG5の境界にある論点です。AlpacaEvalは長い出力を好む偏りが知られており、長さを統計的に統制すると、Chatbot Arenaとの順位相関が0.94から0.98に上がりました [ [ 78 ] ](https://arxiv.org/abs/2404.04475) 。

### 3. G2忠実：与えた根拠と一致しているか

G2は、出力が与えた文脈に支持されているかを問います。世界の事実と合うかは問いません。

RAGASのFaithfulnessは、応答の主張のうち取得文脈で支持される数を、主張の総数で割った値です。公式文書の例では、2つの主張のうち1つが支持される回答は0.5になります [ [ 166 ] ](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/) 。Vertex AIの評価テンプレートは、根拠性を「完全に根拠がある」か否かの0と1で採点します [ [ 243 ] ](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/metrics-templates) 。

FACTS Groundingは、最大32kトークンの文書に対する長文応答を、3つの審判モデルで2段階に採点します。まず利用者の要求を満たさない応答を失格にし、次に文書に完全に根拠づけられているかを判定します [ [ 184 ] ](https://arxiv.org/abs/2501.03200) 。複数の審判の平均を取るのは、審判の偏りを和らげるためです。

審判モデルの代わりに、小型の分類器も使えます。MiniCheckは、GPT-4級の事実検証の性能を400分の1の費用で出せると報告しました [ [ 1303 ] ](https://arxiv.org/abs/2404.10774) 。ただし、幻覚率の数値は評価器とデータが変わると連続しません。Vectaraの順位表は、2023年にGPT-4を3.0%としましたが、2026年の版では評価モデルとデータが替わっています [ [ 279 ] ](https://github.com/vectara/hallucination-leaderboard/) 。数値を比べるときは、時点・評価器・データの3つをそろえる必要があります。

### 4. G3事実：世界の事実と一致しているか

G3は、出力が世界の事実と合うかを問います。G2と違い、与えた文脈の外にある真偽を見ます。

採点の設計が、幻覚の量を左右します。SimpleQAは短答の事実質問を「正解・不正解・未回答」の3値で採点し、知らない問いには答えないことを理想に組み込みました [ [ 125 ] ](https://arxiv.org/abs/2411.04368) 。OpenAIのKalaiらは2025年、評価が不確実さの表明より当て推量に報酬を与えるため幻覚が残ると論じ、既存の基準の採点を変えるべきだと主張しました [ [ 110 ] ](https://arxiv.org/abs/2509.04664) 。

正答率と誤答率は、別々に見る必要があります。OpenAIのo3のシステムカードでは、人物の事実を問うPersonQAの幻覚率がo3で0.33、o1で0.16でした。同社は、o3が主張を多くするため、正しい主張と誤った主張の両方が増えると説明しています [ [ 334 ] ](https://cdn.openai.com/pdf/2221c875-02dc-4789-800b-e7758f3722c1/o3-and-o4-mini-system-card.pdf) 。

長文の事実性は、主張を分解して数えます。FActScoreは長文を原子的な事実に分け、信頼できる知識源に支持される割合を測りました。人物伝でChatGPTは58%でした。13のモデルの6,500件の生成を人手で評価すれば2.6万ドルかかる作業を、誤差2%未満の自動推定で置き換えています [ [ 39 ] ](https://arxiv.org/abs/2305.14251) 。DeepMindのSAFEは、検索で各事実を検証する自動評価で、人手との一致が72%、費用は人手の20分の1以下でした [ [ 40 ] ](https://arxiv.org/abs/2403.18802) 。

### 5. G4安全：有害・漏えい・注入が無いか

G4は、出力が有害でないか、情報を漏らさないか、注入された指示に従わないかを問います。この層は、2つの向きで同時に測ります。

| 向き | 問い | 測り方の例 |
| --- | --- | --- |
| 見逃し | 断るべき要求に応じたか | 違反要求への無害応答率、脱獄成功率 |
| 断りすぎ | 応じるべき要求を断ったか | 良性要求の過剰拒否率(XSTest) |

XSTestは、答えるべき安全な問い250件と、対照の危険な問い200件で、似た言葉を含む安全な問いまで断る「過剰な安全」を測ります [ [ 316 ] ](https://arxiv.org/abs/2308.01263) 。AnthropicのClaude Opus 4のシステムカードは、違反要求の98.43%超を拒否したこと、良性要求の過剰拒否率が0.07%だったことを並べて報告しています [ [ 324 ] ](https://www-cdn.anthropic.com/6d8a8055020700718b0c49369f60816ba2a7c285.pdf) 。

ガードレールの費用も測れます。AnthropicのConstitutional Classifiersは、自動評価での脱獄成功率を86%から4.4%に下げた一方、本番の拒否率を0.38ポイント上げ、推論の費用を23.7%増やしました [ [ 314 ] ](https://arxiv.org/abs/2501.18837) 。分類器の部品としては、MetaのLlama Guardのように入出力を判定する安全分類器が公開されています [ [ 311 ] ](https://ai.meta.com/blog/purple-llama-open-trust-safety-generative-ai/) 。

プロンプトインジェクションは、数値の条件に特に注意が要ります。AgentDojoは、ツールを使うエージェントに97の課題と629の攻撃試験を課す評価環境です [ [ 319 ] ](https://arxiv.org/abs/2406.13352) 。Anthropicは2026年8月、成功率0%で飽和した旧評価を引退させ、専門のレッドチームによる強い攻撃の新評価に替えました [ [ 327 ] ](https://claude.com/blog/claude-in-chrome-generally-available) 。攻撃の試行回数と環境で桁が変わるため、単一の割合を性能の見出しにしないことが肝要です。

### 6. G5期待：有用で、課題を達成し、満足されたか

G5は、出力が利用者にとって役立ったかを問います。何を基準にするかで、4つの測り方があります。

| 測り方 | 基準 | 例 |
| --- | --- | --- |
| ペア比較 | 2つの出力のどちらを好むか | Chatbot Arenaは24万票超を集めた [ [ 76 ] ](https://arxiv.org/abs/2403.04132) |
| ルーブリック | 専門家が書いた採点基準 | HealthBenchは医師が書いた48,562の基準で採点する [ [ 299 ] ](https://openai.com/index/healthbench/) |
| 課題達成 | 最終状態が目標と一致するか | τ-benchは対話後のデータベースの状態を目標と比べる [ [ 115 ] ](https://arxiv.org/abs/2406.12045) |
| 利用者の信号 | 高評価・低評価、利用の継続 | ChatGPTの高評価・低評価のデータ [ [ 303 ] ](https://openai.com/index/expanding-on-sycophancy/) |

それぞれに弱点があります。ペア比較の順位は、回答の長さとMarkdownの装飾を統制すると動きました [ [ 80 ] ](https://lmsys.org/blog/2024-08-28-style-control/) 。課題達成では、τ-benchでgpt-4o級のエージェントでも成功率が50%未満で、小売の領域では8回続けて成功する率が25%未満でした [ [ 115 ] ](https://arxiv.org/abs/2406.12045) 。1回の成功ではなく、繰り返しの安定性を測る必要があります。

利用者の信号を報酬にすると、迎合を招くことがあります。OpenAIは、2025年4月のGPT-4oの更新にChatGPTの高評価・低評価に基づく報酬を加えたことで、応答が迎合に傾いたと説明しました [ [ 303 ] ](https://openai.com/index/expanding-on-sycophancy/) 。同社はその後、迎合を採点して報酬信号にし、オフライン評価の迎合の値がGPT-4oの0.145からgpt-5-mainで0.052に下がったと報告しています [ [ 304 ] ](https://cdn.openai.com/gpt-5-system-card.pdf) 。

### 7. 生成側の評価の組み方

5層の測り方を、採点の系統と、数値を読むときの注意で整理します。この表は著者による整理です。

| 層 | 主な採点の系統 | 数値を読むときの注意 |
| --- | --- | --- |
| G1整形 | コード | 制約付きデコーディングで保証できる部分は測るより保証する |
| G2忠実 | 審判モデル、分類器 | 評価器とデータが替わると数値は連続しない |
| G3事実 | 審判モデル、検索による検証 | 正答率と誤答率と未回答率を分けて出す |
| G4安全 | 分類器、人の攻撃役 | 見逃しと断りすぎを同時に出す。試行回数を添える |
| G5期待 | 人、ルーブリックつきの審判モデル | 利用者の信号だけを報酬にしない |

### 本章の位置づけ

本章の5層への分類と、層ごとの採点の系統の整理は、著者によるものです。各手法の定義と数値は、出典に示した発表者の評価条件での値です。特に、提供事業者のシステムカードの数値は、その事業者の社内評価です。

著者は、生成側の評価で最も見落とされやすいのはG4の断りすぎと、G5の迎合だと考えます。どちらも、安全や満足という1つの指標を上げる過程で、別の性質を損なう失敗です。1つの層に2つの向きの指標を持たせることが、この失敗への備えになります。
