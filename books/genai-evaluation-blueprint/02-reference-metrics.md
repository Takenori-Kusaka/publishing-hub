### 序論：本章が扱う範囲

本章は、機械の出力を「人が書いた参照(正解の文)」と照らし合わせて自動で採点する指標の時代を扱います。期間はおおむね2002年から2018年で、批判の検証は2021年まで追います。期待への近さの定義は、参照の文と語がどれだけ重なるかでした。

[人が測っていた時代の章](01-human-judgement-era)で見たとおり、それまでの評価は人の判定に頼っていました。本章の指標は、その判定が高価で遅いという限界から生まれています。本章は、指標の誕生、改良、批判の順に記します。

参照との一致は、のちに意味の一致へ移ります。その移行は[意味の一致の章](03-learned-metrics)で扱います。参照を使わずに人の選好で測る流れは[嗜好の学習の章](04-preference-learning)で扱います。

### 1. BLEU：熟練した判定者の「代役」

2002年7月、IBMのKishore Papineniらは、機械翻訳の自動評価法BLEUを発表しました。論文は動機を次のように述べています。人による翻訳の評価は網羅的だが高価で、終わるまでに数か月かかり、その労力は再利用できません [ [ 17 ] ](https://aclanthology.org/P02-1040/) 。

BLEUは、機械の訳文と人の参照訳とで、連続する語の並び(n-gram)がどれだけ重なるかを数えます。論文は、この方法が速く安価で、言語に依存せず、人の評価と高く相関すると主張しました。そのうえで、素早く頻繁な評価が必要なときに「熟練した人間の判定者の代わりを務める自動の代役(understudy)」と位置づけています [ [ 17 ] ](https://aclanthology.org/P02-1040/) 。

同じ2002年、NISTのGeorge Doddingtonは、BLEUを改変したn-gramの共起統計による自動評価を発表しました [ [ 8 ] ](https://doi.org/10.3115/1289189.1289273) 。この時代の「期待への近さ」は、人が書いた参照の語の並びにどれだけ近いかです。期待の中身は、参照を書いた人の訳に置かれています。

### 2. ROUGE と改良の系譜

2004年7月、Chin-Yew Linは要約の自動評価パッケージROUGEを公開しました。ROUGEは、要約の品質を、人が作った理想の要約との比較で自動判定する一連の尺度です。名前の由来は「要旨評価のための、再現率に重きを置いた代役」です [ [ 18 ] ](https://aclanthology.org/W04-1013/) 。Linは動機として、要約の評価会議DUCの人手評価が3,000時間を超える人の労力を要し、高価で頻繁には行えないことを挙げています [ [ 18 ] ](https://aclanthology.org/W04-1013/) 。

その後の指標は、語の表面の一致を少しずつ緩めていきました。

- **METEOR(2005年6月)**: 語幹と同義語を含めて単語の一致を広げ、語順の断片化に罰則を付けました。文ごとの人手評価との相関はPearsonのRでアラビア語0.347、中国語0.331でした [ [ 19 ] ](https://aclanthology.org/W05-0909/) 。
- **CIDEr(2014年11月)**: 画像の説明文の評価に、複数の人の説明の合意(consensus)を測る考え方を導入しました [ [ 22 ] ](https://arxiv.org/abs/1411.5726) 。
- **chrF(2015年9月)**: 文字のn-gramでF値を計算します。変種のchrF3は、英語からの翻訳でWMT14の共通評価課題の最良の指標を上回る文単位の相関を示しました [ [ 23 ] ](https://aclanthology.org/W15-3049/) 。

指標そのものを人の評価との相関で検証する場も作られました。機械翻訳の国際会議WMTのMetrics Shared Taskはその1つで、2014年の結果報告が残っています [ [ 24 ] ](https://aclanthology.org/W14-3336/) 。

### 3. 批判：改善は必要条件でも十分条件でもない

指標が広まると、指標と人の評価との食い違いを示す例が報告されました。

2006年4月、Chris Callison-Burchらは、機械翻訳の研究がBLEUに依存しすぎていると論じました。BLEUのスコアの改善は、翻訳品質の実際の改善の必要条件でも十分条件でもないと示しています。反例の1つでは、規則ベースのシステムSystranの品質をBLEUが大幅に過小評価していました [ [ 20 ] ](https://aclanthology.org/E06-1032/) 。同じ会議で、Anja BelzとEhud Reiterは、言語生成システムの自動評価と人手評価の比較を発表しました [ [ 21 ] ](https://aclanthology.org/E06-1040/) 。

2017年7月、Jekaterina Novikovaらは、データ駆動の言語生成について、語に基づく指標が人の評価を弱くしか反映しないことを示しました。指標の性能はデータとシステムによって変わるとし、論文の題で「新しい評価指標が必要」と訴えています [ [ 25 ] ](https://arxiv.org/abs/1707.06875) 。

2018年9月、Ehud ReiterはBLEUの妥当性を体系的に検討しました。34本の論文が報告した284の相関を調べ、BLEUは本来の用途である機械翻訳システムの診断的な評価には支持されると結論しています。一方で、機械翻訳以外の用途、個別の文章の評価、科学的な仮説の検定への使用は支持されないとしました [ [ 26 ] ](https://aclanthology.org/J18-3002/) 。

### 4. 批判の定量化：誤った展開判断

2020年以降の研究は、指標の問題を規模の大きなデータで定量化しました。

- **メタ評価の脆さ(2020年6月)**: 指標の良し悪しを判定する方法そのものが、評価に使う訳文、特に外れ値に強く左右され、指標の有効性について誤って自信を持った結論を導きやすいと示されました [ [ 27 ] ](https://arxiv.org/abs/2006.06264) 。
- **要約の再評価(2020年7月)**: SummEvalは、14の自動指標と23の要約モデルを、専門家とクラウドの人手評価を使い、一貫した方法により再評価しました [ [ 29 ] ](https://arxiv.org/abs/2007.12626) 。
- **ROUGE の20年(2020年10月)**: 約20年にわたりROUGEが要約論文の標準の評価であったこと、古いデータセットでの指標の結論が現代のデータセットとシステムには必ずしも当てはまらないことが報告されました [ [ 30 ] ](https://arxiv.org/abs/2010.07100) 。
- **展開判断への影響(2021年7月)**: Microsoftの研究者らは、4,380のシステムと230万件の文単位の人手評価を使って自動指標の信頼性を検証しました。BLEUだけを使うことが改良モデルの開発を妨げ、誤った展開判断につながったと結論しています [ [ 28 ] ](https://arxiv.org/abs/2107.10821) 。

最後の研究は、指標の誤りが研究上の問題にとどまらず、製品を出すかどうかの判断に影響したことを示しています。

### 5. 参照との一致の整理

| 指標 | 発表 | 何との一致か | 人の評価との関係の報告 | 後の批判 |
| --- | --- | --- | --- | --- |
| BLEU | 2002年7月 | 参照訳のn-gram | 人の評価と高く相関すると主張 | 改善は必要条件でも十分条件でもない(2006年) |
| ROUGE | 2004年7月 | 理想の要約 | 人手評価の3,000時間超を代替する動機 | 古い結論が現代のシステムに当てはまらない(2020年) |

| CIDEr | 2014年11月 | 複数の人の説明の合意 | ― | ― |

表の「―」は、本章が依拠した資料に該当の記述が無いことを示します。

#### 図の読み方

この図は、左から右へ流れる3つの枠で構成されています。左の枠は人の判定で、費用の例として「数か月」(BLEUの論文)と「3,000時間超」(ROUGEの論文)を置いています。中央の枠は、その代役として生まれたBLEU(2002年)とROUGE(2004年)です。右の枠は、代役と人の評価の食い違いを示した3つの批判です。2006年の「改善は必要条件でも十分条件でもない」、2018年の「機械翻訳以外への使用は支持されない」、2021年の「BLEUだけでは誤った展開判断を招いた」です。

読み順は左から右です。左の枠だけを人が判定する場所の色で塗り、中央の自動指標と区別しています。図の添え書きの「34本の論文、284の相関」は、本文の第3節で引いた2018年の体系的な検討の規模です。「4,380システム、230万件の人手評価」は、第4節で引いた2021年の検証の規模です。

### 本章の要点と解釈

本節は、著者による解釈です。前節までの事実記述とは区別して読んでください。

要点は3つです。第一に、BLEUとROUGEは、人の判定が高価で遅いという問題への答えとして、人の判定の「代役」と自ら名乗って生まれました。第二に、代役の正しさは人の評価との相関で示されましたが、2006年以降、相関が崩れる反例と用途の限定が積み重なりました。第三に、2021年の大規模な検証は、代役だけに頼った判断が、製品を出すかどうかの判断を誤らせたことを示しました。

著者は、この時代の教訓を「代理の指標は、作られた用途の外で使うと目的から離れる」とまとめます。Reiterの検討が示したように、BLEUは機械翻訳システムの診断には支持され、それ以外の用途には支持されませんでした。生成AIを業務に使う組織が、要約や回答の品質を語の一致率だけで測るなら、同じ誤りを繰り返すおそれがあると著者は考えます。指標を採用するときは、その指標がどの用途で人の評価と照らして検証されたかを確かめることが、経営層と実務家の双方にとっての最小限の確認だと著者は考えます。
