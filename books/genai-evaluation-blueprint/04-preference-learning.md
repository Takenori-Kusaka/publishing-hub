### 序論：本章が扱う範囲

本章は、人がどちらの出力を好むかという「選好」で期待への近さを定義し、その選好を学習した評価器でモデルを訓練する流れを扱います。中心は2022年で、源流の2017年と、その後の2025年までの展開も記します。

[参照との一致の章](02-reference-metrics)と[意味の一致の章](03-learned-metrics)の指標は、できあがった出力を採点する道具でした。本章の時代には、評価器が訓練の報酬になります。評価が測る道具であると同時に、モデルの振る舞いを形づくる道具になったことが、本章の主題です。

本章は、源流、InstructGPTとChatGPT、評価器を最適化することの限界、人の選好そのものの限界、検証可能な報酬への動きの順に記します。人の代わりに言語モデルが採点する審判モデルは、[審判としてのLLMの章](05-llm-as-judge)で扱います。

### 1. 源流：選好で目標を定義する

2017年6月、Paul Christianoらは、報酬関数を書かずに強化学習を行う方法を示しました。目標を、行動の断片の2つの組に対する人の選好で定義します。選好を示す人は専門家でなくてもよいとしています [ [ 61 ] ](https://arxiv.org/abs/1706.03741) 。人の比較から報酬を学習するこの方法が、人のフィードバックによる強化学習(RLHF)の報酬モデルの原型です。

2020年9月、OpenAIのNisan Stiennonらは、この方法を要約に適用しました。論文は、要約モデルが人の参照要約を予測するように訓練され、ROUGEで評価されていると指摘します。そのうえで、どちらも本当に気にしている要約の品質の粗い代理にすぎないと述べました [ [ 62 ] ](https://arxiv.org/abs/2009.01325) 。人の比較のデータで報酬モデルを学習し、それを最適化した要約は、人の評価によればROUGEを最適化した要約より良いと報告しています [ [ 62 ] ](https://arxiv.org/abs/2009.01325) 。

ここで、期待への近さの定義が変わりました。参照の文との一致ではなく、人が2つの出力のどちらを好むかです。そして、その選好を学習した報酬モデルが、評価器と訓練の目標を兼ねるようになりました。

### 2. InstructGPT と ChatGPT：評価が訓練になる

2022年3月、OpenAIのLong Ouyangらは、InstructGPTの論文を公開しました。ラベラーがモデルの出力を順位づけたデータを集め、そこから学習した報酬で、教師ありの微調整を済ませたモデルをさらに強化学習で微調整しています [ [ 63 ] ](https://arxiv.org/abs/2203.02155) 。結果として、パラメータ13億のInstructGPTの出力が、1,750億のGPT-3の出力より人に好まれました [ [ 63 ] ](https://arxiv.org/abs/2203.02155) 。

2022年4月、Anthropicは有用で無害なアシスタントをRLHFで訓練する論文を公開しました。新しい人のフィードバックのデータで、選好モデルと強化学習の方策を週ごとに更新する「反復オンライン訓練」を記述しています [ [ 64 ] ](https://arxiv.org/abs/2204.05862) 。

2022年11月30日、OpenAIはChatGPTを研究プレビューとして公開しました。公開の記事によれば、ChatGPTはInstructGPTと同じRLHFの方法で、データ収集の設定を少し変えて訓練されています [ [ 1001 ] ](https://openai.com/index/chatgpt/) 。報酬モデルを作るため、AIトレーナーが2つ以上のモデルの応答を品質で順位づけた比較データを集めました。その報酬モデルで方策を微調整する工程を、数回繰り返しています [ [ 1001 ] ](https://openai.com/index/chatgpt/) 。

同じ記事は、評価器としての人の選好の限界も明記しています。

- **真実の源が無い**: もっともらしいが誤った回答を直すのは難しく、その理由の1つは、強化学習の訓練中に真実の源が無いことだとしています [ [ 1001 ] ](https://openai.com/index/chatgpt/) 。
- **長さへの偏り**: モデルはしばしば過度に冗長です。その原因として、訓練者が包括的に見える長い回答を好むという訓練データの偏りと、よく知られた過最適化の問題を挙げています [ [ 1001 ] ](https://openai.com/index/chatgpt/) 。

### 3. 評価器を最適化することの限界

評価器が訓練の目標になると、評価器の不完全さがそのまま問題になります。

2018年3月、ManheimとGarrabrantは、指標に基づいてシステムを過度に最適化したときの失敗の様式には、いくつかの異なる種類があると整理しました。指標が目標の代理であるときに起きる、Goodhartの法則の変種の分類です [ [ 629 ] ](https://arxiv.org/abs/1803.04585) 。

2022年10月、OpenAIのLeo Gaoらは、報酬モデルの過最適化を測定しました。報酬モデルは不完全な代理であるため、その値を最適化しすぎると真の性能を損ないます。これはGoodhartの法則に沿う現象です [ [ 65 ] ](https://arxiv.org/abs/2210.10760) 。論文は合成の設定でこの関係を測り、係数が報酬モデルの規模に応じて滑らかに変わることを示しました [ [ 65 ] ](https://arxiv.org/abs/2210.10760) 。

人の選好を集める費用を減らす方法も、同じ時期に出ています。

- **AIのフィードバック(2022年12月)**: AnthropicのConstitutional AIは、有害性の人手ラベルを使わず、原則のリストに基づくAIの自己批評とAIの選好で選好モデルを訓練しました。これを「AIのフィードバックによる強化学習(RLAIF)」と呼んでいます [ [ 66 ] ](https://arxiv.org/abs/2212.08073) 。
- **報酬モデルを省く(2023年5月)**: DPOは、報酬モデルを明示的に学習せず、単純な分類の損失で方策を直接最適化できることを示しました [ [ 69 ] ](https://arxiv.org/abs/2305.18290) 。
- **RLHFとの比較(2023年9月)**: Googleの研究は、要約、有用な対話、無害な対話の課題で、RLAIFがRLHFと同等の性能を達成したと報告しています [ [ 71 ] ](https://arxiv.org/abs/2309.00267) 。

### 4. 人の選好そのものの限界

2023年以降、選好を評価の基準にすること自体の限界が、次々に報告されました。

- **事実性の過小評価(2023年9月)**: 選好のスコアは多くの観点を含むが、事実性のような重要な観点を十分に反映しないと示されました。出力の断定的な調子が、事実の誤りの知覚を歪めることも報告されています [ [ 72 ] ](https://arxiv.org/abs/2309.16349) 。
- **迎合の選好(2023年10月)**: Anthropicの研究者らは、人と選好モデルの双方が、説得力のある迎合的な応答を正しい応答より好む場合が無視できない割合であると示しました [ [ 73 ] ](https://arxiv.org/abs/2310.13548) 。
- **未解決の問題の体系化(2023年7月)**: RLHFの未解決の問題と根本的な限界を整理し、社会による監視のための監査と開示の基準を提案したサーベイが出ました [ [ 70 ] ](https://arxiv.org/abs/2307.15217) 。
- **報酬モデルの評価の不足(2024年3月)**: RewardBenchは、報酬モデルそのものの評価はほとんど研究されてこなかったとして、報酬モデルを検査するベンチマークを公開しました [ [ 77 ] ](https://arxiv.org/abs/2403.13787) 。
- **表層の特徴への偏り(2025年6月)**: 長さ、構造、専門用語、迎合、曖昧さという5つの表層の特徴を調べた研究があります。これらの特徴と人の選好ラベルとの相関は平均-0.12でした。強い報酬モデルのラベルとの相関は平均+0.36でした [ [ 84 ] ](https://arxiv.org/abs/2506.05339) 。

研究者の発言にも、同じ懸念が現れています。OpenAIとTeslaに在籍した研究者で、現在は独立のAndrej Karpathyは、2024年8月の投稿でRLHFの報酬モデルを「雰囲気の確認(vibe check)」にたとえました。雰囲気は誤解を招きうるもので、実際の報酬ではなく「粗末な代理の目標」だと述べています [ [ 645 ] ](https://x.com/karpathy/status/1821277264996352246) 。

### 5. 検証可能な報酬への動き

2024年末から、人の選好に代えて、正誤を機械で判定できる基準を報酬にする動きが出ました。

2024年11月、AI2のTülu 3は「検証可能な報酬による強化学習(RLVR)」と名づけた方法を示しました。2025年1月のDeepSeek-R1は、数学、競技プログラミング、STEMのような検証可能な課題で、人の推論の手本なしに純粋な強化学習で推論能力を引き出したと報告しています [ [ 106 ] ](https://arxiv.org/abs/2411.15124) 。

ただし、検証可能な報酬も無条件に正しいわけではありません。2025年6月の研究では、Qwen2.5-Math-7Bに対し、ランダムに割り当てた報酬で訓練してもMATH-500の成績が21.4ポイント上がりました。正解の報酬での上昇は29.1ポイントでした [ [ 108 ] ](https://arxiv.org/abs/2506.10947) 。

2025年7月には、正誤を機械で判定しにくい領域への拡張も報告されました。Scale AIのRubrics as Rewardsは、事例ごとのルーブリックを報酬にし、Likert尺度で直接採点する審判モデルに比べ、医療の評価集HealthBenchで最大31%の相対的な改善を示しました。翌日に公開された別の研究は、指示から抽出したチェックリストを報酬に使っています [ [ 109 ] ](https://arxiv.org/abs/2507.17746) 。

2025年9月、OpenAIのAdam Kalaiらは、言語モデルが幻覚(ハルシネーション)を起こす理由の1つとして、評価の手続きを挙げました。訓練と評価の手続きが、不確かさを認めるより推測することに報酬を与えているという主張です。対策として、新しい評価を足すより、順位表を支配する既存のベンチマークの採点法を改めることを求めています [ [ 110 ] ](https://arxiv.org/abs/2509.04664) 。

### 🗺️ 図：評価器が報酬になり、評価が訓練を動かした

![人の比較から報酬モデルを作り、方策を最適化し、出力を再び人が比べる循環と、その外側に置いた過最適化の注記](/images/genai-evaluation-blueprint/04-preference-learning.png)

#### 図の読み方

この図は、4つの箱を時計回りにつないだ循環で構成されています。左上の「人の比較」から始まり、「報酬モデル」「方策の最適化」「新しい出力」と進み、出力は再び人の比較に回ります。第2節で引いたChatGPTの記事が述べる、比較データの収集と微調整の反復を図にしたものです。

読み順は、左上から時計回りです。「人の比較」の箱だけを人が判定する場所の色で塗っています。循環の右側に置いた枠は、第3節の過最適化の注記です。報酬モデルは不完全な代理であり、最適化しすぎると真の性能を損ないます。図の下の添え書きは、第2節で引いたChatGPTの記事が挙げた2つの限界です。長い回答への偏りと、強化学習の訓練中に真実の源が無いことです。

### 本章の要点と解釈

本節は、著者による解釈です。前節までの事実記述とは区別して読んでください。

要点は3つです。第一に、2022年に、期待への近さの定義は「人がどちらを好むか」になり、その選好を学習した報酬モデルが訓練の目標になりました。ChatGPTはこの方法で訓練されています。第二に、評価器が最適化の対象になると、評価器の不完全さが真の性能を損なうことが測定されました。第三に、人の選好そのものも、長さ、断定的な調子、迎合に引きずられることが示され、2024年末からは機械で判定できる報酬への動きが出ました。

著者は、この時代の最も重要な変化を「評価が、出力を測る道具から、出力を作る道具になった」ことだと考えます。評価の基準を決めることは、モデルに何を学ばせるかを決めることと同じになりました。この関係は、組織が生成AIを使う場面にも及ぶと著者は考えます。利用者の高評価の割合だけを改善の指標にすると、長く断定的な回答が増え、事実の誤りを見つけにくくなるおそれがあります。経営層と実務家は、満足の指標と並べて、正誤を確かめる指標を別に持つ必要があると著者は考えます。
