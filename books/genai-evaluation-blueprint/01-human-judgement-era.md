### 序論：本章が扱う範囲

本章は、機械の出力が「期待にどこまで近いか」を、人の判定で測っていた時代を扱います。期間はおおむね1950年から2001年です。自動の指標が広まる前の時代であり、期待への近さの定義は、人が下す判定そのものでした。

本章は4つの源流を順に記します。第一に、判定者が機械と人を区別できるかを問う模倣ゲームです。第二に、情報検索のテストコレクションと、適合性を人が判定する評価キャンペーンです。第三に、人の判定の信頼性を数値にする一致度の係数と、ペア比較の統計モデルです。第四に、対話システムを課題の達成とユーザーの満足で測る枠組みです。最後に、人の判定そのものの限界を、後年の検証から記します。

各節は「期待への近さをどう定義したか」「どう測ったか」「何が限界だったか」の3点で書きます。人の判定が高価で遅いという限界が、次の[参照との一致の章](02-reference-metrics)で扱う自動指標の動機になりました。人の判定の不安定さは、[審判としてのLLMの章](05-llm-as-judge)で再び問題になります。

モデルの問題解決能力を測るベンチマークは本章では扱いません。その位置づけは[能力ベンチマークとの距離の章](10-capability-benchmarks-distance)で述べます。

### 1. 模倣ゲーム：判定者が区別できるか

1950年10月、Alan Turingは学術誌Mindの論文で「機械は考えられるか」という問いを取り上げました。Turingはこの問いを、曖昧さの少ない「模倣ゲーム」に置き換えることを提案しています [ [ 1 ] ](https://academic.oup.com/mind/article/LIX/236/433/986238) 。

模倣ゲームでは、人間の判定者が、文字のやりとりだけを手がかりに相手が機械か人かを判断します。ここでの「期待への近さ」は、出力が人の出力と区別できない度合いです。測る道具は判定者の判断だけで、正解の文や採点の基準はありません。

この発想は、後の評価にも残りました。2021年の研究は、訓練を受けていない評価者がGPT-3の生成文と人の文を偶然の水準でしか区別できなかったと報告しています [ [ 13 ] ](https://arxiv.org/abs/2107.00061) 。区別できないことは、出力が期待に近いことと同じではありません。この点は本章の第5節で扱います。

### 2. テストコレクション：Cranfield から TREC へ

情報検索の実験的な評価は、Cyril Cleverdonらが英国のCranfieldで1960年代に行った索引システムの比較実験に始まります。1966年の報告書の付録は、1,400の文書と279の質問の一覧を収めています [ [ 143 ] ](https://ntrl.ntis.gov/NTRL/dashboard/searchResults/titleDetail/PB169574.xhtml) 。文書の集合と質問と、どの文書が質問に適合するかの判定をひとまとめにしたものを、テストコレクションと呼びます。

テストコレクションでの「期待への近さ」は、人が「適合する」と判定した文書を、システムがどれだけ返したかです。期待の中身は人の判定に置かれ、システムの比較は同じ判定の上で行われます。

1992年、この方式は大規模な評価キャンペーンになりました。TREC(Text REtrieval Conference)は、アメリカのTIPSTER計画の一部として始まり、NISTと国防総省が共催しています [ [ 3 ] ](https://trec.nist.gov/overview.html) 。参加者は共通の大規模なテストコレクションで各自のシステムを走らせます。NISTは各参加者の結果をまとめて(プーリング)、返された文書の正しさを判定し、結果を評価します [ [ 3 ] ](https://trec.nist.gov/overview.html) 。NISTは、最初の6年間で検索システムの有効性がおよそ2倍になったと述べています [ [ 3 ] ](https://trec.nist.gov/overview.html) 。

共通のデータ、共通の評価、結果の比較という型は、のちの多くのベンチマークに引き継がれました。1999年のTREC-8の質問応答トラックでは、最初の正答の順位の逆数を質問ごとに取り、その平均を走行のスコアとする方式(MRR)が使われています [ [ 146 ] ](https://aclanthology.org/L00-1018) 。

この方式にも限界が検証されました。1998年、Justin ZobelはTRECのデータで、プーリングによる判定が不完全であることを示しました。システム間の相対的な順位は信頼できる一方、見つかっていない適合文書が多いため、再現率は過大に見積もられると結論しています [ [ 144 ] ](https://findanexpert.unimelb.edu.au/scholarlywork/1056492-how-reliable-are-the-results-of-large-scale-information-retrieval-experiments%3F) 。2000年、NISTのEllen Voorheesは判定者ごとの適合性の判断の揺れを検討し、判定が変わってもシステムの相対的な順位は安定すると報告しました [ [ 145 ] ](https://eric.ed.gov/?id=EJ606816) 。

### 3. 人の判定を数値にする道具：一致度とペア比較

人の判定で測る以上、判定そのものがどれだけ信頼できるかを測る道具が要ります。人の評価の信頼性を数値にする代表的な係数は、1960年に発表されています。2人の評価者が名義尺度で付けた判定の一致を測るCohenのκです。1970年にはKrippendorffのα、1971年には多数の評価者に使えるFleissのκが続きました。これらは今日の言語生成の評価でも使われています [ [ 4 ] ](https://doi.org/10.1177/001316446002000104) 。

もう1つの道具は、ペア比較です。1952年12月、BradleyとTerryは、2つずつ比べた結果から、それぞれの潜在的な「強さ」を推定するモデルを学術誌Biometrikaで発表しました [ [ 5 ] ](https://academic.oup.com/biomet/article-abstract/39/3-4/324/320283) 。このモデルは70年後、利用者の投票で言語モデルを順位づけるChatbot Arenaの集計に使われます [ [ 75 ] ](https://lmsys.org/blog/2023-12-07-leaderboard/) 。

一致度の係数とペア比較は、期待への近さを直接は測りません。前者は人の判定がどれだけそろうかを、後者は2つの出力のどちらが好まれるかを測ります。期待の中身を決めるのは、どちらの場合も人です。

### 4. 対話システムの評価：課題の達成とユーザーの満足

1990年代には、自然言語処理のシステム評価そのものが研究の対象になりました。1996年、Karen Sparck JonesとJulia Galliersは、自然言語処理システムの評価を分析し整理した単行本を出版しています [ [ 6 ] ](https://doi.org/10.1007/BFb0027470) 。

1997年、Marilyn Walkerらは音声対話システムの評価枠組みPARADISEを発表しました。PARADISEは、性能を「課題の達成」と「対話のコスト」に分け、ユーザーの満足を目的として両者を回帰で結びつけます。課題の複雑さで正規化すれば、異なる課題を行うシステムどうしも比べられるとしています [ [ 7 ] ](https://aclanthology.org/P97-1035/) 。

PARADISEは、それまで広く使われていた方法の限界を明示しています。参照解答との一致で測る方法には「広く認められた多くの限界がある」という指摘です [ [ 7 ] ](https://aclanthology.org/P97-1035/) 。ここでの「期待への近さ」は、正解の文との一致ではなく、ユーザーが課題を達成し満足したかどうかです。

対話の評価は、その後も共有データの整備と実利用者の評価へ進みました。2013年のDialog State Tracking Challengeは、共通の評価基盤が無いという問題に対し、15,000件の人と機械の対話と11種の評価指標を提供し、9つの研究グループから27の応募を集めました [ [ 9 ] ](https://aclanthology.org/W13-4065/) 。2018年1月に報告されたAmazonのAlexa Prizeは、賞金総額250万ドルの大学対抗戦です。選ばれた16チームの対話システムを、実際の利用者が付けた評点とフィードバックで評価しました [ [ 10 ] ](https://arxiv.org/abs/1801.03604) 。

### 5. 人の判定の限界：後年の検証

人の判定は長く評価の基準とされてきました。しかし2020年以降の検証は、その基準自体が不安定であることを示しています。

- **用語と手順の不統一**: 2020年12月の研究は、言語生成の人手評価を報告した論文165本を分析しました。評価の観点を表す用語は200を超え、報告の不備と手法の多様さから、人手評価は「極度に混乱している」と結論しています [ [ 11 ] ](https://aclanthology.org/2020.inlg-1.23/) 。
- **区別する力の不足**: 2021年6月の研究では、訓練を受けていない評価者は、GPT-3の生成文と人の文を偶然の水準でしか区別できませんでした [ [ 13 ] ](https://arxiv.org/abs/2107.00061) 。
- **クラウドの評価者の限界**: 2021年9月の研究は、資格による選別を掛けても、Mechanical Turkの作業者は生成文と人の参照文を区別できなかったと報告しています。英語の教師は区別できました [ [ 14 ] ](https://arxiv.org/abs/2109.06835) 。
- **再現の困難**: 2023年5月の研究は、過去の人手評価の再現を試みました。再現の条件を満たした論文は13%にとどまり、選んだ実験のうち1件を除くすべてに欠陥が見つかりました [ [ 15 ] ](https://arxiv.org/abs/2305.01633) 。

これに対し、人手評価の記録を標準化する提案も出ています。2021年3月、ShimorinaとBelzは、人手評価の実験の性質を十分に詳しく記録する「Human Evaluation Datasheet 1.0」を提案しました。目的は比較可能性、メタ評価、再現性の検証です [ [ 12 ] ](https://arxiv.org/abs/2103.09710) 。

### 6. この時代の整理

| 方式 | 年 | 期待への近さの定義 | 測り方 | 限界 |
| --- | --- | --- | --- | --- |
| 模倣ゲーム | 1950 | 人の出力と区別できない | 判定者の判断 | 区別できないことは期待に合うことと別 |
| テストコレクション | 1960年代 | 人が適合と判定した文書を返す | 人の適合性判定 | 期待の中身を判定者に依存する |
| TREC | 1992〜 | 同上を大規模に共通化 | プーリングと判定 | 再現率の過大評価 |
| 一致度・ペア比較 | 1952〜1971 | 判定がそろう、どちらが好まれる | 係数と統計モデル | 期待の中身は人が決める |
| PARADISE | 1997 | 課題の達成とユーザーの満足 | 回帰で結合 | 満足の測定に人が要る |

### 🗺️ 図：期待への近さは、人の判定で定義されていた

![1950年から1997年までの4つの源流。どの方式も最後に判定したのは人だった](/images/genai-evaluation-blueprint/01-human-judgement-era.png)

#### 図の読み方

この図は、左から右へ年代順に並べた4つの枠で構成されています。左から、1950年の模倣ゲーム、1960年代のCranfieldのテストコレクション、1992年のTREC、1997年のPARADISEです。各枠の下段には、その方式で「誰が何を判定したか」を書いています。判定者が区別できるか、人が適合性を判定するか、NISTがまとめて判定するか、ユーザーが満足したかです。

読み順は左から右です。4つの枠の下には、人が判定する場所を示す帯を1本通しています。どの方式でも、期待の中身を決めて最後に判定したのは人だったことを示します。帯の下の添え書きは、第5節で扱った後年の検証です。人の判定そのものが、用語の不統一と再現の困難を抱えていました。

### 本章の要点と解釈

本節は、著者による解釈です。前節までの事実記述とは区別して読んでください。

要点は3つです。第一に、自動の指標が広まる前、期待への近さは人の判定そのものとして定義されていました。模倣ゲーム、テストコレクション、PARADISEは、判定する対象こそ違いますが、期待の中身を人に置く点で共通しています。第二に、TRECは「共通のデータで、共通の判定により、結果を比べる」という評価キャンペーンの型を作りました。この型は、のちのベンチマークと順位表に引き継がれています。第三に、人の判定は基準として扱われてきましたが、2020年以降の検証は、その基準自体が不統一で再現しにくいことを示しました。

著者は、この時代から実務家が受け取るべき教訓を2つと考えます。1つは、PARADISEが示したように、期待への近さは「正解の文との一致」ではなく「利用者の課題が達成されたか」で定義できるということです。もう1つは、人の判定を基準にするなら、判定の手順と観点を記録し、判定者間の一致度を測る必要があるということです。生成AIを業務に組み込む組織が最初に作る評価用の問題集は、Cranfieldのテストコレクションと同じ構造を持ちます。その品質は、適合性を判定する人の質と、判定の記録の丁寧さで決まると著者は考えます。
