### 序論：本章が扱う範囲

本章は、企業が自社の現在地を測るための物差しを3本に分けて示します。事業フェーズ、導入フェーズ、文化フェーズです。[生成AIの導入段階の章](30-genai-adoption-stages)で示した導入の深さS1からS6は、このうち2本目に当たります。

物差しを3本に分ける理由は単純です。同じ導入段階にいても、新規事業を探索している企業と成熟事業を効率化している企業では、次に打つ手が違います。また、同じ段階にいても、従業員が自発的に使う文化のある企業と禁止と黙認の間で止まっている企業では同じ手が同じ効果を生みません。1本の物差しでは、この差を見落とします。

本章は、[現在地を測る道具の章](23-maturity-models)で整理した成熟度モデルの系譜の上に立ちます。本章の3本の物差しと、各軸の段階の定義は、著者による整理です。自己診断の質問は、本書と同じ枠組みで動くWebアプリ「AXコンパス」と共通です。アプリは本書と同時に公開しています([https://takenori-kusaka.github.io/ax-compass/](https://takenori-kusaka.github.io/ax-compass/))。アプリを使わなくても、本章の表だけで診断できます。

### 1. なぜ1本の物差しでは足りないか

成熟度を1本の尺度で測る調査がある一方で、2本以上の軸を交差させる調査も増えています。Accentureは基盤の能力と差別化の能力、Microsoftは個人のAI能力と組織の準備度、Jöhnkらは技術の導入度とは別の準備度の範疇で企業を測りました [ [ 195 ] ](https://newsroom.accenture.com/news/2022/more-than-60-percent-of-companies-are-only-experimenting-with-ai-creating-significant-opportunities-for-value-on-their-journey-to-ai-maturity-accenture-research-finds) [ [ 205 ] ](https://assets-c4akfrf5b4d3f4b7.z01.azurefd.net/assets/2026/05/2026_Work_Trend_Index_Annual_Report_050526-7_69fc5b1c4e265.pdf) [ [ 215 ] ](https://aisel.aisnet.org/bise/vol63/iss1/2) 。これらに共通するのは、技術の導入の深さだけでは企業の状態を説明できない、という知見です。本書は、導入の深さに加えて、事業の局面と組織の文化を別の軸として立てます。各調査の数値は第7節にまとめます。

### 2. 事業フェーズ：探索、成長、成熟、再生

1本目の物差しは、AIを導入しようとする事業がどの局面にあるかです。本書は4つに分けます。

| 事業フェーズ | 定義 | AIに期待する役割 |
| --- | --- | --- |
| 探索 | 新しい事業や製品を試している。顧客も収益モデルも固まっていない | 新しい提供価値を作る、試作を速くする |
| 成長 | 事業が伸びている。需要に供給が追いつかない | 供給能力を増やす、品質を保ったまま量を出す |
| 成熟 | 事業が安定している。利益率と効率が主題 | 費用を下げる、既存の業務を速くする |
| 再生 | 事業が縮小している。構造の転換が必要 | 事業モデルを組み替える、撤退と転換を支える |

この区分は、McKinseyのコンサルタントが1999年に示した「3つの地平」の考え方を参照しています。現在の中核事業の防衛、立ち上がりつつある新事業の育成、将来の選択肢の種まきの3つは、成果指標と人材と管理の方法が異なります [ [ 278 ] ](https://openlibrary.org/works/OL512178W) 。O'ReillyとTushmanは2004年に、既存事業の深化と新規事業の探索を同時に行う組織を「両利き」と呼び、探索部門を構造的に分けつつ上級経営陣で統合する型が、他の型より成功率が高いと報告しました [ [ 275 ] ](https://hbr.org/2004/04/the-ambidextrous-organization) 。Christensenは1997年に、優良企業が新技術で失敗するのは主要顧客の声を聞くという優良な経営の帰結であり、対処は新技術を評価する小さな市場に合わせた独立組織を作ることだと論じました [ [ 276 ] ](https://openlibrary.org/works/OL1999873W) 。

事業フェーズを先に確かめる理由は、AIの用途がフェーズで決まるからです。成熟事業で「新しい提供価値を作る」用途にAIを当てても、成熟事業の指標はそれを評価しません。探索事業で「費用を下げる」用途にAIを当てても、探索事業にはまだ下げるべき費用がありません。多くの企業は複数の事業を持つため、この物差しは事業ごとに当てます。

### 3. 導入フェーズ：S1からS6

2本目の物差しは、[生成AIの導入段階の章](30-genai-adoption-stages)で定義した6段階です。本章では、各段階を外から観察できる事実で判定するための目安を加えます。

| 段階 | 観察できる事実 |
| --- | --- |
| S1 触れる | 会社として契約したサービスがない。個人が無料のサービスを使っている |
| S2 仕事に適用する | 会社がチャット型のサービスを契約し、従業員に配っている。利用規程がある |
| S3 仕事に組み込む | 業務手順書にAIの利用が書かれている。社内文書を参照する検索がある。推進の担当者がいる |
| S4 システムに組み込む | 自社のシステムから基盤モデルのAPIを呼んでいる。出力を評価する仕組みと費用の管理がある |
| S5 商品に組み込む | 顧客が使う製品やサービスにAIの機能がある。価格や契約に反映されている |
| S6 顧客へ届ける | AIが顧客との取引や対応を完結する場面がある。事業の指標がそれを含む |

判定は業務ごとに行います。会社全体で1つの段階を答えようとすると、最も進んだ業務の段階を答えがちです。IDCは2026年に20市場1,900組織を採点し、自らを上位層だと答えた組織の84.9%が実際にはRepeatable以下だったと報告しました [ [ 199 ] ](https://www.idc.com/resource-center/blog/ai-strategy-is-easier-to-define-than-to-deliver-idcs-benchmark-shows-the-gap) 。自己申告は高く出ます。観察できる事実で判定する理由はここにあります。

### 4. 文化フェーズ：C1からC5

3本目の物差しは、組織の文化です。本書は5段階に分けます。定義の根拠と、段階を上げる施策は[文化の形成の章](36-culture-formation)で詳しく扱います。

| 段階 | 名前 | 定義 |
| --- | --- | --- |
| C1 | 禁止・無関心 | 組織として生成AIを禁じているか、方針がない |
| C2 | 個人の試行 | 従業員が個人の判断で使っている。組織は黙認している |
| C3 | 公認の試行 | 利用規程と学習の場がある。使うことが認められ、推奨されている |
| C4 | 測って運用 | 効果と費用と誤りを数値で追い、業務ごとに改善している |
| C5 | AI・データネイティブ | 全員が作り手で、学習と改善が制度として続いている |

文化フェーズを導入フェーズと分ける根拠は、2つの統計にあります。

第一に、文化は導入より先に動きます。Microsoftの2024年の調査では、職場でAIを使う人の78%が自前のツールを持ち込んでおり、52%は重要な業務でのAI利用を開示するのをためらっていました [ [ 296 ] ](https://www.microsoft.com/en-us/worklab/work-trend-index/ai-at-work-is-here-now-comes-the-hard-part) 。C2の状態は、組織がS2を決める前に成立しています。

第二に、文化は導入より後まで残ります。総務省の2025年度の調査では、生成AIによる業務変革について「組織的な取組はない」と答えた日本企業が約3割弱でした [ [ 107 ] ](https://www.soumu.go.jp/main_content/001082851.pdf) 。サービスを配ったあとも、組織として取り組む段階に進まない企業が一定数あります。配ること(S2)と取り組むこと(C3以上)は、別の判断です。

なお「AI-native」という語は、業界で広く使われていますが、学術的な定義の一次資料は確認できていません。本書はこの語を、AIを後付けではなく設計の前提に置く組織を指す業界用語として使い、C5の名前に添えています。

### 5. 自己診断の質問

次の表は、3本の物差しの現在地を自己診断するための質問です。事業フェーズは5問、導入フェーズと文化フェーズは6問ずつで、各選択肢が1つの区分か段階にだけ対応します。問いと選択肢は、Webアプリ「AXコンパス」と同じ文言です。複数の業務や事業を持つ企業は、代表的な業務を1つ選んで答えます。「誰に聞くか」の列は、取締役が自分では答えにくい問いを、社内の誰に確かめればよいかの目安です。

**事業フェーズ**(全5問)

| 問い | 選択肢 | 誰に聞くか |
| --- | --- | --- |
| 主な事業の売上は、ここ3年でどう動いていますか | 探索：まだ売上の型が定まっていない<br>成長：年率10%以上で伸びている<br>成熟：横ばいか、緩やかに増減している<br>再生：減少が続き、構造的な原因がある | 経理、経営企画 |
| 経営会議でもっとも時間を使っている議題はどれですか | 探索：顧客と提供価値の見極め<br>成長：採用と組織の拡大、供給の確保<br>成熟：利益率と費用の改善<br>再生：事業の選択と集中、撤退と転換 | 取締役自身、経営企画 |
| 新しい取り組みへの予算は、どう決まりますか | 探索：ほぼ全てが新しい取り組みに向いている<br>成長：成長に直結する投資は通りやすい<br>成熟：既存事業の改善に比べ、新規は厳しく見られる<br>再生：既存事業の費用を削って、転換のための投資に回している | 経営企画、経理 |
| 主な競合との関係はどれに近いですか | 探索：競合がまだ定まらない、あるいは市場が形成途上<br>成長：競合と市場の取り合いをしている<br>成熟：顔ぶれが固定し、シェアは安定している<br>再生：異業種や新技術の参入で競争の前提が変わった | 営業部門、事業部長 |
| 業務の手順書や標準は、どの程度整っていますか | 探索：ほとんどない。やり方を日々変えている<br>成長：整備が人員の増加に追いついていない<br>成熟：整っている。改訂は年に数回<br>再生：整っているが、現在の事業に合わなくなっている | 各部門の課長、品質保証部門 |

**導入フェーズ**(全6問)

4問目のAPIは、人が画面で使うのではなく、自社のシステムがAIを直接呼び出す接続口です。分からなければ、情報システム部門に「自社のシステムから生成AIを呼び出している仕組みはあるか」と聞きます。

| 問い | 選択肢 | 誰に聞くか |
| --- | --- | --- |
| 生成AIの利用契約は誰が結んでいますか | S1：個人が無料版や個人契約で使っている(会社の契約はない)<br>S2：会社がSaaSを契約し、希望者か一部の部門に配っている<br>S3：会社契約のSaaSに加え、社内向けのチャット基盤がある<br>S4：基盤モデルのAPIを会社として契約し、システムから使っている<br>S5：API契約に加え、顧客向け製品で使うための契約がある<br>S6：計算資源(GPUやモデルの専有)を事業の原価として調達している | 情報システム部門、購買部門 |
| 業務手順書に生成AIの使い方が書かれていますか | S1：書かれていない。使うかどうかは個人次第<br>S2：利用指針(入力してよい情報の範囲など)だけがある<br>S3：一部の部門の手順書に、使う場面とプロンプトが書かれている<br>S4：手順書に加え、システムが自動でAIを呼ぶ業務フローがある<br>S5：顧客向けの提供手順(AI機能の品質基準、問い合わせ対応)まで書かれている<br>S6：AIが完結する業務と、人が引き取る例外の手順が分けて書かれている | 各部門の課長 |
| 社内文書を生成AIに検索させて答えを得る仕組み(RAG)はありますか | S1：ない。個人が文書を貼り付けて使う程度<br>S2：SaaSに文書をアップロードして個人が使っている<br>S3：部門か全社で共有する検索の仕組みがある<br>S4：業務システムと接続し、権限に応じて検索できる<br>S5：顧客向けの製品にも同じ仕組みを提供している<br>S6：顧客との取引データをリアルタイムでAIが参照・更新している | 情報システム部門 |
| 自社システムから基盤モデルのAPIを呼んでいますか | S1：呼んでいない。技術的な検討もしていない<br>S2：検討はしているが、実装はない<br>S3：試作(PoC)で呼んだことがある<br>S4：本番の業務システムで呼んでいる。評価と費用を監視している<br>S5：顧客向け製品の本番で呼んでいる<br>S6：複数のモデルを切り替えられる基盤を自社で運用している | 情報システム部門 |
| 顧客が使う製品・サービスにAI機能がありますか | S1：ない。予定もない<br>S2：ない。社内の効率化が先と考えている<br>S3：検討中。顧客の要望を調べている段階<br>S4：一部の顧客に試験提供している<br>S5：正式な機能として提供し、価格にも反映している<br>S6：AI機能が製品の中核で、それ抜きでは事業が成り立たない | 事業部長、製品企画 |
| AIが顧客との取引を完結する場面がありますか | S1：ない。顧客対応は全て人が行う<br>S2：AIが下書きを作り、人が確認して送っている<br>S3：よくある質問への一次回答をAIが行い、人が引き継ぐ<br>S4：AIが提案し、人の承認を得て取引を進める場面がある(A2)<br>S5：定めた範囲でAIが取引を完結し、人が事後に確認している(A3)<br>S6：顧客接点の大半をAIが担い、人は例外と設計を担当している | 営業部門、顧客対応部門の課長 |

**文化フェーズ**(全6問)

| 問い | 選択肢 | 誰に聞くか |
| --- | --- | --- |
| 社内での生成AI利用は、どの扱いですか | C1：禁止している、または話題にならない<br>C2：黙認している(個人が勝手に使っている)<br>C3：公認している(指針があり、使ってよいと周知している)<br>C4：推奨している(使うことが評価や目標に入っている)<br>C5：制度化している(全員が使い、改善する仕組みが回っている) | 総務・人事(利用規程の担当) |
| AIの効果を数値で測っていますか | C1：測っていない。測る対象もない<br>C2：個人の感想や逸話で語られている<br>C3：利用率や満足度の調査をしている<br>C4：業務ごとに時間・件数・誤りの率を測り、費用と比べている<br>C5：測った結果を予算と組織の判断に毎期使っている | 推進の担当者、経営企画 |
| 失敗やうまくいかなかった使い方を共有する場はありますか | C1：ない。失敗は個人の責任とされがち<br>C2：親しい同士で話す程度<br>C3：勉強会や共有の場が不定期にある<br>C4：定期的な場があり、失敗が手順や指針の改訂につながっている<br>C5：失敗の共有が制度に組み込まれ、評価で不利にならない | 各部門の課長 |
| 経営層は生成AIをどう扱っていますか | C1：使っていない。関心も薄い<br>C2：関心はあるが、自分では使っていない<br>C3：自分で使い、推進の方針を社内に示している<br>C4：効果と費用の報告を定期的に受け、判断している<br>C5：事業計画と人員計画をAI前提で組んでいる | 取締役自身 |
| AIの推進を担う人や組織はどうなっていますか | C1：いない<br>C2：有志が個人的に進めている<br>C3：推進役か専門チーム(CoE)が任命されている<br>C4：専門チームが基盤と統治を持ち、事業部が用途を持っている<br>C5：各部門が自走し、専門チームは標準と監査に専念している | 経営企画、情報システム部門 |
| データ(文書、業務記録)の整備はどうなっていますか | C1：個人の手元にあり、どこに何があるか分からない<br>C2：共有はされているが、整理や権限の管理はない<br>C3：主要な文書は整理され、アクセス権が決まっている<br>C4：データの品質を測り、整備する担当がいる<br>C5：データの整備が日常の業務に組み込まれ、全員が担っている | 情報システム部門、各部門の課長 |

採点の規則は次のとおりで、アプリも同じ規則で集計します。事業フェーズは、5問で最も多く選ばれた区分を現在地とします。同数のときは、最初の問い(売上の動き)の答えを優先します。導入フェーズと文化フェーズは、答えた段階の数字(S3なら3、C2なら2)の平均を四捨五入した段階を現在地とします。1問だけ高い答えで段階が跳ねないよう、最大ではなく平均を使います。そのうえで、最も低い答えの設問が、次に上げるべき場所(ボトルネック)です。段階が上がるほど評価と統治が先に要るため、低い答えが1つあれば、そこが次の制約になります。アプリの結果画面も、最も低い答えの設問を示します。

### 6. 3つを重ねて読む

3本の物差しの組み合わせが、次の一手を決めます。典型的な組み合わせを4つ挙げます。

**高い導入、低い文化**。S3以上の仕組みがあるのに、C2で止まっている状態です。Microsoftの区分(第7節)ではBlocked agencyかUnclaimed capacityに当たります [ [ 205 ] ](https://assets-c4akfrf5b4d3f4b7.z01.azurefd.net/assets/2026/05/2026_Work_Trend_Index_Annual_Report_050526-7_69fc5b1c4e265.pdf) 。仕組みは使われず、投資は回収されません。次の一手は技術ではなく、[文化の形成の章](36-culture-formation)の施策です。

**低い導入、高い文化**。従業員が自前のツールで業務を進めているのに、会社がS1かS2で止まっている状態です。情報漏えいの危険が最も高い組み合わせです。次の一手は、公認の基盤を配ること(S2からS3)です。

**成熟事業、高い導入**。費用削減の用途でS4に達した状態です。ここから先は、同じ用途を深めても効果は逓減します。次の一手は、別の事業フェーズの事業にAIを当てること(両利き)か、商品への組み込み(S5)です。

**探索事業、低い導入**。新規事業がAIをまだ使っていない状態です。探索事業は失敗の損失が小さいため、S4やS5を直接試す余地があります。成熟事業の統治の基準を探索事業にそのまま当てると、芽を摘みます。この点は3つの地平の考え方と同じです [ [ 278 ] ](https://openlibrary.org/works/OL512178W) 。

### 7. 物差しを分ける根拠となる調査

Accentureは2022年に1,200社を調べ、データとクラウドなどの「基盤の能力」と、戦略・人材・文化などの「差別化の能力」の2軸で企業を4つに分けました。両方とも低いExperimentersは63%、基盤だけ高いBuildersは12%、差別化だけ高いInnovatorsは13%、両方とも高いAchieversは12%でした [ [ 195 ] ](https://newsroom.accenture.com/news/2022/more-than-60-percent-of-companies-are-only-experimenting-with-ai-creating-significant-opportunities-for-value-on-their-journey-to-ai-maturity-accenture-research-finds) 。基盤と差別化は独立に動くため、4つの象限に企業が散らばります。

Microsoftは2026年に10か国20,000人のAI利用者を調べ、個人のAI能力と組織の準備度の2軸で5つの区分を示しました。両方とも高いFrontierは19%、両方とも形成中のEmergentは50%、両方とも低いStalledは16%です。個人の能力だけが高いBlocked agencyは10%、組織の準備度だけが高いUnclaimed capacityは5%でした [ [ 205 ] ](https://assets-c4akfrf5b4d3f4b7.z01.azurefd.net/assets/2026/05/2026_Work_Trend_Index_Annual_Report_050526-7_69fc5b1c4e265.pdf) 。個人と組織は別々に動きます。利用者の1割では、個人が先に進み、組織の追いついていない状態にあります。

学術研究では、Jöhnkらが2021年に組織のAIへの準備度を5つの範疇に分けました。戦略の整合、資源、知識、文化、データの5つで、合計18の因子を挙げています [ [ 215 ] ](https://aisel.aisnet.org/bise/vol63/iss1/2) 。準備度は技術の導入度とは別に測るべきものとして扱われています。

### 経営層への含意

3本の物差しと各軸の段階は、著者による整理です。Accenture、Microsoft、IDC、Jöhnkらの調査が示すのは、技術の導入度と組織の準備度が別々に動くという事実であり、本書の3軸はその事実を経営の判断で使える形へ組み直したものです。

経営層が本章から持ち帰るべき点は3つです。

第一に、現在地は会社に1つではなく、事業と業務ごとにあります。会社全体で1つの段階を答えると、最も進んだ部分の段階になります。自己診断は、代表的な業務を1つ選び、観察できる事実で答えます。

第二に、導入フェーズと文化フェーズは別に測ります。配ることは契約で済みますが、文化は契約では動きません。日本企業の約3割弱が「組織的な取組はない」と答えている事実は、配ったあとに止まる企業が多いことを示します。

第三に、3本の位置の組み合わせが次の一手を決めます。高い導入と低い文化の組み合わせには文化の施策が、低い導入と高い文化の組み合わせには公認の基盤が、成熟事業の高い導入には別の事業フェーズへの展開が、それぞれ対応します。[道筋別の戦略の章](35-strategy-by-path)は、この組み合わせに未来の道筋を重ねて、次の一手を表にします。
