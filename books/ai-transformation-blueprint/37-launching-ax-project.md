### 序論：本章が扱う範囲

本章は、本書の全体を、経営会議に出す1枚の資料と、最初の90日の計画に落とす手順を示します。対象は、自社のAIトランスフォーメーション(以下、AX)のプロジェクトをこれから立ち上げる経営層と、その準備を担う実務者です。

手順は6つです。(1)現在地の自己診断、(2)前提として仮に置く道筋の決定と早期警戒指標の担当決め、(3)次の一手の計画、(4)統治の最低限、(5)会議資料の1枚の型、(6)90日の最初の計画です。各手順には、根拠となる章へのリンクを置きます。

先に明記します。本書と、本書の枠組みを画面にしたWebアプリ「AXコンパス」は、診断の目安であり、各社の判断を代替しません。自己申告に基づく診断は、回答者の立場によって結果が変わります。本章の手順は、判断の材料を同じ形に整えるためのものです。

### 1. 手順1：現在地を自己診断する

最初に、自社の現在地を3つの軸で決めます。事業フェーズ、導入フェーズ(S1〜S6)、文化フェーズ(C1〜C5)です。3つの軸の定義と質問は、[3つの現在地の章](32-three-positions)に示しました。

診断の方法は2つあります。第一に、同章の質問表を印刷し、経営層と実務者がそれぞれ回答して、差を見ることです。経営層と従業員の認識の差は、調査でも観測されています。McKinseyの調査では、従業員の13%が日常業務の30%以上で生成AIを使っており、経営層の推定の4%の3倍超でした [ [ 189 ] ](https://www.mckinsey.com/~/media/mckinsey/business%20functions/quantumblack/our%20insights/superagency%20in%20the%20workplace%20empowering%20people%20to%20unlock%20ais%20full%20potential%20at%20work/superagency-in-the-workplace-empowering-people-to-unlock-ais-full-potential-v4.pdf) 。

第二に、Webアプリ「[AXコンパス](https://takenori-kusaka.github.io/ax-compass/)」を使うことです。本書と同時に公開しています。同章と同じ質問に画面で答えると、結果を出力します。出力するのは、3つの軸の現在地、前提として仮に置く道筋、次の一手の候補です。加えて、関係する提供事業者の層と、会議体向けの1枚の資料も出します。入力は端末の中に保存され、外部へ送信しません。回答はURLに符号化して共有できます。アプリは本書の枠組みを機械的に当てはめるもので、本書の各章へ根拠のリンクを付けています。アプリの「はじめに」の画面からは、本書の内容をまとめた40枚のスライドをPowerPoint形式でダウンロードできます。

診断の結果は、次のように読みます。導入フェーズと文化フェーズの差が大きいときは、先に低い方を上げます。たとえば導入がS3で文化がC2(個人の試行、統制の外)なら、手順の組み込みより先に、公認の試行の場とガイドラインを作ります。IPAのDX推進指標は、全社の仕組みがない中で部門の試行を繰り返すと「ただ単に失敗を繰り返すだけになる」と記しています [ [ 225 ] ](https://www.ipa.go.jp/pressrelease/2025/press20250507.html) 。

日本企業の分布を参照値として置きます。総務省の令和8年版「情報通信白書」では、何らかの業務で生成AIを利用する企業は86.4%に達した一方で、生成AIによる業務の変革について「組織的な取組はない」企業が約3割弱あり、他の3か国より多いとされています [ [ 107 ] ](https://www.soumu.go.jp/main_content/001082851.pdf) 。IPAのDX動向2026では、AIの導入効果として「業務が効率化した」は91.6%、「売上や利益が向上」は3.9%でした [ [ 124 ] ](https://www.ipa.go.jp/digital/chousa/dx-trend/rcu1hd0000017uk8-att/dx-trend-2026.pdf) 。多くの日本企業は、S2からS3、C2からC3の境界にいる、というのが本書の読みです。

### 2. 手順2：前提とする道筋を決め、指標の担当を決める

次に、[3つの道筋の比較の章](29-paths-comparison-indicators)で示した道筋A(加速)、B(漸進)、C(調整)のうち、自社の戦略の前提として仮に置く道筋を決めます。

ここで行うのは、どれが正しいかを当てることではありません。本書は1つの正解を出していません。同章の比較表と指標は、前提として仮に置く道筋を決めるための材料です。決めるのは、「自社はどの道筋を前提に投資するか」と、「前提が崩れたことをどの指標で知るか」です。道筋を1つに決めない選択もあります。その場合は、[道筋別の戦略の章](35-strategy-by-path)の「選択権を買う手」が中心になります。

早期警戒指標は2種類を持ち、それぞれに担当者と確認の頻度を付けます。

**自社で測る指標**。自社の中の変化は、自社でしか測れません。本書が勧めるのは次の4つです。これらは著者の例示であり、指標の名前と定義は各社で決めます。

| 指標 | 測り方の例 | 担当の例 |
| --- | --- | --- |
| 削減時間 | 対象の業務の1件あたりの所要時間を、導入の前後で比べる | 各事業部 |
| 利用者の割合 | 配った席のうち、月に1回以上使った人の割合 | 情報システム部 |
| 差し戻し率 | AIを使った成果物のうち、確認者が差し戻した割合 | 各事業部 |
| ガイドライン違反の件数 | 入力してはならない情報の入力など、規程に反した件数 | 法務、情報セキュリティの担当 |

**社外の指標**。どの道筋へ進んでいるかは、社外の指標で知ります。[3つの道筋の比較の章](29-paths-comparison-indicators)で経営会議向けに選んだ上位3つを使います。AIから大きな価値を実現した企業の比率、大手クラウド事業者の設備投資、AIの時間地平です。時間地平は、AIが人の手を借りずにこなせる作業の長さを、人がかかる時間で表したものです。この指標を公表してきたMETRは2026年9月に公式ページの更新を停止しました [ [ 63 ] ](https://metr.org/time-horizons) 。代替の指標を探す必要があります。加えて、法令の適用時期も見ます。EU AI Actの高リスク規定は2027年12月へ延期されました [ [ 649 ] ](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai) 。

経営会議での確認は四半期に1回で足ります。毎週の報道を追う必要はありません。自社の指標は毎月集計し、四半期の会議で推移を見ます。社外の指標は、公表の頻度がそれぞれ違います。第29章の表のとおり、価値を実現した企業の比率は年次、設備投資は四半期の決算、時間地平は半年ごとに確かめ、新しい値が出た回の会議で更新します。

### 3. 手順3：次の一手を計画する

現在地と道筋が決まれば、次の一手は[道筋別の戦略の章](35-strategy-by-path)の表から読めます。本節では、その読み方を補います。

**導入フェーズを1段上げる**。S2からS3へ上げるなら、部門の手順への組み込み、プロンプトとテンプレートの共有、社内文書の検索基盤が対象です。S3からS4へ上げるなら、基盤モデルのAPIを自社システムから呼ぶ構成、評価と監視、費用の管理が対象です。各段階で必要な人材、データ、統治、評価、費用は[各段階で必要なものの章](34-requirements-and-providers)に、提供事業者の層は[市場の地図の章](18-market-map)にあります。

**運営モデルを選ぶ**。[運営モデルの進化の章](33-operating-model-evolution)で示したとおり、初期はSaaSの契約、中間はIT部門かCoE(中核組織)による取りまとめ、その後は事業部への分散、という推移が各社の実例に共通します。日立は2023年5月にCoE「Generative AIセンター」を新設し、グループ32万人の利用推進と顧客向けの支援を柱にしました [ [ 233 ] ](https://www.hitachi.com/ja-jp/press/articles/2023/05/0515) 。KDDIは、全社員へのチャット提供というボトムアップと、本部長をオーナーとする業務組み込みというトップダウンの2面で進め、得た知見を法人向けに提供しています [ [ 242 ] ](https://biz.kddi.com/beconnected/feature/2024/240306) 。NTTデータは、2023年7月の先行利用から全社導入、社内の知識検索、人材育成の枠組みを経て、2027年度までに全社員20万人への展開を計画し、生成AI関連の受注は2,000件を超えました [ [ 243 ] ](https://www.nttdata.com/global/ja/news/release/2025/102900) 。

**エージェントの自律性を決める**。[AIエージェントの導入の章](31-agent-adoption-stages)で示したとおり、自律性は業務ごとに決めます。最初はA0からA1(読ませる、提案させる)で始め、A2(承認つき実行)に進むのは、評価の仕組みができてからです。

**費用の目安**。社長が最初に聞くのは、「いくらかかるか」です。ここでは、公表された価格を円に換算した早見表を置きます。

席課金のSaaSは、1人ごとに月額を払う契約です。Microsoft 365 Copilotは1ユーザー月30ドルで、2023年の発表以来据え置かれています。中小企業向けには通常21ドルの追加版があり、2026年7月から12月は初年度18ドルの販促価格です [ [ 439 ] ](https://www.microsoft.com/en-us/microsoft-365-copilot/pricing/enterprise) 。Googleは2025年1月にGeminiをWorkspaceの標準機能として同梱し、追加版で月32ドルだった顧客の価格を14ドルにしました [ [ 440 ] ](https://workspace.google.com/blog/product-announcements/empowering-businesses-with-AI) 。

次の表は、1ユーザー月30ドルの席課金を配った場合の、著者の試算です。前提は、1ドル=150円と仮定し、席の数だけを数えることです。既存の業務ソフトの契約、導入の支援、教育の費用は含みません。

| 配る範囲 | 人数 | 月額 | 年額 |
| --- | --- | --- | --- |
| 全員(100人の企業) | 100人 | 45万円 | 540万円 |
| 全員(300人の企業) | 300人 | 135万円 | 1,620万円 |
| 全員(800人の企業) | 800人 | 360万円 | 4,320万円 |
| 800人のうち、事務・設計・営業の一部 | 250人 | 約113万円 | 1,350万円 |

800人の企業では、全員に配るか一部に配るかで、年額が3倍以上違います。筆者は、最初は利用の見込める部門に配り、手順2の利用者の割合を見て広げる方が、費用を説明しやすいと考えます。

APIの従量課金は、使った量に応じて払う契約です。量はトークンで数えます。トークンは、AIが文章を読み書きするときの量の単位で、文章を細かく区切った断片の数です。2026年10月時点で、Opus級(同社の最上位の級)が100万トークンあたり入力4ドル、出力20ドル、最も安価な級で入力0.10ドル、出力0.50ドルです [ [ 423 ] ](https://platform.claude.com/docs/en/about-claude/pricing) 。

次の表は、APIで1つの業務を自動化した場合の月額の、著者の試算です。前提は、1ドル=150円と仮定し、1件あたり入力5,000トークン、出力1,000トークンとすることです。入力は読ませる文書と指示、出力はAIが書く文章です。1件の分量は業務によって大きく変わるため、自社の業務で1件を試して測り直します。自社のシステムとつなぐ開発、評価、監視の費用は含みません。

| 級 | 1件あたり | 月1,000件 | 月1万件 |
| --- | --- | --- | --- |
| Opus級 | 約6円 | 約6,000円 | 約6万円 |
| 最も安価な級 | 約0.15円 | 約150円 | 約1,500円 |

同じ業務でも、級の選び方で費用は40倍違います。価格は年単位で桁が下がるため、費用の見積もりでは、「今の価格」と「1年後に半分以下となる前提」の両方を置きます。

**製造業での使い道を選ぶ**。IPAの調査では、生成AIの用途は「文書・音声の要約・翻訳・校正」82.5%と「文書・レポートの作成」80.5%が上位でした。利用部署は、情報システム71.9%、経営企画69.0%、総務・法務68.4%に対し、製造35.7%、調達31.3%、流通23.9%です。AIエージェントの利用は、いずれの部署でも低い水準でした [ [ 124 ] ](https://www.ipa.go.jp/digital/chousa/dx-trend/rcu1hd0000017uk8-att/dx-trend-2026.pdf) 。製造と調達の部署での利用は、本社の部署の約半分です。

次の表は、製造業での使い道の例です。事実の報告ではなく、著者の例示です。

| 業務 | 使い道の例 | 始める段階 | 注意 |
| --- | --- | --- | --- |
| 設計 | 設計文書と仕様書の下書き、過去の設計変更の記録の検索 | S2〜S3 | 図面と取引先の技術情報は、入力の区分を決めてから扱う |
| 品質 | 品質報告書と不具合報告の要約、似た不具合の検索 | S3 | 結論は品質保証の担当者が確かめる |
| 調達 | 複数の見積書の条件を並べた比較表づくり | S2 | 取引先の見積の扱いは、秘密保持の契約に従う |
| 技術伝承 | 熟練者への聞き取りの記録から手順書の下書きを作る | S3 | 手順書は熟練者が確かめる |
| 営業 | 提案書と議事録の下書き | S2 | 顧客の個人情報は入力しない |

### 4. 手順4：統治の最低限を決める

導入の段階にかかわらず、最初の会議で決めるべき統治は4つです。[統治と規制の章](17-governance-regulation)の内容を、決める順に並べます。

第一に、利用のガイドラインです。日本では、生成AIに関する従業員向けのガイドラインを策定していない企業が多いとされています [ [ 512 ] ](https://www.jil.go.jp/event/ro_forum/20260120/houkoku/01-keynote-toda.html) 。日本ディープラーニング協会は、組織が最初に整える利用ガイドラインのひな形を公開しており、各組織の目的に合わせて修正して使うことを想定しています [ [ 230 ] ](https://www.jdla.org/document/) 。総務省と経済産業省のAI事業者ガイドライン第1.2版には、チェックリストとワークシートが付いています [ [ 496 ] ](https://www.meti.go.jp/shingikai/mono_info_service/ai_shakai_jisso/20260331_report.html) 。

第二に、データの扱いです。個人情報保護委員会の注意喚起に従い、個人データを含む入力が利用目的の範囲内か、提供事業者が機械学習に使わないかを確認します [ [ 500 ] ](https://www.ppc.go.jp/news/careful_information/230602_AI_utilize_alert) 。本書は、製造業ではさらに、図面と取引先から預かった技術情報と営業秘密について、入力してよいかの区分を決めることを勧めます。

第三に、エージェントのIDと権限です。エージェントに人とは別のIDを与え、読める範囲と実行できる範囲を分けます。この道具は、Microsoft、Okta、AWSなどが提供しています。

第四に、承認の位置です。不可逆な操作(送信、支払い、削除、署名)の前に人が承認する設計を、業務ごとに決めます。

これら4つは、国際標準ISO/IEC 42001が求めるAIマネジメントシステムの一部でもあります [ [ 654 ] ](https://www.iso.org/standard/42001) 。認証の取得は任意です。一方で、日本の「適正性確保に関する指針」が同標準に言及していることを、[統治と規制の章](17-governance-regulation)で述べました [ [ 493 ] ](https://www8.cao.go.jp/cstp/ai/ai_guideline/ai_gl_2025.pdf) 。

### 5. 手順5：会議資料の1枚の型

経営会議に出す資料は、1枚に収めます。本書が勧める型は、次の8つの見出しです。AXコンパスは、この型で資料を出力します。

| 見出し | 書くこと | 記入例 | 根拠の章 |
| --- | --- | --- | --- |
| 1. 現在地 | 事業フェーズ、導入フェーズ、文化フェーズ | 成熟(効率)、S2、C2 | [3つの現在地の章](32-three-positions) |
| 2. 前提とする道筋 | A、B、Cのいずれか、または「決めない」 | B(漸進)を前提に、Aへの選択権を持つ | [3つの道筋の比較の章](29-paths-comparison-indicators) |
| 3. 早期警戒指標 | 指標名、現在値、担当、確認の頻度 | 自社: 削減時間、利用者の割合。社外: 第29章の上位3つ。確認は四半期の会議 | 同上 |
| 4. 次の一手 | 上げる軸と段階、期限 | C2→C3(ガイドラインと公認の試行の場)、90日 | [道筋別の戦略の章](35-strategy-by-path) |
| 5. 運営モデル | 誰が取りまとめるか | IT部門が契約と統治、事業部が用途 | [運営モデルの進化の章](33-operating-model-evolution) |
| 6. 必要なものと提供事業者の層 | 人材、データ、統治、評価、費用と、買う層 | L4 業務アプリ内蔵(既に使っている業務ソフトに組み込まれたAI)の席課金から開始 | [各段階で必要なものの章](34-requirements-and-providers) |
| 7. 統治の最低限 | ガイドライン、データ、ID、承認 | ガイドライン策定、個人情報と図面の入力禁止、承認はA1まで | [統治と規制の章](17-governance-regulation) |
| 8. 答えていない問い | 決めなかったこと、分からないこと | 顧客接点への適用時期、SI依存の解消策 | 総括 |

8番目の見出しは、本書の記述規範に由来します。決めなかったことを書かない資料は、決めたことの範囲が分からなくなります。

**完成版の例：部品メーカーA社の1枚**。次の表は、8つの見出しをすべて埋めた1枚の例です。A社は、従業員800人の部品メーカーという架空の会社で、実在の企業ではありません。金額は本章の試算に基づきます。

| 見出し | A社の記入 |
| --- | --- |
| 1. 現在地 | 主力の部品事業は成熟(効率が主題)。導入はS2(チャット型のサービスを会社で契約し、事務の一部に配っている)。文化はC2(配っていない部門では、従業員が個人の判断で使い、組織は黙認している) |
| 2. 前提とする道筋 | 道筋B(漸進)を仮に前提とする。道筋Aへの選択権として、設計部門でAPIの小さな試行を1件持つ。道筋Cに備え、特定の提供事業者に業務を深く結びつけない |
| 3. 早期警戒指標 | 自社で測る3つ: 削減時間(各事業部、毎月集計)、利用者の割合(情報システム部、毎月集計)、差し戻し率(品質保証部、毎月集計)。社外の2つ: AIから大きな価値を実現した企業の比率(経営企画部、年次)、大手クラウド事業者の設備投資(経営企画部、四半期の決算)。確認は四半期の経営会議 |
| 4. 次の一手 | C2→C3。90日でガイドラインを公開し、公認の試行の場を1つ作る。続けてS3へ上げる対象として、品質報告書の要約を1業務選ぶ |
| 5. 運営モデル | 情報システム部が契約、統治、費用を取りまとめ、事業部が用途を選ぶ。各事業部に推進の担当者を1人置く |
| 6. 必要なものと層 | L4 業務アプリ内蔵(Microsoft 365 Copilotなどの、既に使っている業務ソフトに組み込まれたAI)の席課金を、事務・設計・営業の250人に配る。年額は約1,350万円。設計部門の試行は、L3 基盤モデル(AIの本体を提供する事業者)のAPIを使い、月数万円の範囲に収める |
| 7. 統治の最低限 | ガイドラインを策定する。入力しない区分として、個人情報、図面、取引先から預かった技術情報、営業秘密を定める。エージェントはA1(提案まで。実行は人)にとどめる |
| 8. 答えていない問い | 工場の生産現場への適用の時期。取引先からAIの利用条件を求められたときの方針。全員に配るかどうかを決める基準 |

この例は、写して自社の値に直すための見本です。見出し3の担当と頻度、見出し6の人数と金額は、各社の現在地で変わります。

### 6. 手順6：最初の90日

最初の90日の計画の例を、現在地がS2×C2の企業を想定して示します。これは例であり、各社の現在地によって中身は変わります。

**第1〜30日：測る**。自己診断を経営層と実務者の双方で行い、差を記録します。社内で既に使われている生成AIの道具を、統制の外のものを含めて棚卸しします。デジタル庁は2024年度の技術検証で、専門家の伴走支援を受けたチームの70%が業務利用に至ったと報告しています [ [ 514 ] ](https://www.digital.go.jp/news/527968c1-5f55-42d4-868c-54112776c19f) 。測る段階から、伴走する人を付けます。

**第31〜60日：決める**。手順4の統治の最低限を決め、ガイドラインを公開します。道筋と早期警戒指標の担当を決めます。公認の試行の場を1つ作り、参加を募ります。

**第61〜90日：1つ上げる**。文化フェーズをC2からC3へ上げたことを、ガイドラインの公開と試行の場の稼働で確認します。導入フェーズについては、S3へ上げる対象の業務を1つ選び、手順への組み込みを始めます。効果の測定は、時間の削減だけでなく、品質と差し戻し率を含めます。IPAの調査で「売上や利益が向上」が3.9%にとどまることを踏まえ [ [ 124 ] ](https://www.ipa.go.jp/digital/chousa/dx-trend/rcu1hd0000017uk8-att/dx-trend-2026.pdf) 、売上への効果は90日で測らず、次の四半期の計画に送ります。

90日の終わりに、1枚の資料を更新し、次の90日の計画を立てます。段階を1つ上げるごとに、この手順を繰り返します。

### 経営層への含意

本章の手順は、本書の枠組みを会議に持ち込むための型であり、各社の判断を代替するものではありません。使うときの注意を3つ述べます。

第一に、診断は自己申告です。経営層と実務者の回答の差そのものが、文化フェーズの現在地を示す情報になります。差を埋めることより、差があると知ることが先です。

第二に、前提とする道筋を決めることは、予測を当てることではありません。前提を明示し、前提が崩れたことを知る指標を持つことです。前提が崩れたら、資料を更新します。本書の記述規範が「外れる条件」を各道筋に付けているのは、この使い方のためです。

第三に、最初の90日で上げる段階は1つです。導入と文化の両方を同時に2段上げる計画は、Gartnerが中止の理由として挙げた「費用の増大、不明確な事業価値、不十分なリスク管理」の3つを同時に招きます [ [ 181 ] ](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027) 。

本書は、生成AIの系譜と現在地、普及の理論、3つの道筋、そして導入の枠組みを、すべてこの1枚の資料のために書きました。資料が会議で使われ、次の90日の計画になり、四半期ごとに更新されること。それが、本書が目指した状態です。
