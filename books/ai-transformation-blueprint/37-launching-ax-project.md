### 序論：本章が扱う範囲

本章と次の章は、本書の全体を、経営会議に出す1枚の資料と、最初の90日の計画に落とす手順を示します。対象は、自社のAIトランスフォーメーション(以下、AX)のプロジェクトをこれから立ち上げる経営層と、その準備を担う実務者です。

手順は6つです。(1)現在地の自己診断、(2)前提として仮に置く道筋の決定と早期警戒指標の担当決め、(3)次の一手の計画、(4)統治の最低限、(5)会議資料の1枚の型、(6)90日の最初の計画です。本章は手順1から手順4までを扱い、手順3のあとに、最初に買う製品と次に買う製品の選び方を置きます。手順5と手順6、費用の試算、記入例は[会議資料と90日計画の章](38-meeting-pack)で扱います。各手順には、根拠となる章へのリンクを置きます。本文では節の番号ではなく手順の番号で参照します。

先に明記します。本書と、本書の枠組みを画面にしたWebアプリ「AXコンパス」は、診断の目安であり、各社の判断を代替しません。自己申告に基づく診断は、回答者の立場によって結果が変わります。本章の手順は、判断の材料を同じ形に整えるためのものです。

### 1. 手順1：現在地を自己診断する

最初に、自社の現在地を3つの軸で決めます。事業フェーズ、導入フェーズ(S1〜S6)、文化フェーズ(C1〜C5)です。3つの軸の定義と質問は、[3つの現在地の章](32-three-positions)に示しました。複数の業務や事業を持つ企業は、主要な部門ごとに診断し、資料には部門別の分布(例：間接部門S3、設計S2、製造S1)を書きます。

診断の方法は2つあります。第一に、同章の質問表を印刷し、経営層と実務者がそれぞれ回答して、差を見ることです。経営層と従業員の認識の差は、調査でも観測されています。McKinseyの調査では、従業員の13%が日常業務の30%以上で生成AIを使っていました。経営層は4%と推定しており、実際はその3倍超でした [ [ 189 ] ](https://www.mckinsey.com/~/media/mckinsey/business%20functions/quantumblack/our%20insights/superagency%20in%20the%20workplace%20empowering%20people%20to%20unlock%20ais%20full%20potential%20at%20work/superagency-in-the-workplace-empowering-people-to-unlock-ais-full-potential-v4.pdf) 。

第二に、Webアプリ「[AXコンパス](https://takenori-kusaka.github.io/ax-compass/)」を使うことです。本書と同時に公開しています。同章と同じ質問に画面で答えると、3つの軸の現在地、前提として仮に置く道筋、次の一手の候補、関係する提供事業者の層、会議体向けの1枚の資料を出します。入力は端末の中に保存され、外部には送信されません。回答を含むURLを作って共有できます。アプリは本書の枠組みを機械的に当てはめるもので、本書の各章へ根拠のリンクを付けています。アプリの「はじめに」の画面からは、本書の内容をまとめた40枚のスライドをPowerPoint形式でダウンロードできます。

診断の結果は、次のように読みます。導入フェーズと文化フェーズの差が大きいときは、先に低い方を上げます。たとえば導入がS3で文化がC2(個人の試行、統制の外)なら、手順の組み込みより先に、利用規程と学ぶ場を作り、推進者を任命します。IPAのDX推進指標は、全社の仕組みがない中で部門の試行を繰り返すと「ただ単に失敗を繰り返すだけになる」と記しています [ [ 225 ] ](https://www.ipa.go.jp/pressrelease/2025/press20250507.html) 。

日本企業の分布を参照値として置きます。総務省の令和8年版「情報通信白書」では、何らかの業務で生成AIを利用する企業は86.4%に達した一方で、「組織的な取組はない」企業が3割弱あります([企業の利用の章](12-enterprise-adoption)) [ [ 107 ] ](https://www.soumu.go.jp/main_content/001082851.pdf) 。IPAの「DX動向2026」では、AIの導入効果として「業務が効率化した」は91.6%、「売上や利益が向上」は3.9%でした [ [ 124 ] ](https://www.ipa.go.jp/digital/chousa/dx-trend/rcu1hd0000017uk8-att/dx-trend-2026.pdf) 。多くの日本企業は、S2からS3、C2からC3の境界にいる、というのが本書の読みです。

### 2. 手順2：前提とする道筋を決め、指標の担当を決める

次に、[3つの道筋の比較の章](29-paths-comparison-indicators)で示した道筋A(加速)、B(漸進)、C(調整)のうち、自社の戦略の前提として仮に置く道筋を決めます。

ここで行うのは、どれが正しいかを当てることではありません。本書は1つの正解を出していません。同章の比較表と指標は、前提として仮に置く道筋を決めるための材料です。決めるのは、「自社はどの道筋を前提に投資するか」と、「前提が崩れたことをどの指標で知るか」です。道筋を1つに決めない選択もあります。その場合は、[道筋別の戦略の章](35-strategy-by-path)の「選択権を買う手」が中心になります。著者は、経営企画の部門を持たない小さな会社では、「道筋を1つに決めない」を既定の選択にするよう勧めます。社外の指標を追う人手を要しないためです。

早期警戒指標は2種類を持ち、それぞれに担当者と確認の頻度を付けます。

**自社で測る指標**。自社の中の変化は、自社でしか測れません。本書が勧めるのは次の4つです。これらは著者の例示であり、指標の名前と定義は各社で決めます。

| 指標 | 測り方の例 | 担当の例 | 注意 |
| --- | --- | --- | --- |
| 削減時間 | 導入の前後の、対象業務1件あたりの所要時間の差 | 各事業部 | 月の削減時間に時給を掛けて円に直し、何人分に当たるかを示す。削減時間を何に変える(残業の削減、外注の縮小、採用の抑制、増産への対応)かは手順3で決める |
| 利用者の割合 | 配った席のうち、週に1回以上使った人の割合。または月の利用日数 | 情報システム部 | 月1回以上の基準は緩く、ほぼ全員が該当する。席の回収の基準(たとえば3か月続けて週1回未満)と対にする。公表された参照値は乏しい |
| 差し戻し率 | AIを使った成果物のうち、確認者が差し戻した割合 | 各事業部 | 品質の指標。削減時間と対で見る |
| ガイドライン違反の件数 | 入力してはならない情報の入力など、規程に反した件数 | 法務、情報セキュリティの担当 | 検知の仕組みがある場合のみ。ない場合は、件数は定義上ゼロになるため、自己申告の相談件数で代用する |

**社外の指標**。どの道筋へ進んでいるかは、社外の指標で知ります。[3つの道筋の比較の章](29-paths-comparison-indicators)で経営会議向けに選んだ上位3つを使います。AIから大きな価値を実現した企業の比率、大手クラウド事業者の設備投資、AIの時間地平です。時間地平は、AIが人の手を借りずにこなせる作業の長さを、人がかかる時間で表したものです。この指標を公表してきたMETRは2026年9月に公式ページの更新を停止しました [ [ 63 ] ](https://metr.org/time-horizons) 。代替の指標は同章の表に記したとおり、新しい課題群での倍増期間と、80%の成功率で測った時間地平です。読者が探す必要はありません。加えて、法令の適用時期も見ます。EU AI Actの高リスク規定は2027年12月へ延期されました [ [ 649 ] ](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai) 。

確認の頻度は、自社の指標と社外の指標で分けます。自社の指標は毎月集計し、四半期の経営会議で推移を見ます。社外の指標は四半期の経営会議には出さず、年に1回、中期計画の見直しの時に経営企画が確認します。経営企画の部門を持たない小さな会社では、社長が年に1回、[3つの道筋の比較の章](29-paths-comparison-indicators)の表を見返します。社外の指標は公表の頻度がそれぞれ違い、同章の表のとおり、価値を実現した企業の比率は年次、設備投資は四半期の決算、時間地平は半年ごとに新しい値が出ます。毎週の報道を追う必要はありません。

### 3. 手順3：次の一手を計画する

現在地と道筋が決まれば、次の一手は[道筋別の戦略の章](35-strategy-by-path)の表から読めます。本節では、その読み方を補います。

**導入フェーズを1段上げる**。S2からS3へ上げるなら、部門の手順への組み込み、プロンプトとテンプレートの共有、社内文書の検索基盤が対象です。S3からS4へ上げるなら、基盤モデルのAPIを自社システムから呼ぶ構成、評価と監視、費用の管理が対象です。各段階で必要な人材、データ、統治、評価、費用は[各段階で必要なものの章](34-requirements-and-providers)に、提供事業者の層は[市場の地図の章](18-market-map)にあります。

**運営モデルを選ぶ**。[運営モデルの進化の章](33-operating-model-evolution)で示したとおり、初期はSaaSの契約、中間はIT部門か推進組織による取りまとめ、その後は事業部への分散、という推移が各社の実例に共通します。日立は2023年5月に推進組織「Generative AIセンター」を新設し、グループ32万人の利用推進と顧客向けの支援を柱にしました [ [ 233 ] ](https://www.hitachi.com/ja-jp/press/articles/2023/05/0515) 。KDDIは、全社員へのチャット提供というボトムアップと、本部長をオーナーとする業務組み込みというトップダウンの2面で進め、得た知見を法人向けに提供しています [ [ 242 ] ](https://biz.kddi.com/beconnected/feature/2024/240306) 。NTTデータは、2023年7月の先行利用から全社導入、社内の知識検索、人材育成の枠組みを経て、2027年度までに全社員20万人への展開を計画し、生成AI関連の受注は2,000件を超えました [ [ 243 ] ](https://www.nttdata.com/global/ja/news/release/2025/102900) 。

**エージェントの自律性を決める**。[AIエージェントの導入の章](31-agent-adoption-stages)で示したとおり、自律性は業務ごとに決めます。最初はA0からA1(読ませる、提案させる)で始めます。A2(承認つき実行)は、承認者の指定と実行の記録があれば、既存のSaaSの機能と承認の運用で始められます。A3(範囲内の自律実行)に進むのは、評価と記録の仕組みができてからです。

**効果の回収計画を決める**。経営層(社長、役員会)が「いくらかかるか」の次に聞くのは、「いくら戻るか」です。削減時間は、そのままでは損益に現れません。月の削減時間に時給を掛けて円に直し、何人分に当たるかを示したうえで、その時間を何に変えるかを決めます。選択肢は、残業の削減、外注の縮小、採用の抑制、増産への対応のいずれかです。どれに変えるかの責任者は、推進組織ではなく事業部長です。[投資対効果と失敗率の章](15-roi-and-failure)で見たとおり、「業務が効率化した」が9割、「売上や利益が向上」が1桁%という段差は、速くなった時間の行き先を決めていないことの現れだと著者は考えます。

**使い道を選ぶ**。IPAの調査では、生成AIの用途は「文書・音声の要約・翻訳・校正」82.5%と「文書・レポートの作成」80.5%が上位でした。利用部署は、情報システム71.9%、経営企画69.0%、総務・法務68.4%に対し、製造35.7%、調達31.3%、流通23.9%です。AIエージェントの利用は、いずれの部署でも低い水準でした [ [ 124 ] ](https://www.ipa.go.jp/digital/chousa/dx-trend/rcu1hd0000017uk8-att/dx-trend-2026.pdf) 。製造と調達の部署での利用は、本社の部署の約半分です。

次の表は、業種を問わない事務の使い道の例です。事実の報告ではなく、著者の例示です。業務の範囲の区分は、[AIエージェントの導入の章](31-agent-adoption-stages)の表に従います。

| 業務 | 使い道の例 | 始める段階 | 注意 |
| --- | --- | --- | --- |
| 人事・採用 | 求人票の下書き、面談記録の要約 | S2 | 応募者と従業員の個人情報は、入力の区分を決めてから扱う |
| 総務・法務 | 契約書の下書きと条項の比較、規程の検索 | S2〜S3 | 規程の検索は社内文書検索の典型。結論は担当者が確かめる |
| 経理・勤怠 | 請求書の確認、勤怠の照会への回答の下書き | S2〜S3 | 金額と期日は人が確かめる |

| 照会対応 | 社内外からの照会への回答の下書き、過去の回答の検索 | S2〜S3 | 顧客向けの回答は、送る前に人が確認する |

### 4. 製品を選ぶ基準

経営層の次の質問は、「どの会社の何を買うか」です。本書は特定の製品を推奨しません。製品の機能と価格は年単位で変わるためです。代わりに、選ぶ基準を表にします。基準は著者の整理で、各基準の根拠には本書の他の章の事実を引きます。本書は法的助言ではなく、個別の適用は弁護士などに確認してください。

候補になる製品の例を並べます。順番に優劣の意味はありません。

- Microsoft 365 Copilot(Microsoft 365を使っている会社の例)
- Google Workspace(Geminiを同梱。Google Workspaceを使っている会社の例)
- ChatGPTの企業向けプラン
- Claudeの企業向けプラン
- 国内の業務SaaSに組み込まれたAI(サイボウズのkintone、LayerX、Exa Enterprise AIなど。[各段階で必要なものの章](34-requirements-and-providers)の表のL4の層)

著者の推奨は、表の基準で2〜3製品に絞り、30日ほど試してから決めることです。試すときは、同じ部門の数人が、自社の同じ文書を同じ指示で各製品に入れ、結果を並べて比べます。比べる項目は、日本語の質、手直しにかかった時間、管理者の画面で利用記録が見られるかです。試す文書には、手順4で入力を禁じる区分の情報を含めません。

**既に席を配った企業が次に買うもの**。チャット型の席を既に配っている企業が次に買うのは、S3の社内文書検索、L5の開発者ツールとエージェント基盤、L6の評価と観測の道具です([市場の地図の章](18-market-map))。この場合の基準は、上の表の「既存の席との接続」と「利用記録の粒度」です。既存の席と別のIDで動く製品は、利用記録が分かれ、手順2の指標を業務別に測れなくなります。買う順序は、利用率の止まった原因で決めます。原因が「業務に合わない」なら社内文書検索(S3)、「測れていない」なら評価と観測の道具(L6)です。原因の分け方は[会議資料と90日計画の章](38-meeting-pack)の90日計画の例3で示します。

### 5. 手順4：統治の最低限を決める

本書は法的助言ではなく、個別の適用は弁護士などに確認してください。導入フェーズにかかわらず、最初の会議で決める統治は4つです。[統治と規制の章](17-governance-regulation)の内容を、決める順に並べます。第一(ガイドライン)と第二(データ)は全社に当てはまります。第三(IDと権限)と第四(承認の位置)は、エージェントをA2以上で使う計画がある場合に方針として決め、専用の製品の購入はA3へ進む時点でよいものです。

第一に、利用のガイドラインです。日本では、生成AIに関する従業員向けのガイドラインを策定していない企業が多いとされています [ [ 512 ] ](https://www.jil.go.jp/event/ro_forum/20260120/houkoku/01-keynote-toda.html) 。日本ディープラーニング協会は、組織が最初に整える利用ガイドラインのひな形を公開しており、各組織の目的に合わせて修正して使うことを想定しています [ [ 230 ] ](https://www.jdla.org/document/) 。総務省と経済産業省のAI事業者ガイドライン第1.2版には、チェックリストとワークシートが付いています [ [ 496 ] ](https://www.meti.go.jp/shingikai/mono_info_service/ai_shakai_jisso/20260331_report.html) 。利用記録の取得と利用の義務づけは就業規則に関わるため、ガイドラインは就業規則との整合を確かめます。

第二に、データの扱いです。個人情報保護委員会の注意喚起に従い、個人情報を含む入力が利用目的の範囲内か、個人データを含む入力が応答の出力以外(学習など)に使われないかを確認します [ [ 500 ] ](https://www.ppc.go.jp/news/careful_information/230602_AI_utilize_alert) 。個人データを提供事業者に渡す場合は、個人情報保護法の第25条に基づく委託先の監督が要ります。委託先の選定と契約の条項と安全管理の確認です [ [ 1954 ] ](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/) 。あわせて、入力してよいかの区分を決めます。本書が勧める区分は次の3つです。

- 営業秘密。不正競争防止法の営業秘密は「有用性」「秘密管理性」「非公知性」の3要件を満たす情報で、保護を受けるには営業秘密として管理されている必要があります [ [ 1955 ] ](https://www.meti.go.jp/policy/economy/chizai/chiteki/trade-secret.html) 。区分を決めるのは、秘密管理性を保ち、取引先との秘密保持契約の第三者への開示の禁止に触れないためです。製造業では、図面と取引先から預かった技術情報がこれに当たります。
- 輸出管理規制の対象技術。外為法に基づく安全保障貿易管理は、技術の提供を目的とする取引も規制の対象にしています [ [ 1958 ] ](https://www.meti.go.jp/policy/anpo/index.html) 。アメリカの輸出管理規則(EAR)の対象技術も同様です。海外の提供事業者の環境に規制の対象技術を入れてよいかは、輸出管理の部門に確かめます。
- 個人情報を預かる業種の情報。人材、医療、会計などの業種では、本人の情報(履歴書、健康情報、マイナンバー)と、顧客から預かった情報(顧客企業の人事情報など)が最も危ない区分です。

第三に、エージェントのIDと権限です。エージェントに人とは別のIDを与え、読める範囲と実行できる範囲を分けます。A2までは、承認者の指定と実行の記録を既存のSaaSの機能で行えます。専用のID製品を買うのは、A3へ進む時点です。そのための製品は、Microsoft、Okta、AWSなどが提供しています。

第四に、承認の位置です。不可逆な操作(送信、支払い、削除、署名)の前に人が承認する設計を、業務ごとに決めます。

これら4つは、国際標準ISO/IEC 42001が求めるAIマネジメントシステムの一部でもあります [ [ 654 ] ](https://www.iso.org/standard/42001) 。認証の取得は任意です。ただし、日本の「適正性確保に関する指針」が同標準に言及していることを、[統治と規制の章](17-governance-regulation)で述べました [ [ 493 ] ](https://www8.cao.go.jp/cstp/ai/ai_guideline/ai_gl_2025.pdf) 。

### 経営層への含意

本章の手順は、本書の枠組みを会議に持ち込むための型であり、各社の判断を代替するものではありません。使うときの注意を3つ述べます。

第一に、診断は自己申告です。経営層と実務者の回答の差そのものが、文化フェーズの現在地を示す情報になります。差を埋めることより、差があると知ることが先です。

第二に、前提とする道筋を決めることは、予測を当てることではありません。前提を明示し、前提が崩れたことを知る指標を持つことです。前提が崩れたら、資料を更新します。本書の記述規範が「外れる条件」を各道筋に付けているのは、この使い方のためです。社外の指標を四半期ごとに追う必要はなく、年に1回で足ります。

第三に、統治の4つは、一度に製品を買いそろえるものではありません。ガイドラインとデータの区分は全社で最初に決め、エージェントのIDと権限、承認の位置は、A2以上で使う計画が出た時点で方針として決めます。専用の製品は、A3へ進む時点で足ります。

次の章では、ここまでの出力を1枚の資料に書き、費用を試算し、最初の90日の計画に落とします。
