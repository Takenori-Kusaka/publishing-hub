### 序論：本章が扱う範囲

本章は、企業の中で「誰が生成AIを取りまとめるか」という問いを扱います。初期はIT部門がSaaSを契約し、中間ではIT部門か専任の推進組織がAIを取りまとめ、最後は各事業部が自分で使いこなす。多くの企業がこの経路を語りますが、各段階で何が起きるかと、いつ次へ移るべきかは、あまり言語化されていません。

本章は運営モデルを5つの型に分け、それぞれを一次資料で確かめ、[生成AIの導入段階の章](30-genai-adoption-stages)の6段階と対応づけます。あわせて、日本に固有の条件として、IT人材がベンダー側に偏っている構造を扱います。この構造は、運営モデルの選択肢そのものを狭めます。

本章が扱わないのは、各運営モデルで必要になる人材の数や費用です。それは[各段階で必要なものの章](34-requirements-and-providers)で扱います。

### 1. 運営モデルの5つの型

本書は、生成AIの運営モデルを次の5つに分けます。型の名前と順序は著者による整理です。

| 型 | 名前 | 誰が決めるか | 典型の形 |
| --- | --- | --- | --- |
| O1 | SaaS利用 | IT部門が契約し、利用者が各自で使う | チャット型サービスの一括契約、利用規程 |
| O2 | 集中 | 専任の推進組織が用途と基盤と統治を一手に担う | AIセンター、CoE、CAIO |
| O3 | ハブ&スポーク | 推進組織が基盤と統治を担い、事業部が用途を担う | 推進組織と事業部の混成チーム |
| O4 | 分散 | 事業部が自走し、推進組織は標準と監査を担う | 各事業部の推進者、全社の標準と監査 |
| O5 | 製品組織 | AIが事業の一部になり、製品組織が担う | AI機能を持つ製品の開発組織 |

この5つは、McKinseyが示す生成AIの運営モデルの型である中央集権型、ハブ&スポーク型、分散型の3つに、前後の2つを加えたものです [ [ 191 ] ](https://www.mckinsey.com/capabilities/tech-and-ai/our-insights/a-data-leaders-operating-guide-to-scaling-gen-ai) 。前に加えたO1は、推進組織を作る前の状態です。後に加えたO5は、AIが業務支援の道具から製品の一部になった状態です。

### 2. 各型を裏づける事実

**O1：SaaS利用**。ほとんどの企業の出発点です。Microsoft 365 Copilotの有償席数は2026年7月の時点で3,000万を超え、Accentureの1社で74万席を超える契約があります [ [ 413 ] ](https://www.microsoft.com/en-us/investor/events/fy-2026/earnings-fy-2026-q4) 。OpenAIは2025年11月に、有料の法人顧客が100万社に達したと公表しました [ [ 441 ] ](https://openai.com/index/1-million-businesses-putting-ai-to-work/) 。契約の単位は席であり、運営はIT部門の契約管理の延長です。

**O2：集中**。専任の組織を作り、用途の発掘から基盤の整備と統治までを一手に担う型です。Gartnerが2024年第4四半期に432社を調べた結果では、AIの成熟度が高い組織の91%が専任のAIリーダーを任命し、約60%がAIの戦略と統治とデータと基盤を中央に集約していました [ [ 186 ] ](https://www.gartner.com/en/newsroom/press-releases/2025-06-30-gartner-survey-finds-forty-five-percent-of-organizations-with-high-artificial-intelligence-maturity-keep-artificial-intelligence-projects-operational-for-at-least-three-years) 。AWSが2025年に9か国3,739人のIT意思決定者を調べた結果では、60%の組織が最高AI責任者などの専任の役員を置いていました [ [ 208 ] ](https://press.aboutamazon.com/aws/2025/5/generative-ai-adoption-index) 。IDCの成熟度モデルは、専任のリーダーを持つCoEが全社のロードマップを作り統治が正式になる段階を「Repeatable」と定義しています [ [ 199 ] ](https://www.idc.com/resource-center/blog/ai-strategy-is-easier-to-define-than-to-deliver-idcs-benchmark-shows-the-gap) 。

日本の例では、日立製作所が2023年5月に「Generative AIセンター」を設け、グループ32万人の業務での利用を推進しながら、ノウハウを蓄積して顧客にも提供する循環を掲げました [ [ 233 ] ](https://www.hitachi.com/ja-jp/press/articles/2023/05/0515) 。行政では、デジタル庁が各府省庁にAI統括責任者を置く体制を示し、2026年度中に全府省庁約18万人の職員が生成AIを使える状態にする予定です [ [ 231 ] ](https://www.digital.go.jp/news/decb64eb-f26e-41cb-8d37-f3dd173108b8) 。

**O3：ハブ&スポーク**。推進組織が基盤と統治を担い、事業部が用途を担う型です。KDDIは2023年夏に推進組織を設け、本部長をオーナーとする「トップダウン」と、社員1万人に対話型サービスを配る「ボトムアップ」の2つの観点から進めました。推進組織と事業部の混成チームが営業準備の時間を約74%削減し、その知見を法人向けのサービスとして提供しています [ [ 242 ] ](https://biz.kddi.com/beconnected/feature/2024/240306) 。同社の担当者は、各部門のボトムアップだけでは活用が加速しないと述べています。

**O4：分散**。事業部が自走し、推進組織は標準と監査に退く型です。LINEヤフーは2025年7月に全従業員へ生成AIの活用を義務づけ、全部署に活用推進者を置きました [ [ 238 ] ](https://www.lycorp.co.jp/ja/news/release/018121) 。メルカリは全社を33の領域に分け、各領域にエンジニアとプロジェクト管理者と領域責任者を置いて、業務の流れをAI前提に組み替えています [ [ 240 ] ](https://engineering.mercari.com/blog/entry/20251225-mercari-ai-native-company) 。いずれも、推進組織が用途を決めるのではなく、各部署が自分の業務で決める形です。

**O5：製品組織**。AIが製品の一部になった型です。サイバーエージェントは2023年5月に独自の日本語モデルを広告の製品に組み込みました [ [ 239 ] ](https://www.cyberagent.co.jp/news/detail/id=29442) 。Sansanは2025年11月にAIエージェントの提供を始め、外部のAIから名刺や接点のデータを参照できる接続口を公開しました [ [ 550 ] ](https://jp.corp-sansan.com/news/2025/1121_01.html) 。マネーフォワードは2026年4月に、バックオフィスの業務を自律的に遂行する製品を発表しました [ [ 551 ] ](https://note.moneyforward.com/n/n46c98694e25c) 。これらの企業では、AIの運営は推進組織ではなく製品の開発組織の仕事です。

### 3. 日本の条件：IT人材はどこにいるか

運営モデルの選択肢は、社内にどれだけの技術者がいるかで決まります。日本では、この前提が他国と大きく異なります。

情報処理推進機構の日米比較によれば、情報処理・通信に携わる人材のうちIT企業に所属する割合は、日本が73.6%、米国が35.1%です [ [ 520 ] ](https://www.ipa.go.jp/archive/press/2022/press20230316-2.html) 。日本では、IT人材の約4分の1しか利用者側の企業にいません。経済産業省は2018年の報告で、ベンダー企業が既存システムの保守に人員を割かれ「人月商売の多重下請構造から脱却できない」と予想しました [ [ 507 ] ](https://www.meti.go.jp/policy/it_policy/dx/20180907_03.pdf) 。総務省の調査では、情報サービス業の開発部門で元請の企業が87.8%、一次下請の企業が56.2%で、多くの企業が元請と下請の両方を担っています [ [ 522 ] ](https://www.soumu.go.jp/johotsusintokei/whitepaper/ja/h29/html/nc261550.html) 。

この構造が運営モデルに与える影響は3つあります。

第一に、O2の推進組織を社内の人材だけで作れる企業が限られます。推進組織の中核は外部のSIか、ベンダーの支援に依存しやすくなります。NTTデータグループは生成AI関連の受注が2,000件を超え、実践的な人材を2027年度までに全社員約20万人へ広げると公表しています [ [ 243 ] ](https://www.nttdata.com/global/ja/news/release/2025/102900) 。富士通は2026年5月にAnthropicと戦略的な契約を結び、全社員10万人にClaudeを展開しつつ1,000人規模の技術者チームを置くと発表しました [ [ 470 ] ](https://global.fujitsu/ja-JP/pr/news/2026/05/27-01) 。供給側はこの構造に合わせて人材を増やしています。

第二に、O3からO4へ移るときに、事業部側における受け皿となる人材の不在が制約になります。推進組織が基盤を整えても、事業部に用途を設計できる人がいなければ、用途は推進組織に戻ってきます。

第三に、SIに任せた部分の知見は、社内に残りません。経済産業省は2024年に、日本では社内の利活用は進んだが、日常業務への組み込みと新サービスの創出と経営層の関与が停滞していると総括しました [ [ 226 ] ](https://www.meti.go.jp/press/2024/06/20240628006/20240628006.html) 。組み込みの設計を外部に任せる構造では、組み込みの段階で足踏みが起きます。

### 4. どの導入段階にどの運営モデルが合うか

運営モデルは、導入の深さに応じて変わります。次の表は著者による対応づけです。

| 導入段階 | 合う運営モデル | 理由 |
| --- | --- | --- |
| S1 触れる | (なし) | 組織の判断がまだない |
| S2 仕事に適用する | O1 SaaS利用 | 契約と規程で足りる |
| S3 仕事に組み込む | O2 集中 → O3 ハブ&スポーク | 業務の設計は事業部が、基盤と統治は推進組織が担う |
| S4 システムに組み込む | O3 ハブ&スポーク | 評価・監視・費用の標準は全社で、用途は事業部で |
| S5 商品に組み込む | O4 分散 → O5 製品組織 | 製品の責任は製品組織が負う |
| S6 顧客へ届ける | O5 製品組織 | 事業の指標がAIを含む |

対応の根拠は、推進組織の役割の変化にあります。S2では推進組織は要りません。S3で推進組織が生まれ、用途の発掘から統治までを担います。S4では用途が増え、推進組織が全部を担えなくなるため、基盤と統治だけを残して用途を事業部へ渡します。S5以降では、AIは製品の一部であり、製品の責任者が担います。

Gartnerの調査では、成熟度の高い組織の45%がAIの案件を3年以上本番で維持しているのに対し、低い組織では20%でした [ [ 186 ] ](https://www.gartner.com/en/newsroom/press-releases/2025-06-30-gartner-survey-finds-forty-five-percent-of-organizations-with-high-artificial-intelligence-maturity-keep-artificial-intelligence-projects-operational-for-at-least-three-years) 。本番で維持する責任を誰が負うかが、運営モデルの核心です。

### 5. 移行の兆候

運営モデルを次へ移すべき兆候は、観察できます。

O1からO2へ移す兆候は、利用規程だけでは答えられない問いが増えることです。どの業務から始めるか、社内文書をどう参照させるか、誤りの責任を誰が負うか。これらに答える人がいない状態のまま続けば、推進組織が要ります。

O2からO3へ移す兆候は、推進組織に用途の依頼が溜まることです。推進組織が全社の用途を順に処理する形は、用途の数が増えると詰まります。KDDIの例は、推進組織が基盤を担い事業部が用途を担う形で詰まりを解消したものです。

O3からO4へ移す兆候は、事業部が推進組織を待たずに用途を作り始めることです。これは第3節で述べた人材の制約が解けた証拠でもあります。推進組織は標準と監査に退きます。

O4からO5へ移す兆候は、AIの機能が顧客の購買理由になることです。社内の効率の道具が、製品の価値の一部に変わった時点で、運営は製品組織の仕事になります。

移行は後戻りもします。KPMGの調査では、AIエージェントを配備した組織の割合が2025年の第3四半期から第4四半期にかけて42%から26%へ下がりました [ [ 197 ] ](https://kpmg.com/us/en/media/news/q3-ai-pulse.html) 。分散した用途が統治の範囲を超えると、集中へ戻す判断もあり得ます。

### 経営層への含意

運営モデルの5つの型と導入段階との対応は、著者による整理です。McKinseyの3つの型とGartnerの中央集約の統計は、集中からハブ&スポーク、分散への推移を裏づけますが、企業ごとの最適な型を指定するものではありません。

経営層が本章から持ち帰るべき点は3つです。

第一に、推進組織は作って終わりではなく、役割を縮めていく組織です。最初は全部を担い、次に基盤と統治だけを担い、最後は標準と監査に退きます。縮める計画を最初から持っていないと、推進組織が用途の詰まりの原因になります。

第二に、日本では事業部側の受け皿が制約です。IT人材の約4分の3がベンダー側にいる構造では、推進組織を作ること以上に、事業部に用途を設計できる人を置くことが難しくなります。SIに任せる範囲を決めるときは、知見が社内に残る範囲を先に決めます。

第三に、移行の兆候は観察できます。規程で答えられない問いの増加、推進組織に溜まる依頼、事業部の自走、顧客の購買理由の変化です。兆候が現れたら型を変えます。兆候が現れていないのに型を変えると、受け皿のない移行になります。
