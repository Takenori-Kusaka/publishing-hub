### 序論：本章が扱う範囲

本章は、2017年から2020年までの4年間に、現在の生成AIの土台となった3つの技術が順に成立した経緯を整理します。3つとは、Transformer という計算の構造、事前学習と転移という学習の方式、そしてスケーリング則という性能の予測可能性です。

この4年間は、一般の利用者には見えない期間でした。製品はなく、論文と研究用のモデルだけがありました。しかし、2022年11月の ChatGPT 以降に起きたことは、すべてこの期間の成果の上に載っています。企業が今日導入を検討している製品の性能、価格、限界は、ここで決まった構造に由来します。

本章の本文は事実の記述に限ります。この時期の出来事が経営判断にどう関わるかは、章末の解釈の節で扱います。技術の細部に関心がない場合は、第7節の表と章末の解釈だけを読んでも、以後の章を読むうえで支障はありません。専門用語は、初出の箇所で短く定義し、詳しい定義は[用語集](glossary)に置いています。次の[転換点の章](02-chatgpt-moment-2022)では、この土台の上に製品が載り、普及が始まる2022年を扱います。

### 1. 2017年：Transformer という構造

2017年6月12日、Google の研究者らは論文「Attention Is All You Need」を公開しました。この論文が提案した Transformer は、文中の語と語の関係を「注意(attention)」という計算で一度に扱う構造です。それまで主流だった、語を1つずつ順に処理する再帰型の構造を置き換えました。論文は、英独翻訳の標準的な課題で BLEU 28.4 という当時の最高水準を報告しています [ [ 1 ] ](https://arxiv.org/abs/1706.03762) 。

この構造の意味は、翻訳の精度そのものより、計算の並列化にありました。語を順に処理する構造では、文が長くなるほど処理は直列に伸びます。Transformer は文全体を同時に扱うため、GPU のような並列計算機に向いています。後の節で述べる「規模を大きくすれば性能が上がる」という経験則は、この並列化が前提です。

### 2. 2018年：事前学習と転移という方式

2018年6月11日、OpenAI は後に GPT-1 と呼ばれるモデルを発表しました。大量の文章から「次の語を当てる」課題だけで事前に学習し、その後に少量の例で個別の課題へ適応させる方式です。発表時の報告では、12種類の言語理解の課題のうち9つで当時の最高性能を更新し、複数課題の総合指標 GLUE で 68.9 から 72.8 へ改善したとされています [ [ 2 ] ](https://openai.com/index/language-unsupervised/) 。

同年10月11日、Google は BERT を公開しました。GPT-1 が文を左から右へ読むのに対し、BERT は前後の両方向から読みます。GLUE のスコアを 80.5% に引き上げ、7.7 ポイントの改善を報告しました [ [ 3 ] ](https://arxiv.org/abs/1810.04805) 。

この2つのモデルが確立した方式は、現在まで変わっていません。課題ごとにモデルを設計するのではなく、1つの大きなモデルを汎用の目的で事前に学習しておき、用途に応じて適応させるという方式です。企業が今日「基盤モデル」と呼んでいるものは、この方式の延長にあります。

### 3. 2019年：規模の拡大と公開の制御

2019年2月14日、OpenAI は GPT-2 を発表しました。このとき OpenAI は、悪用の懸念を理由に最大のモデルを直ちには公開せず、小さい版から段階的に公開する方針を採りました。2019年5月に3億4,500万パラメータの版を公開し、その後に15億パラメータの版を公開しています [ [ 4 ] ](https://openai.com/index/better-language-models/) 。

この段階的公開は、技術の歴史としては小さな出来事です。しかし、開発元が「公開するか、誰に公開するか」を制御するという慣行は、この時点で始まりました。後の章で扱う閉鎖モデルとオープンウェイトのモデルの対立は、ここに起点があります。

### 4. 2020年：スケーリング則

2020年1月23日、OpenAI の Kaplan らは「Scaling Laws for Neural Language Models」を公開しました。この論文は、言語モデルの損失(予測の誤り)が、モデルの大きさ、学習データの量、投入する計算量のそれぞれに対して、べき乗の法則に従って下がることを示しました。この傾向は7桁以上の範囲にわたって観測されています [ [ 5 ] ](https://arxiv.org/abs/2001.08361) 。

この発見の意味は、性能が予測可能になったことです。それまでの機械学習では、モデルを大きくしても性能が上がるかは試してみなければ分かりませんでした。スケーリング則は、計算量をいくら投じればどの程度の損失に到達するかを、事前に見積もる根拠を与えました。

同年5月28日、OpenAI は1,750億パラメータの GPT-3 の論文を公開しました。論文は、追加の学習をせず、数個の例を示すだけ(few-shot)で多くの課題をこなせることを示しました [ [ 6 ] ](https://arxiv.org/abs/2005.14165) 。GPT-2 の15億パラメータから、約2年で100倍以上の規模です。

スケーリング則はその後、2022年3月29日に DeepMind の Hoffmann らによって修正されました。同じ計算量のもとでは、モデルの大きさだけでなく学習データの量も同じ比率で増やすべきだという結果です。この結論は400以上のモデルを学習して導かれました [ [ 10 ] ](https://arxiv.org/abs/2203.15556) 。この修正により、「大きければよい」ではなく「計算量に対して最適な配分がある」という理解が定着しました。

### 5. 言語の外側：画像生成の基礎

同じ時期に、画像生成の基礎も整いました。2021年12月20日に公開された潜在拡散モデルの論文は、画像を圧縮した空間でノイズを除去していく方式を示しました。この方式が、2022年8月22日に公開される Stable Diffusion の基礎となります [ [ 7 ] ](https://arxiv.org/abs/2112.10752) 。

本書は言語モデルを中心に扱いますが、企業の導入の現場では画像や音声の生成も同時に現れました。その起点が、言語モデルと同じ2017年から2021年の研究にあることを記しておきます。

### 6. 日本での準備

同じ方式は、日本語でも早い段階で再現されています。rinna は2021年4月7日に、日本語の GPT-2(中規模版)を公開しました。日本語の CC-100 と Wikipedia のデータを使い、V100 という GPU 8基を約30日使って学習したモデルです。ライセンスは MIT であり、商用利用を含めて自由に使えます [ [ 94 ] ](https://huggingface.co/rinna/japanese-gpt2-medium) 。

この時点の日本語モデルは、GPT-3 の1,750億パラメータと比べれば小さく、研究と開発者向けの公開にとどまっていました。しかし、事前学習と転移という方式が言語を問わず成り立つことは、この段階で確認されています。日本の技術史は[日本の技術史の章](09-japan-model-history)で、2023年以降の国産モデルの開発とともに扱います。

### 7. この4年間の構造

ここまでの出来事を、本書の以後の章で使う3つの部品として整理します。

| 部品 | 成立 | 内容 | 現在への影響 |
| --- | --- | --- | --- |
| 構造 | 2017年、Transformer | 文全体を同時に扱う並列化しやすい計算 | GPU と計算資源への需要の起点 |
| 方式 | 2018年、GPT-1 と BERT | 汎用の事前学習と、用途への転移 | 「基盤モデル」という製品形態 |
| 法則 | 2020年、スケーリング則 | 規模と性能の関係が予測できる | 投資の規模と競争の形を決めた |

3つの部品のうち、経営判断に最も関わるのは法則です。性能が計算量で予測できるなら、計算資源に投資できる者が性能で先行します。[計算資源と資本の章](08-compute-capital-energy)で扱う投資の規模は、この法則の帰結です。

### 本章の要点と解釈

本セクションは、著者による解釈です。前節までの事実記述とは区別して読んでください。

要点は3つです。第一に、生成AIの土台は2017年から2020年の4年間に、構造、方式、法則の順で成立しました。第二に、この期間に製品は存在せず、一般の利用者には見えていませんでした。第三に、スケーリング則によって性能が計算量から予測できるようになり、計算資源への投資が競争の中心になりました。

筆者は、この期間の最も重要な帰結は「予測可能性」にあると考えます。技術の進歩が運に左右されるなら、企業にとって様子見は合理的です。しかし性能が投資額から見積もれるなら、投資できる者が確実に先行します。2023年以降の投資の規模、[競争の構造化の章](03-competition-2023)で扱う参入の集中、そして価格の低下は、どれもこの予測可能性から説明できます。

経営層への含意は次のとおりです。現在の製品の性能差や価格差は、各社の工夫の差というより、投じた計算量の差として理解できます。したがって、特定の製品に長期の前提を置くのではなく、計算量の投入が続く限り性能は上がり続けるという前提で、乗り換え可能な導入の形を選ぶことが合理的です。この点は[運営モデルの進化の章](33-operating-model-evolution)で具体化します。
