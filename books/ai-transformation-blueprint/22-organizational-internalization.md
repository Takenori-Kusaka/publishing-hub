### 序論：本章が扱う範囲

[汎用技術と生産性Jカーブの章](21-gpt-and-j-curve)は、技術の効果が出るまでに補完的な投資が要ることを示しました。本章は、その投資の中身を扱います。技術が組織の内部でどこまで変わるか、言い換えれば「内部化の深さ」を説明する理論です。

取り上げるのは4つの系統です。第一に、情報技術の導入が段階を踏むというNolanの段階仮説と、その系譜にある能力成熟度モデル(CMM)です。第二に、技術は仕事を置き換えるだけでなく可視化するというZuboffの二重性と、同じ技術が組織によって別の結果を生むというOrlikowskiとBarleyの研究です。第三に、AIの導入を「点」「応用」「システム」の3水準で分けたAgrawal、Gans、Goldfarbの枠組みです。第四に、既存の企業が新しい技術を取り込むための組織能力を扱うTeece、O'ReillyとTushman、Christensenの理論です。

各理論について、原典の主張、生成AIの事実への当てはめ、当てはまらない点の順に記述します。理論の選択と当てはめは著者の判断です。本章の整理は、[生成AIの導入段階の章](30-genai-adoption-stages)で定義する導入の深さS1〜S6の理論的な根拠になります。

### 1. Nolanの段階仮説 ―― 拡張の後に統制が来る

経営判断にとっての意味は、「現場が勝手に使い始めて統制が効かない」という状態が50年前から観測されてきた通過点であり、次に来るのは統制の段階だということです。

Richard Nolanは1973年に、企業の電子データ処理の予算がS字曲線を描くことから、着手、拡張、統制、統合の4段階を提案しました [ [ 272 ] ](https://doi.org/10.1145/362280.362284) 。1979年には、これをデータ管理と成熟を加えた6段階に拡張しました [ [ 219 ] ](https://hbr.org/1979/03/managing-the-crises-in-data-processing) 。各段階は、アプリケーションの群、データ処理の組織、計画と統制、利用者の意識という4つの成長過程で特徴づけられます。拡張の段階では利用が組織の各所に広がって費用が急増し、統制の段階でその危機に対処するため管理が導入されます。統合を経て、重心は技術の管理からデータという資源の管理へ移ります。

生成AIの事実に当てはめると、2023年から2025年の企業の経過は、着手から拡張、そして統制への移行として読めます。[普及の理論の章](20-diffusion-theory)で参照したとおり、2024年の時点で職場のAI利用者の78%が会社の提供でないツールを持ち込んでいました [ [ 296 ] ](https://www.microsoft.com/en-us/worklab/work-trend-index/ai-at-work-is-here-now-comes-the-hard-part) 。これは拡張の段階の典型です。その後、[企業の利用の章](12-enterprise-adoption)で示したとおり、ガイドラインの策定、全社契約、利用の義務化という統制と統合の動きが続きました。Nolanが最後に置いた「データ管理」は、[日本の条件の章](19-japan-conditions)で示した「社内データを参照させる基盤の整備が遅れている」という課題に対応します。

当てはまらない点は、Nolanの段階が予算の推移という単一の指標に基づくことです。経験的な根拠には批判が多く、段階を一方向に進むという仮定も検証されていません。本書は、段階の順序ではなく、各段階で組織に何が要るかという整理に限って援用します。

### 2. 能力成熟度モデル ―― 「成熟度」という語の起源

経営判断にとっての意味は、各社が示す「AI成熟度」の多くが1993年のソフトウェア開発の評価枠組みの型を継いでおり、型の由来を知れば各社の枠組みを比較できる、ということです。

Paulkらは1993年に、ソフトウェア開発組織の成熟度を5段階で評価する能力成熟度モデル(CMM)を定義しました [ [ 273 ] ](https://www.sei.cmu.edu/library/capability-maturity-model-for-software-version-11/) 。5段階は、初期、反復可能、定義済み、管理された、最適化です。各段階には、その段階で確立されているべき主要なプロセス領域が割り当てられます。1986年にアメリカ国防総省の請負業者の評価のために始まった枠組みで、1987年の質問票がモデルそのものと誤解された反省から、1993年にモデルを明示しました。

生成AIの事実に当てはめると、[現在地を測る道具の章](23-maturity-models)で整理するとおり、2021年の系統的レビューは、AIの成熟度モデルの研究で「5段階の連続的な表現」が主流であることを確認しています [ [ 213 ] ](https://pmc.ncbi.nlm.nih.gov/articles/PMC8409328) 。IDCの成熟度モデルは散発的、機会的、反復可能、管理された、最適化の5段階で、CMMの語をそのまま継いでいます [ [ 199 ] ](https://www.idc.com/resource-center/blog/ai-strategy-is-easier-to-define-than-to-deliver-idcs-benchmark-shows-the-gap) 。

当てはまらない点は、CMMが「プロセスの規律」を測る枠組みであることです。CMMの最適化の段階は、プロセスの定量的な管理と継続的な改善が行われている状態を指し、技術が事業に与える効果を測りません。AIの成熟度モデルがCMMの型を継ぐとき、同じ限界を継ぎます。規律の高い組織が、事業の価値を出しているとは限りません。

### 3. Zuboffの二重性 ―― 置き換えるか、可視化するか

経営判断にとっての意味は、同じ技術を「人を減らす」ために使うか「仕事を見えるようにして学ぶ」ために使うかで、組織の到達点が分かれる、ということです。

Shoshana Zuboffは1988年の『In the Age of the Smart Machine』で、製紙工場、銀行、保険会社など8つの組織の観察から、情報技術が2つの能力を持つと論じました [ [ 265 ] ](https://openlibrary.org/works/OL4988685W) 。自動化(automate)は、人の作業を機械に置き換えます。情報化(informate)は、作業の過程を記号化して可視化し、新しい知識と学習の対象にします。情報化を活かすには、管理職が情報の独占を手放し、現場の知的な技能を育てる権限と技能の再配分が要ります。これを拒んで自動化だけを追うと、技術の潜在力が失われ、監視と統制が強まります。

生成AIの事実に当てはめると、Anthropicが自社の利用記録を分析した報告が、この二重性を測っています。2025年2月の初回の報告では、利用の57%が人の作業を補う「拡張」で、43%が作業を代行する「自動化」でした [ [ 115 ] ](https://www.anthropic.com/research/the-anthropic-economic-index) 。2025年9月の報告では、企業向けのAPI経由の利用の77%が自動化でした [ [ 116 ] ](https://www.anthropic.com/research/anthropic-economic-index-september-2025-report) 。対話による個人の利用は拡張に、システムに組み込んだ利用は自動化に偏ります。Zuboffの言葉で言えば、組織に深く組み込むほど自動化に寄り、情報化の機会を設計しなければ失われます。

さらに、[生産性の実証の章](13-productivity-evidence)で参照した顧客サポートの研究は、情報化の具体例です。生成AIの支援で経験の浅い担当者の解決件数が最も改善したのは、熟練者の暗黙知がAIを通じて新人に伝わったためと解釈されています [ [ 288 ] ](https://doi.org/10.1093/qje/qjae044) 。作業の過程が記号化され、学習の対象になった例です。

当てはまらない点は、Zuboffの観察対象が1980年代の情報システムであることです。当時の情報化は、作業の記録を人が読んで学ぶことを前提としました。生成AIでは、記録を読んで学ぶ主体がAIそのものになりえます。情報化の受益者が人かAIかという問いは、Zuboffの枠組みの外にあります。

### 4. OrlikowskiとBarley ―― 同じ技術が別の組織を作る

経営判断にとっての意味は、他社の導入事例をそのまま真似ても同じ結果にはならず、結果を決めるのは技術ではなく「技術をめぐって人々が何をするか」だ、ということです。

Stephen Barleyは1986年に、同じCTスキャナを導入した2つの病院の放射線科を1年間観察し、同一の技術が異なる組織構造を生んだことを示しました [ [ 267 ] ](https://doi.org/10.2307/2392767) 。技術は構造を決定せず、既存の役割関係を再交渉する「機会」を作ります。導入後の日々の相互作用のパターンが繰り返されて制度化され、組織ごとの違いが生まれます。

Wanda Orlikowskiは1992年に、技術は人の行為の産物であると同時に、人の行為を媒介する構造でもあるという「二重性」を提示しました [ [ 266 ] ](https://doi.org/10.1287/orsc.3.3.398) 。技術は設計時の意図と使用時の解釈の両方で形成され、設計と使用は時間と空間で分離しています。技術が組織に与える影響は、技術の性質だけでなく、使用者がそれをどう使い、組織の制度的な特性とどう相互作用するかで決まります。TristとBamforthは1951年に、イギリスの炭鉱で機械化が生産性の向上に結びつかなかった事例から、技術システムと社会システムは独立に最適化できず、同時に設計する必要があると結論していました [ [ 269 ] ](https://doi.org/10.1177/001872675100400101) 。

生成AIの事実に当てはめると、同じ製品を導入した組織の間の差が、これらの理論の予測どおりに大きく出ています。BCGの2025年の調査では、AIから規模のある価値を得ている企業は5%、スケール中が35%、60%はほとんど価値を得ていませんでした [ [ 180 ] ](https://www.bcg.com/publications/2025/are-you-generating-value-from-ai-the-widening-gap) 。[市場の地図の章](18-market-map)で示したとおり、企業が使う基盤モデルは数社に集中しています。使う基盤モデルが数社に集中する一方で結果は5%と60%に分かれており、差を生む要因は技術の外側にあると、これらの理論は予測します。

当てはまらない点は、これらの理論が「差が生まれる」ことを説明し、「どうすれば望む側に入れるか」を直接には示さないことです。Barleyの観察は、結果を事後に説明します。処方は、次節以降の枠組みと[文化の形成の章](36-culture-formation)で扱います。

### 5. 点・応用・システム ―― AI導入の3つの水準

経営判断にとっての意味は、既存の判断を1つずつAIに置き換える「点の解決」は効果が小さく、判断の相互依存を組み直す「システムの解決」まで進まなければ汎用技術の効果は出ないということです。

Agrawal、Gans、Goldfarbは2018年の『Prediction Machines』で、AIの経済的な本質を「予測のコストの低下」として捉えました [ [ 280 ] ](https://openlibrary.org/works/OL19747345W) 。予測が安くなると、予測の補完財である判断とデータの価値が上がり、代替財である人の予測の価値が下がります。2022年の『Power and Prediction』は、2018年の本が想定したより普及が遅れた理由を、AIの導入が「点の解決策」に留まり「システムの解決策」に至っていないからだと論じました [ [ 281 ] ](https://store.hbr.org/product/power-and-prediction-the-disruptive-economics-of-artificial-intelligence/10580) 。点の解決策は、既存の意思決定をAIで置き換えます。応用の解決策は、道具や機械の単位で再設計します。システムの解決策は、意思決定の相互依存を組み直します。電化が工場の配置換えを要したのと同じで、現在は技術の実証と本格的な普及の間の「狭間の時代」にある、というのが同書の主張です。

同じ著者らの2021年の論文は、AIの予測が意思決定のばらつきを増やし、相互依存するタスクで問題を起こすため、モジュール化か調整の仕組みが要ると定式化しました [ [ 1806 ] ](https://www.nber.org/papers/w28811) 。

生成AIの事実に当てはめると、本書の導入の深さS1〜S6は、この3水準の細分化です。S1(触れる)とS2(仕事に適用する)は点の解決策、S3(仕事に組み込む)とS4(システムに組み込む)は応用の解決策、S5(商品に組み込む)とS6(顧客へ届ける)はシステムの解決策に対応します。[生成AIの導入段階の章](30-genai-adoption-stages)で示す各社の枠組みの多くが3段で、本書の1〜2、3〜4、5〜6がそれぞれ1段にまとまるのは、この対応によります。

Microsoftの2025年の調査が示した3つの相も、同じ構造です。第1相は全員がAIの助手を持って同じ仕事を速くする段階です。第2相ではエージェントが人の指示で特定のタスクを担い、第3相では人の指揮のもとでエージェントが運転します [ [ 204 ] ](https://www.microsoft.com/en-us/worklab/work-trend-index/2025-the-year-the-frontier-firm-is-born) 。第1相が点、第2相が応用、第3相がシステムに対応します。

当てはまらない点は、同書が「予測」をAIの本質とすることです。生成AIの出力は予測の形式を取りますが、利用者にとっては文章、コード、画像という成果物です。予測と判断の分離という同書の処方は、成果物を生成する場面にそのまま当てはまりません。成果物の妥当性を誰が判断するかという問いが、別に残ります。この問いは[AIエージェントの導入の章](31-agent-adoption-stages)で、自律性の水準として扱います。

### 6. 既存企業の組織能力 ―― 両利き、ダイナミック・ケイパビリティ、破壊的技術

経営判断にとっての意味は、既存の事業で生成AIを使って効率を上げることと、生成AIで新しい事業を作ることは、別の組織と別の指標を要するということです。

Teece、Pisano、Shuenは1997年に、急速に変化する環境で競争優位を得る源泉を「内外の能力を統合・構築・再構成する企業の能力」と定義し、ダイナミック・ケイパビリティと名づけました [ [ 274 ] ](https://doi.org/10.1002/%28SICI%291097-0266%28199708%2918:7%3C509::AID-SMJ882%3E3.0.CO;2-Z) 。企業の能力は、調整と学習と再構成のプロセス、技術と補完資産のポジション、過去の投資による経路の3つで決まります。

O'ReillyとTushmanは2004年に、既存事業の深化と新規事業の探索を同時に行う組織を「両利き」と呼び、35の事例から、探索部門を構造的に分離しつつ上級経営陣で統合する型の成功率が最も高いと報告しました [ [ 275 ] ](https://hbr.org/2004/04/the-ambidextrous-organization) 。Christensenは1997年に、優良企業が失敗するのは主要な顧客の声を聞き利益率の高い市場に投資するという優良な経営の帰結であり、当初は性能と利益率の低い「破壊的技術」に対しては独立した組織で対処すべきだと論じました [ [ 276 ] ](https://openlibrary.org/works/OL1999873W) 。HendersonとClarkは1990年に、部品は変わらないが結合の方法が変わる「アーキテクチャ革新」に既存企業の対応が遅れることを示しました [ [ 277 ] ](https://doi.org/10.2307/2393549) 。

生成AIの事実に当てはめると、[3つの現在地の章](32-three-positions)で事業フェーズを導入フェーズと別の軸に置く根拠が、これらの理論にあります。成熟した事業で効率を上げる導入(S2〜S4)と、新しい事業を作る導入(S5〜S6)は、両利きの深化と探索に対応し、同じ指標で評価すると探索の芽を摘みます。HendersonとClarkの枠組みでは、生成AIは既存の業務という部品を変えずに結合の方法を変えるため、既存企業が変化を過小評価しやすい型の革新です。

当てはまらない点は、これらの理論が生成AI以前の技術を対象に構築されたことです。生成AIが破壊的技術かどうかは、Christensenの定義(当初は性能が低く小さな市場から始まる)に照らすと判定が難しく、[普及の理論の章](20-diffusion-theory)で示したとおり、当初から大きな市場で高い性能を示しました。破壊的技術の型には当てはまらない可能性があります。

#### 図の読み方

この図は、上から下へ3つの帯を積んだものです。各帯はAgrawal、Gans、Goldfarbの3水準で、上が点の解決策、中が応用の解決策、下がシステムの解決策です。

各帯の右側に、本書の導入の深さS1〜S6のうち対応する2段階を置いています。点の解決策にはS1とS2、応用の解決策にはS3とS4、システムの解決策にはS5とS6です。

帯の左側の語は、その水準で何を組み替えるかです。点の水準では個人の作業、応用の水準では部門の業務手順とシステム、システムの水準では事業の意思決定の相互依存が組み替わります。下の帯ほど補完的な投資が大きく、Zuboffの言う情報化の設計が要ります。導入フェーズS1〜S6の定義は[生成AIの導入段階の章](30-genai-adoption-stages)に記しています。

### 本章の位置づけ

本章で取り上げた理論の選択と、生成AIの事実への当てはめは、著者の判断です。

組織の内部化の理論が本書の推論に与える結論は、次の4つです。第一に、現場の自発的な利用の拡張とその後の統制は情報技術の導入で繰り返されてきた順序であり、統制の次にはデータの管理が来ます。第二に、同じ技術を導入しても結果は組織ごとに分かれ、差を生むのは技術ではなく、技術をめぐる人々の行動と制度です。第三に、AIの導入には点・応用・システムの3水準があり、効果の大きさは水準に依存します。第四に、既存の事業の効率化と新しい事業の創出は、別の組織能力と別の指標を要します。

これらの結論は、[生成AIの導入段階の章](30-genai-adoption-stages)で導入の深さS1〜S6を定義し、[運営モデルの進化の章](33-operating-model-evolution)で統制の段階の組織形態を論じる根拠になります。次の章は、内部化の深さを測る道具である成熟度モデルの系譜を扱います。
