### 序論：本章が扱う範囲

本章は、本書全体を1枚の図に圧縮し、どの章がどこに対応するかを示します。経営層が本書を会議で使うときに、全体の構造を10分で把握できることを目的とします。

本章には新しい事実の記述はほとんどありません。各章で根拠とともに述べる内容を、構造として先に見せるだけです。数値と出典は各章にあります。

### 1. 砂時計と層

本書の構造は、砂時計と、その右に並ぶ層の2つからできています。

砂時計は社会全体の時間軸です。上半分が過去（第Ⅰ部）、くびれが現在（第Ⅱ部）、下半分が未来（第Ⅳ部）です。第Ⅲ部の理論は、砂時計を読むための眼鏡に相当します。

層は、1社の中の時間軸です。導入の深さ（S1〜S6）、AIエージェントの自律性（A0〜A4）、文化の段階（C1〜C5）、運営モデル（O1〜O5）の4つの軸を、第Ⅴ部で定義します。自社が動かせるのはこの4つです。社会の系譜と未来は、各社にとって外部環境です。自社が動かせるのは層のほうだけです。

#### 図の読み方

左の砂時計は上から下へ読みます。上の「過去：系譜」は第1章から第10章、くびれの「今」は第11章から第19章、下の「未来：3つの道筋」は第25章から第29章に対応します。砂時計の下に置いた「理論で読む」は第20章から第24章で、砂時計全体を読む方法を与えます。

右の層は上から下へ読みます。「導入の深さS1〜S6」は第30章で定義し、図では自律性（A0〜A4、第31章）を導入の深さに含めて描きました。「文化C1〜C5」は第32章で定義し、第36章で詳述します。最下段の「経営層が決める」だけを丹（朱色）で示しました。本書の図では、丹は人が判断する場所にだけ使います。前提に置く道筋と次の一手は第35章と第37章、会議資料の1枚と90日計画は第38章です。

砂時計のくびれから右の層へ伸びる点線は、社会の現在地が各社の現在地の前提になることを示します。図の下の添え書きのとおり、社会の系譜と未来は外部環境であり、自社が動かせるのは右の層だけです。

### 2. 第Ⅰ部〜第Ⅳ部：社会の時間軸

第Ⅰ部は、2017年のTransformer論文から2026年10月までの系譜を10章で追います。技術の節目だけでなく、普及の速度、能力の計測、計算資源と資本、日本の技術史、そして電化や計算機といった先例の普及曲線を含めます。先例を含めるのは、生成AIの普及の速さを測る物差しが必要だからです。たとえばアメリカの労働者のうち、仕事で生成AIを使ったことがある人の割合は2024年時点で27%であり、これはIBM PCの発売3年後にあたる1984年に仕事でPCを使っていた25%と同程度だと報告されています [ [ 108 ] ](https://www.nber.org/system/files/working_papers/w32966/w32966.pdf) 。仕事での利用はPC発売3年後と同程度で、人口への普及は先例より速い、というのが本書の読みです。

第Ⅱ部は、現在地を9章で確かめます。個人と企業の利用率は調査によって大きく開くため、定義差を解くことを1章分（第12章）に充てます。生産性の実証（第13章）と雇用の実証（第14章）は、ランダム化比較試験と労働統計に限って整理します。投資対効果（第15章）、AIエージェント（第16章）、統治と規制（第17章）、市場の地図（第18章）、日本の条件（第19章）が続きます。

第Ⅲ部は、第Ⅰ・Ⅱ部の事実を読む理論を5章で整理します。普及の理論（第20章）、汎用技術と生産性Jカーブ（第21章）、組織の内部化（第22章）、成熟度モデル（第23章）、予測の方法（第24章）です。

第Ⅳ部は、言説の分類（第25章）から始め、3つの道筋（第26〜28章）を2027年・2029年・2031年の像として描き、比較と早期警戒指標（第29章）で締めます。

### 3. 第Ⅴ部：自社の時間軸

第Ⅴ部は、各社が自社の現在地を特定し、次の一手を選ぶための9章です。本書の枠組みを先に表で示します。定義と根拠は各章にあります。

**導入の深さS1〜S6（第30章）**

| 段階 | 名前 | 何が起きているか |
| --- | --- | --- |
| S1 | 触れる | 個人が試用する。業務の成果物には使わない |
| S2 | 仕事に適用する | 個人が自分の業務で使う。成果物は人が確認して出す |
| S3 | 仕事に組み込む | 部門の手順に組み込む。プロンプトや社内文書検索を共有する |
| S4 | システムに組み込む | APIで自社システムと業務の流れに統合する。評価・監視・費用を管理する |
| S5 | 商品に組み込む | 自社の製品やサービスの機能として顧客に提供する |
| S6 | 顧客へ届ける | 顧客接点でAIが自律的に価値を届ける。事業モデルが変わる |

**AIエージェントの自律性A0〜A4（第31章）**

| 段階 | 名前 | 定義 |
| --- | --- | --- |
| A0 | 助言 | エージェントは情報を集め、分析し、答える。何も実行しない |
| A1 | 提案 | 実行の案(下書き、手順、変更差分)を作る。実行は人が行う |
| A2 | 承認つき実行 | 実行の直前に人の承認を求め、承認後に実行する |
| A3 | 範囲内の自律実行 | 定めた範囲(権限、金額、対象)の中で自律的に実行し、事後に人が監査する |
| A4 | 協調 | 複数のエージェントが分業し、人は目標を指示する。個々の行動は監督しない |

**文化の段階C1〜C5（第32章・第36章）**

| 段階 | 名前 | 定義 |
| --- | --- | --- |
| C1 | 禁止・無関心 | 組織として生成AIを禁じているか、方針がない |
| C2 | 個人の試行 | 従業員が個人の判断で使っている。組織は黙認している |
| C3 | 公認の試行 | 利用規程、学ぶ場(研修か公認の試行の場)、推進者の3つがそろった状態 |
| C4 | 測って運用 | 効果と費用と誤りを数値で追い、業務ごとに改善している |
| C5 | AI・データネイティブ | 全員が作り手で、学習と改善が制度として続いている |

**運営モデルO1〜O5（第33章）**

| 型 | 名前 | 誰が決めるか |
| --- | --- | --- |
| O1 | SaaS利用 | IT部門が契約し、利用者が各自で使う |
| O2 | 集中 | 専任の推進組織が用途と基盤と統治を一手に担う |
| O3 | ハブ&スポーク | 推進組織が基盤と統治を担い、事業部が用途を担う |
| O4 | 分散 | 事業部が自走し、推進組織は標準と監査を担う |
| O5 | 製品組織 | AIが事業の一部になり、製品組織が担う |

従業員が数百人未満の会社では、SaaS利用（O1）が通常の形です。

**3つの道筋と手の種類（第35章）**

道筋A「加速」、道筋B「漸進」、道筋C「調整」のそれぞれについて、どの道筋でも後悔しない手、将来の選択権を買う手、1つの道筋に賭ける手を分けて示します。

### 4. 読む順序

本書は順に読むことを前提に書いていますが、経営会議の準備として使う場合は、次の順序を提案します。

第一に、本章と第12章（企業の利用）と第15章（投資対効果と失敗率）を読み、現在地の相場観を持ちます。第二に、第29章（3つの道筋の比較）を読み、自社がどの道筋を前提にするかを仮置きします。第三に、第30章から第32章で自社の段階を特定し、第35章と第37章で次の一手を決め、第38章で会議資料の1枚と90日計画に落とします。第四に、必要に応じて第Ⅰ部と第Ⅲ部に戻り、根拠を確かめます。

### 本章の位置づけ

本章は目次の代わりです。本書の枠組み（S1〜S6、A0〜A4、C1〜C5、運営モデルO1〜O5、3つの道筋）は著者の整理であり、各社や各機関が公表している段階論との対応は第30章で明示します。枠組みは判断の材料を並べるための座標であって、座標の上のどこに自社を置くかは読者の判断です。
