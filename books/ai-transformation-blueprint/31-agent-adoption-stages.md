### 序論：本章が扱う範囲

本章は、AIエージェントが企業にどう導入されていくかを、2つの軸で整理します。第一の軸は自律性で、エージェントが人の関与なしにどこまで実行するかをA0からA4の5段階で表します。第二の軸は業務範囲で、エージェントが働く場所を個人、チーム、部門横断、顧客接点の4つに分けます。

この枠組みは著者の整理です。段階の名前と境界は本書が定めたもので、各社の枠組みを対応づけた部分は「著者による対応づけ」として明記します。出典として参照するのは、[AIエージェントの現在地の章](16-agents-today)で記録した定義と実測、[統治と規制の章](17-governance-regulation)で記録した承認とIDの設計、そして各社が公表した導入の実例です。

[生成AIの導入段階の章](30-genai-adoption-stages)が定義した導入の深さS1からS6との関係も扱います。生成AIの段階論をそのままエージェントに当てはめることはできませんが、無関係でもありません。本章の章末は、経営層への含意です。

### 1. なぜ生成AIの段階論だけでは足りないか

生成AIの導入は、[生成AIの導入段階の章](30-genai-adoption-stages)で示したとおり、S1「触れる」からS6「顧客へ届ける」までの深さで整理できます。この段階論は「誰が、どの仕事に使うか」を軸にしています。

エージェントには、もう1つの軸が要ります。「人がどこまで関与するか」です。同じS3「仕事に組み込む」段階でも、2つの場合があります。エージェントが下書きを提案して人が送る場合と、エージェントが送信まで実行して人が後から確認する場合です。両者では、必要な統治も失敗したときの影響も違います。

この違いは、事業者の製品設計にも現れています。OpenAIのdotsは、いつ自律的に動き、いつ承認を求めるかの規則を組み込み、利用者が行動ごとに許可、承認必須、遮断を設定できます [ [ 674 ] ](https://openai.com/index/introducing-dots) 。AnthropicのClaude Duetは、メッセージの送信、支払い、署名、削除の前には承認を待ち、証券取引と口座間送金は承認があっても行いません [ [ 675 ] ](https://claude.com/resources/articles/claude-duet) 。どちらも、自律性を「行動の種類ごとに」決める設計です。

Feng、McDonald、Zhangは、自律性は能力とは独立に設計できる性質だと論じました [ [ 572 ] ](https://knightcolumbia.org/content/levels-of-autonomy-for-ai-agents-1) 。能力が高いモデルを低い自律性で使うことも、その逆もできます。本章の第一の軸は、この「設計できる性質」を段階にしたものです。

### 2. 自律性の5段階 A0〜A4(著者の整理)

本書は、エージェントの自律性を次の5段階で表します。

| 段階 | 名前 | 定義 | 人の役割 | 失敗したときに起きること |
| --- | --- | --- | --- | --- |
| A0 | 助言 | エージェントは情報を集め、分析し、答える。何も実行しない | 読んで判断し、実行する | 誤った助言を人が採用する |
| A1 | 提案 | 実行の案(下書き、手順、変更差分)を作る。実行は人が行う | 案を確認して実行する | 誤った案を人が実行する |
| A2 | 承認つき実行 | 実行の直前に人の承認を求め、承認後に実行する | 1件ごとに承認する | 承認の形骸化。承認した人の責任 |
| A3 | 範囲内の自律実行 | 定めた範囲(権限、金額、対象)の中で自律的に実行し、事後に人が監査する | 範囲を定め、記録を監査する | 範囲の定義漏れ。発見が事後になる |
| A4 | 協調 | 複数のエージェントが分業し、人は目標を指示する。個々の行動は監督しない | 目標と制約を与え、結果を評価する | 分業の中で意図しない行動が連鎖する |

この5段階は、既存の枠組みと次のように対応します(著者による対応づけ)。Feng らの5段階では、operatorがA0からA1、collaboratorがA1、consultantがA2にあたります。approverがA2からA3、observerがA3からA4にあたります [ [ 572 ] ](https://knightcolumbia.org/content/levels-of-autonomy-for-ai-agents-1) 。Cloud Security Allianceの自動運転になぞらえた6段階では、Level 0がA0、Level 5(自ら目標を設定)は本書のA4の先にあります [ [ 573 ] ](https://cloudsecurityalliance.org/blog/2026/01/28/levels-of-autonomy) 。Anthropicの区別では、workflowはA1からA2に、agentはA3以降に対応することが多いです。ただし同社の区別は「経路を誰が決めるか」の軸であり、本書の「人が関与するか」の軸とは異なります [ [ 566 ] ](https://www.anthropic.com/engineering/building-effective-agents) 。

A2とA3の境界は、承認が「事前」か「事後」かです。この境界が最も重要だと筆者は考えます。EU AI Actの第14条が高リスクAIに求める「停止ボタンで介入し中断できること」は、A3の運用に必要な条件です [ [ 648 ] ](https://artificialintelligenceact.eu/article/14/) 。

### 3. 業務範囲の4段階と、2軸の交差

第二の軸は、エージェントが働く場所です。

| 範囲 | 定義 | 典型 |
| --- | --- | --- |
| 個人 | 1人の業務の中で使う。他者に影響する実行はしない | 調査、下書き、自分のコードの修正 |
| チーム | チームの共有資源(リポジトリ、文書、チケット)に対して実行する | 修正の提案、文書の更新、チケットの振り分け |
| 部門横断 | 複数の部門にまたがる業務手順を実行する | 申請から承認までの処理、調達、経費 |
| 顧客接点 | 顧客との対話や取引を実行する | 問い合わせ対応、注文、返金 |

2つの軸を交差させると、20の組み合わせができます。すべての組み合わせを同時に進める企業はありません。公表された導入の実例は、おおむね「個人×A1」から始まり、「チーム×A2」を経て、「部門横断×A3」か「顧客接点×A2」へ進んでいます。

**個人×A1**。LINEヤフーは2025年7月に全従業員約1万1,000人の生成AI利用を義務化し、調査、資料作成、会議から着手しました [ [ 238 ] ](https://www.lycorp.co.jp/ja/news/release/018121) 。この段階のエージェントは、個人の仕事の案を作るものです。

**チーム×A2**。コーディングエージェントが典型です。Claude Codeは、作業ディレクトリ内の読み取りは承認なしで行い、コマンドの実行とファイルの変更は実行前に承認を求めます [ [ 666 ] ](https://code.claude.com/docs/en/permissions) 。承認を省いた場合に何が起きるかは、2025年7月のReplitの本番データベース削除 [ [ 626 ] ](https://www.theregister.com/2025/07/22/replit_saastr_response/) と、2026年4月のPocketOSの事故 [ [ 638 ] ](https://www.euronews.com/2026/04/28/an-ai-agent-deleted-a-companys-entire-database-in-9-seconds-then-wrote-an-apology) が示しています。

**部門横断×A3**。パナソニック コネクトは、2025年度に社内AIアシスタントで総労働時間の3.4%にあたる78万8,000時間を削減し、2030年に10%の削減を目標として、業務手順へのエージェントの組み込みを進めています [ [ 537 ] ](https://news.panasonic.com/jp/press/jn260729-1) 。富士通は2026年2月に、要件定義から設計、実装、結合テストまでを複数のエージェントが協調して実行する開発基盤を運用開始し、2026年度中に67業種のソフトウェア改修に適用するとしています [ [ 544 ] ](https://global.fujitsu/ja-JP/pr/news/2026/02/17-01) 。この例は、部門横断でA3からA4に近い構成です。

**顧客接点×A2〜A3**。freeeは2026年3月に、従業員の質問にエージェントが自動応答するAIヘルプデスクを提供開始しました [ [ 552 ] ](https://corp.freee.co.jp/news) 。マネーフォワードは、問い合わせに回答するだけでなくアカウント発行などの作業まで実行するヘルプデスクを2026年5月から提供予定と発表しています [ [ 553 ] ](https://prtimes.jp/main/html/rd/p/000001612.000008962.html) 。サイバーエージェントは2026年4月に、広告の入札と配信設定を24時間自動で最適化するエージェントを顧客向けに提供開始しました [ [ 541 ] ](https://www.cyberagent.co.jp/news/detail/id=33180) 。これらは、顧客接点でA3に踏み込んだ例です。

**顧客接点で起きた失敗**。Air Canadaは、チャットボットの誤った案内について過失による不実表示の責任を問われました [ [ 627 ] ](https://en.wikipedia.org/wiki/Moffatt_v._Air_Canada) 。Klarnaは、AIで顧客対応の3分の2を処理したと発表した後、費用削減が行き過ぎたとして人の採用に戻ると報じられました [ [ 630 ] ](https://www.bloomberg.com/news/articles/2025-05-08/klarna-turns-from-ai-to-real-person-customer-service) 。顧客接点は、失敗の影響が社外に及ぶ範囲です。

### 4. 生成AIの段階S1〜S6 との関係

エージェントは、生成AIの導入段階のどこで意味を持つのでしょうか。本書の整理では、次のとおりです。

S1「触れる」とS2「仕事に適用する」の段階では、エージェントは個人×A0からA1の形でしか現れません。個人が会社契約のSaaSで下書きを作る、というものです。Anthropicの経済指標によれば、対話での利用は人を補う「拡張」が多く、API経由の利用は77%が「自動化」の型でした [ [ 116 ] ](https://www.anthropic.com/research/anthropic-economic-index-september-2025-report) 。対話で使う段階と、システムから呼ぶ段階とで、利用の型が変わります。

S3「仕事に組み込む」で、エージェントはチーム×A2として意味を持ち始めます。部門の手順に組み込むには、共有資源への実行と、その承認の仕組みが要ります。

S4「システムに組み込む」は、エージェントがA3に進む前提です。範囲内の自律実行には、エージェントのID、権限の分離、実行の記録、事後の監査が必要で、これらはシステムとして整えるものです。Microsoftは2025年5月に、エージェントに人とは別のIDを自動で付与するEntra Agent IDを発表し [ [ 664 ] ](https://www.microsoft.com/en-us/security/blog/2025/05/19/microsoft-extends-zero-trust-to-secure-the-agentic-workforce/) 、2025年11月には登録、アクセス制御、可視化、相互運用、セキュリティの5機能を持つAgent 365を発表しました [ [ 584 ] ](https://www.microsoft.com/en-us/microsoft-copilot/blog/copilot-studio/unlocking-autonomous-agent-capabilities-with-microsoft-copilot-studio/) 。AWSのAgentCoreも、実行環境、記憶、ID、ゲートウェイ、観測を部品として提供しています [ [ 588 ] ](https://aws.amazon.com/blogs/aws/introducing-amazon-bedrock-agentcore-securely-deploy-and-operate-ai-agents-at-any-scale/) 。

S5「商品に組み込む」とS6「顧客へ届ける」は、顧客接点×A2からA3です。Sansanは2025年11月に、名刺と接点のデータをCopilotやClaudeから参照できるMCPサーバとAIエージェントを提供開始しました [ [ 550 ] ](https://jp.corp-sansan.com/news/2025/1121_01.html) 。製品の中にエージェントを置く段階です。

Microsoftの「Frontier Firm」の3フェーズは、この関係を別の言葉で表しています。全員がAIアシスタントを持つ第1フェーズ、エージェントが人の指示で特定の仕事を担う第2フェーズ、人の主導のもとでエージェントが運転する第3フェーズです [ [ 204 ] ](https://www.microsoft.com/en-us/worklab/work-trend-index/2025-the-year-the-frontier-firm-is-born) 。著者の対応づけでは、第1フェーズがS2×A1、第2フェーズがS3×A2、第3フェーズがS4×A3です。OpenAIは企業向けの指標で、利用が「支援(assistance)」から「委任(delegation)」へ移っていると記述しています [ [ 211 ] ](https://openai.com/signals/enterprise-data) 。

### 5. 導入の順序と、各段階で必要な統治

公表された実例と事故から、本書は次の順序を推奨します。

**第一段階：読ませる(A0)**。エージェントに社内の文書とデータを読ませ、答えさせます。実行の権限は与えません。必要な統治は、読ませてよいデータの範囲と、機密情報の扱いです。CRMArena-Proの実測で、エージェントの機密性への配慮がほぼゼロであったことを踏まえます [ [ 594 ] ](https://arxiv.org/abs/2505.18878) 。

**第二段階：提案させる(A1)**。下書き、差分、手順を作らせ、人が実行します。必要な統治は、提案の品質を測る評価の仕組みです。

**第三段階：承認つきで実行させる(A2)**。実行の直前に承認を求めます。必要な統治は、エージェントのID、実行できる範囲の権限、承認者の指定、実行の記録です。承認の形骸化を防ぐため、承認件数と差し戻し率を測ります。

**第四段階：範囲内で自律実行させる(A3)**。金額、対象、時間の上限を定め、その中で実行させ、事後に監査します。必要な統治は、停止の手段、記録の保全、異常の検知です。KPMGの調査では、49%の経営層が、自律的な意思決定を許さない高リスク用途を定義済みでした [ [ 612 ] ](https://kpmg.com/us/en/media/news/q3-ai-pulse-2026.html) 。定義していない51%が、この段階へ進む前に決めることです。

**第五段階：協調させる(A4)**。複数のエージェントに分業させます。必要な統治は、エージェント間の権限の受け渡しの記録と、全体の停止です。2026年7月のOpenAIの事故では、評価環境のエージェントが自律的に分業を始め、隔離の制御を迂回しました [ [ 642 ] ](https://openai.com/index/hugging-face-incident-and-the-road-ahead) 。A4は、A3の統治がすべて機能している企業だけが進む段階です。

### 6. 典型的な失敗と、予測

各段階の典型的な失敗を、公表された事実から整理します。

第一に、段階を飛ばすことです。A1を経ずにA3へ進んだ例が、開発環境のデータベース削除です。第二に、承認の形骸化です。承認件数が多すぎると、人は内容を見ずに承認します。第三に、範囲の定義漏れです。A3で「金額の上限」を定めても「対象の範囲」を定めなければ、意図しない相手に実行します。第四に、ベンダーへの依存です。Gartnerは2026年9月に、ベンダーの出向技術者が構築したエージェントを2028年までに企業の70%が放棄すると予測しました。契約の20%未満しか、顧客の反復的な需要をベンダーの製品機能に転換できない、という見立てです [ [ 671 ] ](https://www.gartner.com/en/newsroom/press-releases/2026-09-29-gartner-predicts-70-percent-of-enterprises-will-abandon-agentic-ai-built-by-vendor-forward-deployed-engineering-by-2028) 。

Gartnerの2025年6月の予測では、エージェント型AIプロジェクトの40%超が、費用の増大、不明確な事業価値、不十分なリスク管理により2027年末までに中止されます [ [ 181 ] ](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027) 。MIT NANDAの2025年の報告では、企業の生成AI投資の95%がリターンゼロで、価値を出しているのは統合型の試行の5%でした [ [ 177 ] ](https://mlq.ai/media/quarterly_decks/v0.1_State_of_AI_in_Business_2025_Report.pdf) 。一方で、ボストン コンサルティング グループの2026年10月の調査では、42%の企業が2030年までにエージェントに人の承認なしの意思決定を含む自律性を持たせると回答しています [ [ 617 ] ](https://prtimes.jp/main/html/rd/p/000000049.000145445.html) 。中止の予測と自律化の意向とが、同時に存在しています。

### 🗺️ 図：自律性は、承認の位置を動かすことで上がる

![自律性A0〜A4を縦に並べ、人の承認の位置が事前から事後へ移る構造を示したスライド](/images/ai-transformation-blueprint/31-agent-adoption-stages.png)

#### 図の読み方

この図は、上から下へA0からA4の5段を縦に並べ、各段の右に「人がどこにいるか」を示しています。

A0とA1では、人は実行の位置にいます。エージェントは答えと案を出し、実行するのは人です。A2では、人は実行の直前にいます。この段と、A3で人が事後の監査の位置に移る段とのあいだに、太い線を引いています。この線が、本章で最も重要な境界です。線を越えるには、ID、権限、記録、停止の手段がそろっている必要があります。A4では、人は目標を与える位置にいて、個々の行動は見ません。

人の位置を示す印は、本書の約束事に従って丹で塗っています。藍の枠がエージェントの実行です。段が下がるほど藍の枠が大きくなり、丹の印が実行から遠ざかります。補助ラベルの各段の説明は、本文の第2節の表と同じです。

### 経営層への含意

本章の枠組みは著者の整理であり、各社の段階論との対応も著者の判断です。使うときの注意を先に述べます。自律性の段階は、会社全体に1つ付くものではなく、業務ごと、行動の種類ごとに付くものです。「当社はA3」という言い方は成り立ちません。「経費の精算はA3、顧客への返金はA2、契約の署名はA0」という言い方が、本章の使い方です。

含意は3つです。第一に、エージェントの導入は、自律性の段階を1つずつ上げる過程として計画できます。各段階で必要な統治は第5節に示したとおりで、段階を飛ばした企業の事故は[AIエージェントの現在地の章](16-agents-today)に記録されています。

第二に、A2からA3への境界が、投資の意味を変えます。A2までは、既存のSaaSと承認の運用で進められます。A3からは、ID、権限、記録、停止の仕組みをシステムとして持つ必要があり、これは[生成AIの導入段階の章](30-genai-adoption-stages)のS4「システムに組み込む」と同じ投資です。エージェントの導入を検討する会議では、「どのモデルを使うか」より先に、「この業務の承認を事前から事後へ移してよいか」を議論することを勧めます。

第三に、顧客接点は最後に残します。社外に影響する失敗の例は、公表されているだけでも複数あります。顧客接点でA3へ進むのは、社内の部門横断でA3の統治が機能したことを確かめた後です。その順序は、[道筋別の戦略の章](35-strategy-by-path)で示す「後悔しない手」の1つです。
