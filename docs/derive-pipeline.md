# 派生物の検証付き生成パイプライン（derive）

正本 `articles/<id>.md` から Qiita 版と note 版を、生成AIに事実を歪めさせずに作るための仕組みです。設計の経緯と根拠は、リポジトリ外の設計文書にまとめました。ここでは、リポジトリに置いた実装の使い方と、確かめた限界を記します。

## 背景

生成AIに派生物を改訂させる評価を 6 回繰り返したところ、検査のエラーは 0 になっても、正本と矛盾する事実が毎回残りました。原因は 2 つです。1 つは、1 回の指示に生成と自己照合と検査対応を同時に負わせたこと。もう 1 つは、禁止表現の正規表現という代理指標の結果を生成器に返し続けたことです。代理指標を最適化させると、生成器はそれをかわす言い換えを学びます。

## モデルの実体

`gemini --model gemini-3.7-flash` を Gemini CLI 0.59.0 に渡すと、実際に応答するモデルは gemini-3.5-flash です。CLI のモデル解決が flash 系の指定を置き換えます。応答の利用記録（stats.models）で確認しました。このパイプラインは、応答したモデル名を毎回検証し、実体名で記録します。

## 段の構成

Node のスクリプトが順序と合否を決め、1 回の呼び出しには 1 つの仕事だけを任せます。

1. **索引（`scripts/derive/index.mjs`）**: 正本の文に節番号つきの ID を振ります。
2. **要件表（`lint/derive/requirements/<id>.json`）**: 媒体ごとに、正本で満たせる必須の節、使ってよい外部リンク、正本にない話題、note の平易な言い換えを、人が承認して置きます。
3. **較正（`scripts/derive/calibrate.mjs`）**: 過去の誤りの文と正本に忠実な文を判定器にかけ、誤りを捕まえ、忠実な文を通せるかを測ります。
4. **生成（`scripts/derive/run-qiita.mjs` / `run-note.mjs`）**: 構造の骨組みを固定し、散文の枠ごとに「使ってよい正本の文（ID つき逐語）」だけを Gemini に渡して書かせます。旧稿は渡しません。渡した命題しか書けないので、正本にない理由や効果を作れません。
5. **判定（`scripts/derive/lib/judge.mjs`）**: 生成した散文を、生成器とは別系統の判定器にかけます。判定器は個人設定を外した空の作業ディレクトリで動き、正本の全文だけを見て文単位に判定します。
6. **検査**: `npm run check` の 11 段階（コードの逐語、開示、重複率、構造）を通します。

## 判定器の限界（較正の結論）

過去 6 ラウンドの誤り 33 文と、正本に忠実な 14 文を判定器にかけました。真陽性率（誤りを捕まえた率）と真陰性率（忠実な文を通した率）を両立する集約ルールは見つかりませんでした。Haiku は 97% と 64%、Sonnet は 97% と 86% です。ゆるめの集約にすると忠実な文は 100% 通りますが、微妙な誤りを見逃します。判定器は、忠実な言い換えと微妙な捏造を同じラベルに入れてしまい、両者を分ける信号が Sonnet の水準でも十分には出ません。

結論として、微妙な事実の歪みは機械だけでは保証できません。そこで、捏造そのものを生成側の帰属の制約（事実は正本の ID に紐づけてから書く）で入口から防ぎ、判定器は高精度の門として使い、残りは人の確認（H1）が担います。

## 使い方

```bash
node scripts/derive/index.mjs                 # 正本の索引
node scripts/derive/calibrate.mjs --repeats=3 # 判定器の較正
node scripts/derive/run-qiita.mjs             # Qiita 版の生成と判定
node scripts/derive/run-note.mjs              # note 版の生成と判定
```

生成した原稿は `.tmp/derive/<媒体>/` に出ます。判定で矛盾・正本外が 0 件でも、公開の前には人の確認が要ります。生成物を公開の場所（`platforms/*/public/`）へ移し、内容を読んで `Reviewed-by` を付けるのは人の仕事です。生成AIは公開状態への変更も `Reviewed-by` の付与もしません。

## 確かめられなかったこと

- gemini-3.7-flash は Gemini API には存在しますが、CLI では使えません。API を直接呼ぶ経路は未実装です。
- 日本語の文単位の判定精度を示す一次情報はほとんどありません。見逃しが 0 件でも、上限は件数で決まる幅にとどまります。
- 判定器（Claude）と受け入れ査読（Claude）は系統を共有します。人の確認は外せません。
