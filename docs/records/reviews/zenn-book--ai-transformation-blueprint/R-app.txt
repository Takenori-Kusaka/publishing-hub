## 全体の評価

診断の流れ、集計規則、結果の生成は 4 パターンすべてで本の規則どおりに動き、設問と根拠の整合も全件取れている。止める水準は 1 件で、共有 URL のハッシュが再読込時に編集を上書きする問題は、会議の前に回答を直す場面で結果が古くなるため先に直す価値がある。直す水準は、不正 JSON の成功扱い、印刷枚数と文言の不一致、同点設問の羅列、Markdown の欠落、コントラスト、第37章の「8 つの見出し」の記述である。文言は落ち着いており、煽りや複数称はない。段階の定義文を本に揃えれば、本とアプリを並べて使う読者の信頼を保てる。

## 確認しなかった範囲

- 公開 URL(GitHub Pages)の実機ではなく、ローカルのビルド(`dist/`)を検証した。ブランド CSS の配信や Pages の base パスは確認していない。
- Safari / Firefox / 実機スマートフォンでは動かしていない(Chromium headless のみ)。`:has()` セレクタは Chromium で動作確認したのみ。
- スクリーンリーダー(NVDA、VoiceOver)での読み上げ順は実機で確認していない。
- 根拠リンク 26 件と章リンク 28 件の URL への実際の到達(HTTP)は確認していない(本の付録B の照合のみ)。
- pptx の中身(40 枚の内容、最後の 1 枚が 8 見出しの型かどうか)は開いていない。
- 自己診断の回答パターン全数(4^5 × 6^6 × 5^6)は当然網羅していない。段階の境界(平均 x.5)と事業の同数は 1 例ずつ確かめた。
- `npm run check`(svelte-check と brand:check)は実行していない(build と test のみ)。
