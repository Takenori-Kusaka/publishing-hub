# 校正の設定

`.textlintrc.json` は **Zenn の読み物**に合わせて設計しています。[process-compass](https://github.com/Takenori-Kusaka/process-compass) の設定を複製したものではありません。

## なぜ別々にするのか

同じ preset を使っていても、**媒体が違えば適切な規約が違います**。

| | process-compass | publishing-hub |
| --- | --- | --- |
| 媒体 | 規程文書(標準・ADR) | 読み物(本・記事) |
| 読み手 | 規定を参照する人 | 通しで読む人 |
| 箇条書きの調 | **である調で統一**(要求事項として読ませる) | **統一しない**(本文の流れに合わせる) |
| 見出しの調 | 統一しない | 統一しない |
| 本文 | ですます調 | ですます調 |

規程文書の箇条書きが である調なのは、要求事項を「〜する」「〜しない」と言い切る形にするためです。読み物の箇条書きに同じ規約を当てると、本文と調が食い違って読みにくくなります。

片方の設定をもう片方へ持ち込むと、**どちらかが不自然になります**。だから分けています。

## 規程文書側との差分

`no-mix-dearu-desumasu` の3つの指定のうち、リストと見出しの強制を外しています。

```json
"no-mix-dearu-desumasu": {
  "preferInHeader": "",
  "preferInBody": "ですます",
  "preferInList": "",
  "strict": false
}
```

**本文が ですます調で揃っていることは引き続き検査します。** 混在は読みにくさとして残るためです。外したのは「リストの調を特定の側へ寄せる」規約だけです。

`max-ten`(読点の数)は明示的に3にしています。読み物では一文が長くなりやすく、既定に任せると気づかないうちに読点が増えるためです。

## 検査する項目

| 規則 | 何を見るか |
| --- | --- |
| `sentence-length` | 一文150字まで |
| `no-doubled-joshi` | 一文に同じ助詞が2回以上 |
| `max-ten` | 一文に読点が4つ以上 |
| `max-comma` | 一文にカンマが6つ以上 |
| `max-kanji-continuous-len` | 漢字が7文字以上連続 |
| `ja-no-mixed-period` | 文末の記号の不統一 |
| `no-mix-dearu-desumasu` | 本文の である／ですます の混在 |

## 無効化しているもの

| 規則 | 理由 |
| --- | --- |
| `no-exclamation-question-mark` | 読み物では問いかけの「?」を使う |
| `ja-no-weak-phrase` | 「〜かもしれません」のような留保が必要な場面がある。断定できないことを断定しないほうが誠実 |

## 実行

```bash
npm run lint         # 校正だけ
npm run check        # 校正 + 本の構成の検証
```

CI(`.github/workflows/check.yml`)でも同じものが走ります。ただし**CI の失敗は Zenn へのデプロイを止めません**。Zenn の同期は GitHub 連携が直接行うためです。この検査は公開前に気づくための手段であって、公開を遮断する強制層ではありません。

## 除外について

原則として、 `.textlintignore` に不要な除外は置きません。ただし、現在1ファイルのみ特例として除外しています。

### 特例除外ファイル

- **対象:** `articles/srb-appendix-bibliography.md`
- **理由:** 本書は書籍・論文等の参考文献台帳であり、英数字、外部URL、外国語の書籍タイトルが連続して記述されています。これらが日本語の文章検査（漢字連続、一文の長さ、二重助詞等）に多数の偽陽性エラーを引き起こすため、例外的に除外しています。
- **見直し期限:** 2027年9月12日（または参考文献リストの大幅な刷新時）
- **解除条件:** 英語タイトル部やURL参照部を自動でスキップする校正フィルタプラグインが導入されること。
